💻 算法 / Algorithms

Day 142 · #416 Partition Equal Subset Sum (Medium) 🟡

🧩 一维动态规划 (12/12) — 收官之战，建立在整个 1-D DP 模版之上

题目 / Problem

🔗 https://leetcode.com/problems/partition-equal-subset-sum/

📹 https://neetcode.io/problems/partition-equal-subset-sum

给定整数数组 nums，判断能否将其分成两个元素和相等的子集。

Given array nums, return True if you can partition it into two subsets with equal sum.

Example:

nums = [1, 5, 11, 5] → True ([1, 5, 5] and [11]) nums = [1, 2, 3, 5] → False

现实类比 / Real-World Analogy

公平分家产：父亲去世，留下 N 件价值不同的藏品。你和弟弟能不能各拿一半（总价值相等）？这就是 Partition Equal Subset Sum。

Settling an estate: can two heirs split N items of varying value into equal halves?

与模版的映射 / Mapping to Template

这道题的核心洞察：把"能否凑出总和 target = sum//2"转化为 0/1 背包问题。

# 标准 1-D DP 模版变种 (0/1 背包)
dp = [False] * (target + 1)
dp[0] = True         # base case: 凑出 0 总是可行

for num in nums:
    # 倒序遍历！防止同一个数用两次
    for j in range(target, num - 1, -1):
        dp[j] = dp[j] or dp[j - num]

return dp[target]

为什么倒序？ 正向遍历 dp[j] 会用到本轮刚更新的 dp[j-num]，相当于同一个数用了两次。倒序保证每个 num 只用一次（0/1 背包 vs 完全背包的核心区别）。

完整解法 / Full Solution with Trace

def canPartition(nums: list[int]) -> bool:
    total = sum(nums)
    # odd sum → impossible to split into two equal halves
    if total % 2 != 0:
        return False
    
    target = total // 2
    dp = [False] * (target + 1)
    dp[0] = True
    
    for num in nums:
        # iterate right-to-left to avoid reusing the same num
        for j in range(target, num - 1, -1):
            dp[j] = dp[j] or dp[j - num]
    
    return dp[target]

手动 trace： nums = [1, 5, 11, 5], target = 11

初始: dp = [T, F, F, F, F, F, F, F, F, F, F, F] num=1: dp = [T, T, F, F, F, F, F, F, F, F, F, F] num=5: dp = [T, T, F, F, F, T, T, F, F, F, F, F] num=11:dp = [T, T, F, F, F, T, T, F, F, F, F, T] ← dp[11]=True! num=5: dp = [T, T, F, F, F, T, T, F, F, F, T, T] (dp[11] already True) return dp[11] → True
💡 可以加 if dp[target]: return True 提前退出（优化），但不影响正确性。

复杂度 / Complexity

  • Time: O(n × target) = O(n × sum/2)
  • Space: O(target) ← 1-D 滚动数组优化

这是整个 1-D DP 模块（12题）的收官题，来看模式进化：

🧒 ELI5

有一堆积木，每块有重量。能不能分成两堆，让两堆重量相同？你把目标重量当成背包容量，每块积木决定放不放进去。dp[j]=True 表示"用已经看过的积木，能凑出重量 j"。倒序是为了每块积木只用一次。

Day 142 · Expert Synthesis — Staff Engineer 面试终极场景

场景 / Scenario

"你是一位 Staff Engineer，即将面试一个 Principal 岗位。面试官问你：给我讲一个你主导了整个组织技术方向转型的故事。"
You're a Staff Engineer interviewing for Principal. The interviewer says: "Tell me about a time you led a technology direction change across the entire org."

这道题不是一个 behavioral question——它是综合测试：影响力、技术判断、跨组协作、战略眼光，全在一道题里。

为什么这是最难的题型

过去 60 个行为题测的是各种维度（冲突、失败、优先级、跨团队…）。这道题全部叠加：

  • 需要有 明确的技术判断 (不是"我们讨论了很久")
  • 需要有 跨团队影响 (不是"我说服了我的 manager")
  • 需要有 可量化结果 (不是"大家都很开心")
  • 需要有 阻力和克服 (没有阻力=不够大的决策)

STAR 拆解 / STAR Breakdown

情境 (Situation):

"公司的微服务架构运行了 5 年，P95 延迟 800ms，部署需要协调 12 个团队，每次 incident 根因分析需要 3 天。3 个团队有各自的 'modernization' 计划，互相冲突。"

任务 (Task):

"作为 Infrastructure 的 Staff Engineer，我没有直线管理这 12 个团队，但被要求在 6 个月内拿出一个全公司认可的迁移路径。"

行动 (Action) — 最关键：

  1. 技术审计：先花 3 周亲自 on-call + 看监控，不听别人说，自己弄清楚真正的痛点
  2. 建立工作组：不是委员会（没有决策权），而是"每个团队出一个有代码提交权限的 IC"
  3. 原型 > 提案：做了两个真实原型（gRPC + service mesh vs event-driven），让数据说话
  4. 处理阻力：有一个 Senior Director 喜欢他团队的方案。我安排了 1:1，承认他方案的优点，展示数据差距，提出"他的核心需求可以在新架构里满足"——找到 共同利益
  5. RFC 流程：写了公开 RFC，任何人可以提 comment，透明决策

结果 (Result):

"RFC 通过，18 个月后迁移完成。P95 延迟从 800ms 降到 120ms，部署频率提升 4×，incident MTTR 从 3 天降到 4 小时。"

❌ Bad vs ✅ Good

❌ "我写了一份提案，发给所有人，大家都同意了。"

→ 没有冲突 = 决策规模太小，或者你跳过了困难部分。

✅ "我主动寻找反对声音，特别是最强的反对者，因为他们往往掌握我不知道的信息。"

❌ "我是最聪明的人，所以大家都听我的。"

→ Principal 的影响力来自信任和数据，不是头衔。

✅ "我建立了一个让正确答案自然浮现的流程，而不是强推我的答案。"

Senior/Staff 提升点

  1. Scope 信号：面试官想看到的影响范围是 "多个团队" 或 "全公司"，不是你自己的团队
  2. 阻力是加分项：没有阻力的故事说明决策不够大。要主动讲你如何处理反对
  3. 数据锚定：每个决策背后要有数据，"感觉对" 是 IC L5 的答案，"数据显示" 是 Principal 的答案
  4. 学到什么：加一句 "如果重来，我会更早建立 RFC 流程而不是先私下游说"——展示元认知

想象一群人要一起决定去哪家餐厅吃饭，每个人都有偏好，有人很强势。Staff Engineer 不是说"我要去这家"，而是：先搞清楚大家真正在乎什么（口味？价格？距离？），然后找到一个满足大多数核心需求的选择，让最强烈的反对者变成支持者，最后写下来让所有人投票确认。这就是技术方向转型。

可运行代码 / Runnable: 简单 RAG Pipeline

# pip install openai numpy scikit-learn
import numpy as np
from sklearn.metrics.pairwise import cosine_similarity

# Simulated knowledge base (in prod: use pgvector / Pinecone)
knowledge_base = [
    {"text": "Python GIL prevents true parallelism for CPU-bound tasks", "id": 1},
    {"text": "asyncio enables concurrency for I/O-bound tasks without threads", "id": 2},
    {"text": "ProcessPoolExecutor bypasses GIL using separate processes", "id": 3},
]

def embed(text: str) -> np.ndarray:
    """Dummy embedding — replace with openai.embeddings.create()"""
    # deterministic fake embedding based on word overlap
    words = set(text.lower().split())
    vec = np.array([1.0 if w in words else 0.0 for w in 
                    "python gil asyncio process concurrent thread io cpu".split()])
    norm = np.linalg.norm(vec)
    return vec / norm if norm > 0 else vec

def rag_retrieve(query: str, top_k: int = 2) -> list[str]:
    query_emb = embed(query).reshape(1, -1)
    doc_embs = np.array([embed(doc["text"]) for doc in knowledge_base])
    scores = cosine_similarity(query_emb, doc_embs)[0]
    top_indices = scores.argsort()[-top_k:][::-1]
    return [knowledge_base[i]["text"] for i in top_indices]

# Demo
query = "how to run Python code in parallel bypassing GIL?"
context = rag_retrieve(query)
print("Retrieved context:")
for c in context:
    print(f"  - {c}")
# → ProcessPoolExecutor + asyncio chunks retrieved
