Quick Review Quiz (Days 156–159)

Q1: [Algorithms] Burst Balloons uses interval DP. What's the key reversal trick?

A1: Instead of thinking "which balloon to pop first," think "which balloon is popped LAST in interval [i,j]." This avoids the problem of broken adjacency after popping. dp[i][j] = max(dp[i][k] + nums[i]nums[k]nums[j] + dp[k][j]) for k in (i,j).

Q2: [Algorithms] Regular Expression Matching — when p[j-1] == '*', what two states do you check?

A2: (1) Zero occurrences: dp[i][j-2] — skip the x unit entirely. (2) One or more: dp[i-1][j] if s[i-1] matches p[j-2] — consume one char, keep the same pattern active.

Q3: [Algorithms] Maximum Subarray (Kadane's) — what's the invariant at each step?

A3: curr = max(nums[i], curr + nums[i]) — either extend the current subarray or start fresh at nums[i]. Global max tracks the best seen. O(n) time, O(1) space.

Overview / 概述

中文：

正则表达式匹配是一道经典的 Hard 级动态规划题，考频极高（Google、Meta、Amazon 都出过）。给定字符串 s 和模式 p，其中 . 匹配任意单字符，* 匹配前驱字符的零次或多次出现，判断 p 是否能完整匹配 s。

难点在于 * 的"零次"语义——它可以让前驱字符彻底消失，导致状态空间爆炸。暴力递归会超时，必须用记忆化或 DP 才能在 O(m·n) 时间内解决。

English:

Regular Expression Matching is a canonical Hard DP problem. Given string s and pattern p where . matches any single character and matches zero or more of the preceding element, determine if p matches s entirely*.

The tricky part is *'s "zero occurrences" case — the preceding character can vanish, creating branching state explosions in naive recursion. We need DP to reach O(m·n) time.

🔗 LeetCode: https://leetcode.com/problems/regular-expression-matching/

📹 NeetCode: https://www.youtube.com/watch?v=HAA8mgxlov8

Part 1: Theory / 理论基础 (5 min)

中文：核心思路

设 dp[i][j] 表示 s[0..i-1] 能否被 p[0..j-1] 匹配。

三种情况递推：

情况 1：普通字符匹配 (p[j-1] 是字母或 .)

  • dp[i][j] = dp[i-1][j-1] 当 s[i-1] == p[j-1] 或 p[j-1] == '.'

情况 2： 号 (p[j-1] == '')

  • * 代表前驱字符 p[j-2] 匹配零次或多次
  • 零次：dp[i][j] = dp[i][j-2]（跳过 p[j-2]* 整个模式）
  • 一次及以上：dp[i][j] = dp[i-1][j] 当 s[i-1] == p[j-2] 或 p[j-2] == '.'

— 即「用 p[j-2]* 匹配 s[i-1]，然后 s[0..i-2] 还需被 p[0..j-1] 匹配」

情况 3：边界

  • dp[0][0] = True（空字符串匹配空模式）
  • dp[0][j]：只有 p[0..j-1] 是 abc*... 形式才为 True

English: Mental Model

Think of dp[i][j] as: "Can pattern p's first j characters match string s's first i characters?"

The key insight: x is a single unit in the pattern. When you encounter at position j, you must look at the character TWO positions back (p[j-2]) — it's the character that * quantifies.

State transition diagram: p[j-1] is regular char/dot p[j-1] is '*' ┌─────────────────────────┐ ┌────────────────────────────┐ │ match? use dp[i-1][j-1]│ │ ZERO use: dp[i][j-2] │ dp[i][j] ──► │ no match? dp[i][j]=F │ │ ONE+: if s[i-1] ~ p[j-2] │ └─────────────────────────┘ │ use: dp[i-1][j] │ └────────────────────────────┘

Part 2: Step-by-Step Implementation / 一步一步实现 (8 min)

Approach 1: Naive Recursion (会超时 — TLE)

中文： 直觉解法，但对 * 做了指数级分叉，时间复杂度 O(2^(m+n))。

def isMatch_naive(s: str, p: str) -> bool:
    # Base case: empty pattern
    if not p:
        return not s
    
    # Does the first character match?
    first_match = bool(s) and p[0] in {s[0], '.'}
    
    # Is the SECOND character a '*'?
    if len(p) >= 2 and p[1] == '*':
        # Option A: use '*' zero times (skip the "x*" unit entirely)
        # Option B: use it once (consume s[0] and keep the same pattern)
        return (isMatch_naive(s, p[2:]) or          # zero times
                (first_match and isMatch_naive(s[1:], p)))  # one or more
    else:
        # No '*': must match first char and recurse on rest
        return first_match and isMatch_naive(s[1:], p[1:])

Approach 2: Memoization (Top-Down DP)

中文： 用 @cache 消除重复子问题，时间 O(m·n)，空间 O(m·n)。

from functools import cache

def isMatch_memo(s: str, p: str) -> bool:
    @cache
    def dp(i: int, j: int) -> bool:
        """
        Returns True if s[i:] is fully matched by p[j:].
        i: current index in s (0..len(s))
        j: current index in p (0..len(p))
        """
        # Base case: exhausted the pattern
        if j == len(p):
            return i == len(s)  # True only if s is also exhausted
        
        # Does s[i] match p[j]?
        first_match = i < len(s) and p[j] in {s[i], '.'}
        
        # Lookahead: is the NEXT pattern char a '*'?
        if j + 1 < len(p) and p[j + 1] == '*':
            # Zero occurrences: skip "p[j]*" unit entirely (move j by 2)
            # One or more: consume s[i] only if first_match (keep j, move i)
            return dp(i, j + 2) or (first_match and dp(i + 1, j))
        else:
            # No '*' following: must match current chars and advance both
            return first_match and dp(i + 1, j + 1)
    
    return dp(0, 0)

关键提示 / Key tip: We recurse on indices (not substrings) so Python's @cache can deduplicate efficiently.

Approach 3: Bottom-Up DP (最优解 / Optimal)

中文： 迭代版 DP，逻辑与记忆化完全对应，但无递归开销。

def isMatch(s: str, p: str) -> bool:
    m, n = len(s), len(p)
    
    # dp[i][j] = can p[0..j-1] match s[0..i-1] ?
    # Using (m+1) x (n+1) table; row 0 = empty s, col 0 = empty p
    dp = [[False] * (n + 1) for _ in range(m + 1)]
    
    # --- Base case initialization ---
    dp[0][0] = True  # empty string matches empty pattern
    
    # Empty string can match patterns like a*, a*b*, a*b*c* ...
    # If p[j-1] == '*', it can annihilate p[j-2], inheriting dp[0][j-2]
    for j in range(2, n + 1):
        if p[j - 1] == '*':
            dp[0][j] = dp[0][j - 2]  # zero occurrences of p[j-2]
    
    # --- Fill the table row by row ---
    for i in range(1, m + 1):       # i iterates over s characters
        for j in range(1, n + 1):   # j iterates over p characters
            
            if p[j - 1] == '*':
                # '*' acts on the character BEFORE it: p[j-2]
                # Case A: use '*' ZERO times → skip "p[j-2]*" entirely
                zero_times = dp[i][j - 2]
                
                # Case B: use '*' ONE or MORE times
                # s[i-1] must match p[j-2] (the char that '*' quantifies)
                # Then we "consume" s[i-1] and keep the same pattern position j
                prev_char_matches = (p[j - 2] == s[i - 1] or p[j - 2] == '.')
                one_or_more = dp[i - 1][j] if prev_char_matches else False
                
                dp[i][j] = zero_times or one_or_more
            
            elif p[j - 1] == '.' or p[j - 1] == s[i - 1]:
                # Direct match: both chars align → inherit diagonal
                dp[i][j] = dp[i - 1][j - 1]
            
            # else: mismatch, dp[i][j] stays False
    
    return dp[m][n]

DP Table Walkthrough (s="aab", p="cab"):

"" c * a * b "" T F T F T F a F F F T T F a F F F F T F b F F F F F T ← answer!

每个 * 格子看的是两格前（零次）和左上（一次）。

Each * cell looks two columns left (zero) and one row up (one-or-more).

复杂度 / Complexity:

  • Time: O(m · n)
  • Space: O(m · n), optimizable to O(n) with rolling array

Space-Optimized Version (Bonus)

def isMatch_1d(s: str, p: str) -> bool:
    m, n = len(s), len(p)
    # Only keep current and previous row
    prev = [False] * (n + 1)
    prev[0] = True
    for j in range(2, n + 1):
        if p[j - 1] == '*':
            prev[j] = prev[j - 2]
    
    for i in range(1, m + 1):
        curr = [False] * (n + 1)
        for j in range(1, n + 1):
            if p[j - 1] == '*':
                prev_char_matches = p[j - 2] in {s[i - 1], '.'}
                curr[j] = curr[j - 2] or (prev_char_matches and prev[j])
            elif p[j - 1] in {s[i - 1], '.'}:
                curr[j] = prev[j - 1]
        prev = curr
    
    return prev[n]

Part 3: Edge Cases & Gotchas / 边界情况 (2 min)

中文：

场景输入期望陷阱
* 消零s="b", p="a*b"Truea* 匹配空
连续 .*s="aaa", p=".*"True.* 吞掉一切
模式比字符串长s="a", p="aaa*"True全部零次后仍为空
* 出现在位置 1s="", p="a*"True初始化行必须处理
* 只匹配一次s="a", p="a*"True不要忘记"一次及以上"
无 * 长度不等s="ab", p="a"False长度不能弥补

English:

Critical gotcha: ALWAYS has a preceding character in valid input (per LeetCode constraints), so p[j-2] access when p[j-1] == '' is safe — but only when j >= 2. Always initialize from j=2 in the first row.

Another trap: When p[j-1] == '', do NOT look at dp[i-1][j-1] (diagonal). The applies to p[j-2], not p[j-1].

Dot trap: '.' matches exactly one character — it cannot match zero. Only '.*' can match zero.

Part 4: Real-World Application / 实际应用 (2 min)

中文：

这道题的 DP 思想直接应用于：

  1. SQL LIKE 操作符：% 和 _ 通配符的匹配逻辑与本题高度相似
  2. 路由匹配：Express.js / FastAPI 的路径通配（/api/*）
  3. grep/awk 引擎：GNU grep 的 NFA → DFA 转换正是 DP 核心思想
  4. 编译原理：词法分析器（lexer）中的正则表达式转 NFA 再转 DFA

English:

This exact DP structure powers real regex engines:

# SQL LIKE equivalent (simplified)
def sql_like(s: str, pattern: str) -> bool:
    # '%' = '.*' in regex, '_' = '.' in regex
    p = pattern.replace('%', '.*').replace('_', '.')
    return isMatch(s, '^' + p + '$')  # conceptually

Production reality: Real regex engines like RE2 (used by Google, Go, Python's re2 module) convert the regex to an NFA, then simulate it — essentially the same DP state transitions but streaming over input. The DP approach here is a direct table-based NFA simulation.

Interview context: Interviewers sometimes follow up: "How would you extend this to support + and ??"

  • x+ = xx* (one or more)
  • x? = (x|ε) — add a case: if p[j-1] == '?', either skip it (dp[i][j-2]) or consume one char

Part 5: Interview Simulation / 面试模拟 (3 min)

中文： 面试官最爱追问的 5 个问题：

Q1: 为什么不能用 s.find() 或 Python 的 re 模块？

A1: 面试考的是你能否手写 DP 推导出状态转移，调库没有考查价值。面试时要先说："现实中当然用 re.fullmatch(p, s)，但我来展示 DP 解法。"

Q2: 时间复杂度是多少？能优化吗？

A2: O(m·n) 时间，O(m·n) 空间。空间可用滚动数组优化到 O(n)，时间无法进一步优化（需要遍历所有状态）。

Q3: 如果模式中有 +（一次及以上）和 ?（零次或一次），怎么改？

A3: 在 DP 中加两个分支：? → dp[i][j] = dp[i][j-2] or (first_match and dp[i-1][j-1])；+ 类似于 * 但去掉零次分支。

Q4: 递归版和迭代版哪个更好？

A4: 迭代版更稳定（无调用栈溢出风险），空间优化更自然；递归版思路更直观。面试中先讲递归思路，再写迭代版代码。

Q5: 能不能用 BFS/DFS 做？

A5: 可以——把 (i, j) 当节点做 BFS。这正是 NFA 仿真的本质。但 DP 表法更直接，状态管理更清晰。

English Q&A:

Q1: Where does * complexity come from?

A: Without memoization, * creates two branches at each step (zero/one-more), leading to O(2^(m+n)) in the worst case. With DP, each (i,j) state is computed once → O(m·n).

Q2: What's the invariant of dp[0][j]?

A: dp[0][j] = "can pattern p[0..j-1] match the empty string?" — only true for patterns like a, ab, ., etc. This row drives correct initialization.

Q3: Why do we check dp[i-1][j] (not dp[i-1][j-1]) for the one-or-more case?

A: Because can match multiple chars. After consuming s[i-1], the SAME p[j-1] () is still in play to potentially match s[i-2]. We keep j fixed and move i.

Q4: What if the pattern starts with *?

A: Per LeetCode constraints, * never appears as the first character — it always has a preceding character. No need to guard for this.

Q5: Can this be extended to full POSIX regex?

A: This covers the core: . and *. Full POSIX adds +, ?, [], ^, $, {n,m}, alternation |, and groups (). Each extension adds state transitions but the DP framework remains.
