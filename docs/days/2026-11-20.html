🏗️ 系统设计 / System Design — Day 153 (Synthesis)

分布式事务模式全比较：SAGA vs 2PC vs Outbox Pattern

想象你在设计…

你在构建一个电商平台（像我们 Day 38 设计的 Stripe 支付系统 + Day 36 的 E-Commerce Platform）。用户下单时需要同时：

  1. 扣减库存
  2. 创建订单
  3. 扣款
  4. 发送确认邮件

这四步分布在四个不同的微服务上。任何一步失败都需要回滚。如何保证分布式事务的一致性？

ASCII 架构对比

┌─────────────────────────────────────────────────────┐ │ 分布式事务三大模式 │ └─────────────────────────────────────────────────────┘ 2PC (Two-Phase Commit): Coordinator ──→ Phase 1: "准备好了吗?" ──→ [ServiceA, ServiceB, ServiceC] Coordinator ←── Phase 1 Response: "YES" ←── [all vote] Coordinator ──→ Phase 2: "提交!" ──→ [ServiceA, ServiceB, ServiceC] ⚠️ 协调者宕机 = 所有参与者阻塞 SAGA (Choreography): OrderService ──→ [event: OrderCreated] ↓ InventoryService ──→ [event: InventoryReserved] ↓ PaymentService ──→ [event: PaymentFailed] ↓ InventoryService ←── [compensate: ReleaseInventory] ← 补偿事务 OrderService ←── [compensate: CancelOrder] Transactional Outbox: ┌──────────────┐ ┌────────────────┐ ┌──────────────┐ │ Service DB │ │ Outbox Table │ │ Message Bus │ │ order: saved │ ── │ event: pending │ ──→│ Kafka/SQS │ │ (same TX) │ │ (atomic write) │ │ │ └──────────────┘ └────────────────┘ └──────────────┘ CDC (Debezium) or polling pulls outbox → publishes events

为什么这样设计？关键权衡

模式一致性可用性复杂度适用场景
2PC强一致性❌ 低（协调者是单点）中等金融核心账本、跨库同一数据中心
SAGA最终一致性✅ 高高（需补偿逻辑）微服务、跨服务工作流
Outbox至少一次✅ 高中等保证"事件一定发出去"

核心原则：CAP 定理（Day 12）告诉我们，分布式系统无法同时保证 C + A + P。SAGA 选择 AP，2PC 选择 CP。

常见错误 / 别踩这个坑

❌ 误用 2PC 于跨数据中心场景：网络延迟 + 协调者宕机 = 全系统阻塞。2PC 只适合同一数据中心的强一致需求。

❌ SAGA 忘记幂等补偿：补偿事务可能执行多次（网络重试）。每个补偿操作必须是幂等的。

❌ Outbox 不清理：Outbox 表会无限增长。���要在事件确认发出后及时删除或归档记录。

✅ 现实选择：Stripe 用 Outbox + Idempotency Keys；Uber 用 SAGA + Cadence/Temporal workflow engine（我们 Day 41 讨论过 Distributed Task Queue）。

深度连接：与之前内容的联系

  • Day 13 消息队列：SAGA 的编排依赖 Kafka/SQS 可靠传递
  • Day 38 支付系统：Stripe 使用幂等 Key + Outbox 保证支付事件不丢失
  • Day 47 Raft/Paxos：2PC 的协调者可以用 Raft 实现 HA
  • Day 63 分布式锁：SAGA 补偿期间需要锁防止并发冲突

🧒 ELI5

想象你和朋友合伙买礼物。2PC 是：你问所有人"有钱吗？"等大家都说有才付款，但如果你（协调人）突然失联，大家都傻等着。SAGA 是：每人先付自己那份，如果中途有人没钱，之前付了的人各自退款。Outbox 是：先把"我要给你发钱"这个承诺写在纸上压在枕头下，确保即使中途断网，这个承诺也不会丢。

#115 Distinct Subsequences [Hard] — 2-D Dynamic Programming (9/11)

🧩 二维动态规划模式 (9/11) — 延续 Day 149 (Interleaving String) 的模版

🔗 Links

  • LeetCode: https://leetcode.com/problems/distinct-subsequences/ 🔴 Hard
  • NeetCode: https://neetcode.io/problems/count-subsequences

现实类比 / Real-world Analogy

想象你在做文本搜索：给定一份长文档 s 和一个关键词 t，问关键词以子序列形式出现在文档里多少次（字符可以不连续，但顺序不变）。这就是 Distinct Subsequences 的核心——计算路径数量，而非判断是否存在。

问题定义

给定字符串 s 和 t，计算 s 的子序列中有多少个等于 t。

s = "rabbbit", t = "rabbit"
输出: 3
(三种方式选取 rabbit，对应三个不同的 'b' 被跳过)

映射到模版 / Map to Template

这是计数型 2D DP，不同于之前的：

  • Day 141 Edit Distance → 最小代价
  • Day 148 Target Sum → 组合计数（1D 背包）
  • Day 149 Interleaving String → 可行性判断

今天：dp[i][j] = s 的前 i 个字符中，t 的前 j 个字符作为子序列出现的次数。

转移规律（画表格找）：

"" r a b b i t ← t (j轴) "" 1 0 0 0 0 0 0 r 1 1 0 0 0 0 0 a 1 1 1 0 0 0 0 b 1 1 1 1 0 0 0 b 1 1 1 2 1 0 0 b 1 1 1 3 3 0 0 i 1 1 1 3 3 3 0 t 1 1 1 3 3 3 3 ← 答案!

规律：

  • s[i] == t[j]：既可以"用 s[i] 匹配 t[j]"(dp[i-1][j-1])，也可以"跳过 s[i]"(dp[i-1][j])

→ dp[i][j] = dp[i-1][j-1] + dp[i-1][j]

  • s[i] != t[j]：只能跳过 s[i]

→ dp[i][j] = dp[i-1][j]

Python 解法 + 执行追踪

def num_distinct(s: str, t: str) -> int:
    m, n = len(s), len(t)
    
    # dp[i][j] = count of t[:j] in s[:i] as subsequence
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    
    # Base: empty t is a subsequence of any s prefix (1 way)
    for i in range(m + 1):
        dp[i][0] = 1
    
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            # Always carry forward: skip s[i-1]
            dp[i][j] = dp[i-1][j]
            # If chars match, also add paths that USE s[i-1]
            if s[i-1] == t[j-1]:
                dp[i][j] += dp[i-1][j-1]
    
    return dp[m][n]

# Trace: s="rabbbit", t="rabbit"
# After filling: dp[7][6] = 3  ✓

空间优化（O(n) 滚动数组）：

def num_distinct_optimized(s: str, t: str) -> int:
    n = len(t)
    dp = [0] * (n + 1)
    dp[0] = 1  # empty t base case
    
    for ch in s:
        # Traverse RIGHT TO LEFT to avoid using updated values
        for j in range(n, 0, -1):
            if ch == t[j-1]:
                dp[j] += dp[j-1]
    
    return dp[n]

复杂度：Time O(m×n)，Space O(m×n) → 优化后 O(n)

举一反三 / Pattern Connections

题目DP 类型转移核心
Edit Distance (#72)最小代价min(insert, delete, replace)
Interleaving String (#97)可行性OR 操作
Distinct Subsequences (#115)计数加法累积
Burst Balloons (#312) ← 下一题区间 DP区间分割

关键区别：当 DP 问"有多少种方式"时，转移用加法；问"能否"时用OR；问"最优"时用min/max。

🗣️ 软技能 / Soft Skills — Day 153 (Synthesis)

Staff-Level Scenario: 你的团队欠了三年技术债，新 CTO 要求 6 个月内清零

场景设定

新 CTO 刚上任，宣布要在 Q2 结束前"清掉所有技术债"。你是 Staff Engineer，负责一个有 300 万行代码的核心服务，里面有未迁移的 Python 2 代码、循环依赖的模块、以及一堆没有测试的关键路径。你怎么做？

这道题综合了我们覆盖过的多个主题：技术债处理（Day 16）、优先级排序（Day 12）、向上管理（Day 3）、跨团队对齐（Day 14）。

STAR 框架拆解

Situation — 建立共同语言

技术债不是一个技术问题，它是一个沟通问题。先量化：

  • 把债务分类：安全风险 / 稳定性风险 / 开发速度阻碍
  • 用业务语言翻译："Python 2 EOL 意味着 CVE 无人修补"
  • 建立"债务登记册"（Debt Registry），每条记录关联业务影响

Task — 重新定义目标

❌ 坏目标："6 个月清零技术债"（不可能，会制造恐慌）

✅ 好目标："6 个月内消除 TOP 3 高风险债务，并建立不再累积新债的机制"

向 CTO push back，但要带数据和替代方案。

Action — 执行框架

Week 1-2: 审计 + 分级 → 高风险（安全/稳定性）: 立即行动 → 中风险（开发速度）: 季度计划 → 低风险（代码质量）: 随机结对处理 Month 1-2: 并行战略 → 新功能：50% 时间 → 技术债：30% 时间 (固定 budget, 不 cancel) → 防新债：20% 时间 (lint rules, PR 模版, ADR) Month 3-6: 进度可视化 → 每两周向 CTO 汇报：已消除的业务风险 (not "lines fixed") → 建立"债务燃烧图" Burndown Chart

Result — 预期成果

不要承诺"全部清零"，而是承诺：

  1. 安全债务：100% 消除（Python 2 迁移完成）
  2. 稳定性债务：关键路径测试覆盖率 >80%
  3. 流程：PR 中不引入新的 P0/P1 级债务

❌ 坏答案 vs ✅ 好答案

答法
❌"我们按 CTO 要求，全力以赴 6 个月冲刺清零！"
❌"技术债太多了，6 个月根本不可能，这个目标不合理。"
✅"我理解紧迫感。让我在这周做完审计，带着数据回来，我们一起定一个既能控风险又不停止业务交付的计划。"

Senior/Staff 加分点

  • 用 ADR (Architecture Decision Records) 防新债：每个架构决策留记录，避免同样的债务再犯
  • 把技术债变成可见资产：在 roadmap 上展示，让 PM 也参与优先级排序
  • 教团队识别债务：Code Review checklist 里加入"这会产生技术债吗？"

关键提炼

  1. 先审计后承诺：没有数据的计划是空谈
  2. 用业务语言：CTO 关心风险和速度，不关心代码行数
  3. 固定 budget，不 cancel：技术债时间被随意取消是债务积累的根源
  4. 建机制而非做一次性清理：真正的解法是不再产生新债

🔬 Saturday Deep Dive: Distinct Subsequences — 不同子序列 (18 min read)

📊 NeetCode: 119/150 · SysDesign: 60/40 · Behavioral: 60/40 · Frontend: 37/50 · AI: 30/30

🔗 LeetCode #115 · 📹 NeetCode Video

Overview / 概述

中文：

这道题问的是：字符串 s 中，有多少种不同的方式可以通过删除某些字符（不改变顺序）来得到字符串 t？

这是 2D 动态规划的经典题，也是这个模式最难的题之一。它考察你是否真正理解"二维 DP 的状态定义"，以及如何从"两个字符串的前缀"来建立转移方程。

面试中出现这道题，说明面试官在测试你的 DP 功底。大多数人一遇到 Hard DP 就慌，但只要你能画出 dp 表格并手动填几格，转移方程就会自己浮现。

English:

Given strings s and t, count the number of distinct subsequences of s that equal t. A subsequence is formed by deleting characters without changing order.

This is one of the canonical Hard 2D DP problems. It tests whether you understand how to define state over two string prefixes and derive a recurrence from first principles.

The pattern here: if the current characters match, you have a choice; if they don't, you have no choice. That binary intuition drives the whole solution.

Part 1: Theory / 理论基础 (5 min)

什么是子序列计数？/ What Are We Counting?

中文：

先明确问题的结构。给定 s = "rabbbit", t = "rabbit"，答案是 3。为什么？因为 s 里有三个 b，你可以选择删掉任意一个 b 来得到 t。

关键洞察：我们不是在找一个答案，而是在统计所有可能的"选法"的数量。 这就是为什么要用 DP 而不是递归搜索（虽然 DP 的本质是记忆化递归）。

English:

Example: s = "rabbbit", t = "rabbit" → 3.

There are three bs in s; you can drop any one of them to form t. Each choice gives a distinct way.

Key insight: We're not finding one path — we're counting all valid paths. That's what forces us toward DP.

DP 状态定义 / State Definition

中文：

定义 dp[i][j] = 用 s 的前 i 个字符，能组成 t 的前 j 个字符的方案数。

最终答案是 dp[len(s)][len(t)]。

English:

Define dp[i][j] = number of ways to form t[0..j-1] using s[0..i-1].

Final answer: dp[len(s)][len(t)].

转移方程 / Recurrence

中文：

分两种情况讨论：

  1. s[i-1] != t[j-1]（当前字符不匹配）：

- s[i-1] 只能被跳过，不能用来匹配 t[j-1]

- 所以 dp[i][j] = dp[i-1][j]（跳过 s[i-1]，问题规模缩小）

  1. s[i-1] == t[j-1]（当前字符匹配）：

- 选项 A： 用 s[i-1] 来匹配 t[j-1] → 贡献 dp[i-1][j-1] 种方案

- 选项 B： 跳过 s[i-1]，不用它匹配 → 贡献 dp[i-1][j] 种方案

- 两种选法互不影响，所以相加：dp[i][j] = dp[i-1][j-1] + dp[i-1][j]

English:

  1. s[i-1] != t[j-1]: We must skip s[i-1].

→ dp[i][j] = dp[i-1][j]

  1. s[i-1] == t[j-1]: Two independent choices:

- Use s[i-1] to match t[j-1]: contributes dp[i-1][j-1]

- Skip s[i-1] anyway: contributes dp[i-1][j]

→ dp[i][j] = dp[i-1][j-1] + dp[i-1][j]

边界条件 / Base Cases

中文：

  • dp[i][0] = 1：用 s 的任何前缀都能组成空字符串 t，恰好 1 种方式（什么都不选）。
  • dp[0][j] = 0（j > 0）：用空字符串 s 无法组成非空 t。

English:

  • dp[i][0] = 1 for all i: empty target is always achievable (delete everything).
  • dp[0][j] = 0 for j > 0: can't form non-empty target from empty source.

心智模型 / Mental Model

中文：

把 dp 表格想象成一张地图。左上角是起点（空 s，空 t），右下角是终点（完整 s，完整 t）。每一步你只能向右（扩展 s）移动。当字符匹配时，你可以"斜着走"（消耗 s 和 t 各一个字符），也可以继续往右走（跳过 s 中的这个字符）。答案就是从起点到终点所有路径的数量。

English:

Think of the DP table as a grid. Start top-left (empty s, empty t), end bottom-right (full s, full t). You always move down one row (advance in s). When chars match, you can also absorb one char of t (diagonal move). The answer counts all valid paths to the bottom-right.

Part 2: Step-by-Step Implementation / 一步一步实现 (8 min)

Step 1: 手动画表格 / Hand-Trace the Table

s = "babgbag", t = "bag"

      ""  b  a  g
  ""   1  0  0  0
  b    1  1  0  0
  a    1  1  1  0
  b    1  2  1  0
  g    1  2  1  1
  b    1  3  1  1
  a    1  3  4  1
  g    1  3  4  5

中文解释：

  • dp[3][1]（s="bab", t="b"）= 2：s 里有两个 b，各自都能匹配 t[0]。
  • dp[6][2]（s="babgba", t="ba"）= 4：有 4 种方式取 "ba"。
  • 最终 dp[7][3] = 5，就是答案。

English explanation:

  • dp[3][1] = 2: two bs in "bab" can each serve as the match for t[0]='b'.
  • dp[6][2] = 4: four ways to pick "ba" from "babgba".
  • Final answer dp[7][3] = 5.

Step 2: O(m×n) Space 完整实现 / Full O(m×n) Solution

def numDistinct(s: str, t: str) -> int:
    m, n = len(s), len(t)
    
    # dp[i][j] = ways to form t[0..j-1] from s[0..i-1]
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    
    # Base case: empty t can be formed from any prefix of s in exactly 1 way
    for i in range(m + 1):
        dp[i][0] = 1
    
    # Fill the table row by row (advance through s)
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            # Always carry forward the "skip s[i-1]" option
            dp[i][j] = dp[i-1][j]
            
            # If characters match, also add the "use s[i-1]" option
            if s[i-1] == t[j-1]:
                dp[i][j] += dp[i-1][j-1]
    
    return dp[m][n]

时间复杂度 / Time: O(m × n)

空间复杂度 / Space: O(m × n)

Step 3: O(n) Space 优化 / Space-Optimized Solution

中文：

注意到 dp[i][j] 只依赖 dp[i-1][j] 和 dp[i-1][j-1]，即上一行。可以用一维数组滚动更新，把空间压缩到 O(n)。

关键点： 必须从右往左更新，否则 dp[j-1] 会被提前覆盖（和 0/1 背包的滚动数组一样）。

English:

dp[i][j] only depends on the previous row. Use a 1D rolling array.

Critical: Iterate j right to left to avoid using already-updated values (same trick as 0/1 Knapsack).

def numDistinct_optimized(s: str, t: str) -> int:
    m, n = len(s), len(t)
    
    # dp[j] = ways to form t[0..j-1] using s seen so far
    dp = [0] * (n + 1)
    dp[0] = 1  # empty t: always 1 way
    
    for i in range(m):                   # advance through s
        # Iterate RIGHT TO LEFT to avoid overwriting dp[j-1] before we use it
        for j in range(n, 0, -1):
            if s[i] == t[j-1]:
                dp[j] += dp[j-1]         # match: add the "use s[i]" contribution
            # else: dp[j] stays (carry forward "skip s[i]" — already there)
    
    return dp[n]

时间复杂度 / Time: O(m × n)

空间复杂度 / Space: O(n) ← one row only

Step 4: 记忆化递归版本（自顶向下）/ Top-Down Memoization

中文：

如果你在面试中思路卡住，先写递归版本是完全合理的。自顶向下往往更容易写对，然后再优化。

English:

If you're stuck, start with top-down. It maps more naturally to the problem definition.

from functools import lru_cache

def numDistinct_memo(s: str, t: str) -> int:
    
    @lru_cache(maxsize=None)
    def dp(i: int, j: int) -> int:
        # Base cases
        if j == 0:
            return 1          # empty t: matched successfully
        if i == 0:
            return 0          # ran out of s but t still has chars
        
        # Always try skipping s[i-1]
        result = dp(i - 1, j)
        
        # If match, also try using s[i-1]
        if s[i-1] == t[j-1]:
            result += dp(i - 1, j - 1)
        
        return result
    
    return dp(len(s), len(t))

Part 3: Edge Cases & Gotchas / 边界情况 (2 min)

中文：

  1. t 比 s 长 → 不可能有子序列，答案为 0。DP 自然处理（dp 表格里 j > i 的格子始终为 0）。
  1. s == t → 恰好 1 种方式（不删任何字符），dp 对角线自然产生结果 1。
  1. t 为空字符串 → 返回 1（由 dp[i][0] = 1 保证）。
  1. 数字溢出 → 答案可能非常大（指数级）。Python 自动大整数，Java/C++ 注意用 long。
  1. 滚动数组方向错误 → 如果从左往右更新 1D dp，dp[j-1] 已经包含了当前行的更新，会重复计算同一个 s[i] 匹配多次。必须从右往左！

English:

  1. len(t) > len(s) → impossible; answer is 0. The DP handles this naturally.
  1. s == t → exactly 1 way. The diagonal fills correctly.
  1. Empty t → returns 1 by the base case dp[i][0] = 1.
  1. Integer overflow → results can be astronomical. Python is fine; Java/C++ use long.
  1. Wrong iteration direction in space-optimized version → iterating left-to-right lets dp[j-1] reflect the current row, causing a single s[i] to match t[j-1] multiple times. Always iterate right to left.

Part 4: Real-World Application / 实际应用 (2 min)

中文：

"不同子序列计数"这个模式在现实工程中有几个直接对应：

  1. 基因序列分析 / Bioinformatics: 统计 DNA 序列 s 中有多少种方式包含某个特征序列 t（例如限制性内切酶识别位点）。这是生物信息学里的核心问题。
  1. 自动补全评分 / Autocomplete Ranking: 判断用户输入 t 和候选词 s 的"模糊匹配"质量时，子序列计数可以作为相关性得分的一部分。
  1. 代码相似度检测 / Code Similarity: 检测一段代码片段是否被另一段"抄袭"但做了删减，子序列方案数可以衡量结构相似性。
  1. NLP 中的序列对齐: 在某些对齐模型里，统计一个句子生成另一个句子的所有对齐方式，本质上就是子序列计数。

English:

  1. Bioinformatics: Counting how many ways a DNA sequence contains a specific motif (enzyme recognition site) is exactly this problem.
  1. Fuzzy autocomplete scoring: Subsequence count is a natural similarity signal — more ways to embed the query means higher relevance.
  1. Plagiarism detection: Measuring how many ways a code fragment can be "derived" from another by deletion.
  1. NLP sequence alignment: Some generative alignment models count all ways to produce a target sequence from a source, which reduces to this DP.

Part 5: Interview Simulation / 面试模拟 (3 min)

场景设定 / Scenario:

你在 Meta/Google 的面试中，面试官给出这道题。以下是 5 个典型追问。

Q1: 你怎么想到用 DP 的？/ How did you identify this as a DP problem?

A:

中文：这道题有两个信号：(1) 求"方案数"而不是"是否存在"——凡是计数都要想 DP；(2) 两个字符串的关系，且没有明显的贪心策略——这是 2D DP 的强信号。

English: Two signals: (1) Counting rather than existence — counting problems almost always use DP. (2) Two strings with no obvious greedy — that's a 2D DP flag. I define state over all pairs of prefixes.

Q2: 能进一步优化空间吗？/ Can you optimize space further?

A:

中文：可以把 2D dp 压缩到 1D，从 O(mn) 降到 O(n)（n 是 t 的长度）。关键是从右往左更新，防止当前行的值影响自身的计算。理论上无法再压缩——因为你至少需要保存一行的所有状态。

English: Yes, 1D rolling array brings it from O(mn) to O(n). No further reduction is possible — you need at least one full row of t's states to compute the next row.

Q3: 如果 s 和 t 都很长（比如各 1000 字符），有没有更快的算法？/ What if s and t are very long?

A:

中文：O(mn) 是这类问题的理论下界（需要遍历所有 (i,j) 对）。但实践中，如果字母表很小（比如只有 4 个 DNA 碱基），可以用 bit-parallel 技巧把内层循环向量化，获得常数因子加速。对于极长字符串，也可以分块计算或用矩阵乘法在某些特殊情况下加速。

English: O(mn) is essentially optimal for the general case — you must examine all (i,j) pairs. With a small alphabet (e.g., DNA with 4 chars), bit-parallel tricks can vectorize the inner loop. For astronomical inputs you'd use blocking or approximation algorithms.

Q4: 转移方程里为什么不匹配时也要保留 dp[i-1][j]？/ Why do we always carry dp[i-1][j] even when characters match?

A:

中文：因为即使 s[i-1] 和 t[j-1] 相同，你仍然可以选择不用这个 s[i-1] 来匹配——把它跳过，让后面的字符去匹配。这是子序列的本质：每个 s 中的字符你可以用也可以不用。dp[i-1][j] 代表的就是"跳过 s[i-1]，用前 i-1 个字符匹配完整 t[0..j-1]"的方案数。

English: Even when s[i-1] == t[j-1], we're not forced to use that character. We can skip it and use a later occurrence. dp[i-1][j] captures all ways to match t[0..j-1] without consuming s[i-1]. Both choices are independent so we sum them.

Q5: 和 Edit Distance (#72) 有什么区别？它们的 DP 结构相似在哪？/ How does this compare to Edit Distance?

A:

中文：两者都是 2D DP，都在 s[i-1] == t[j-1] 时使用对角线转移 dp[i-1][j-1]。区别在于操作集：Edit Distance 允许插入、删除、替换（取三者最小值）；而 Distinct Subsequences 只允许删除（从 s 中删字符），且求的是方案数而不是最小代价。可以把 Distinct Subsequences 看作"只有删除操作的 Edit Distance 计数版"。

English: Both are 2D DP with diagonal transition when characters match. The difference: Edit Distance minimizes over insert/delete/replace; Distinct Subsequences counts over delete-only operations. DS is effectively "Edit Distance restricted to deletion, counting instead of minimizing."

🧠 Summary / 总结

Pattern / 模式2D Dynamic Programming
State / 状态dp[i][j] = ways to form t[0..j-1] from s[0..i-1]
Recurrence / 转移Match: dp[i-1][j-1] + dp[i-1][j]; No match: dp[i-1][j]
Base case / 边界dp[i][0] = 1, dp[0][j>0] = 0
Time / 时间O(m × n)
Space / 空间O(m × n) → O(n) with rolling array
Key gotcha / 易错点Rolling array must iterate right to left

核心直觉 / Core Intuition:

字符匹配时，你有选择；字符不匹配时，你没有选择。有选择时，两条路都加上。
When chars match, you have a choice — sum both paths. When they don't, you have no choice — carry forward.

3. 分布式事务三大模式

Stripe → Outbox + Idempotency Keys；Uber → SAGA + Temporal。
