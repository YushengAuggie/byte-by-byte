🏗️ 系统设计 / System Design — Design a Search Engine

场景 / Scenario:

想象你在设计 Google 或 Bing 的核心搜索功能。用户输入查询，你需要在几毫秒内从数十亿个网页中返回最相关的结果。

Imagine you are designing the core search functionality of Google or Bing. A user enters a query, and you need to return the most relevant results from billions of web pages in milliseconds.

架构图 / Architecture Diagram:

[User] --> [Load Balancer] --> [Web Servers]
                                     |
                                     v
                            [Query Processor]
                               /           \
                              /             \
                    [Index Cluster]    [Document Store]
                    (Inverted Index)   (HTML/Snippets)
                             |
                      [Ranker / ML]

核心权衡 / Key Tradeoffs:

  1. Inverted Index (倒排索引): 为什么不直接搜网页？因为太慢。倒排索引将单词映射到包含该单词的文档列表（就像书后的索引），极大加快了查询速度。/ Why not just search web pages directly? Too slow. An inverted index maps words to a list of documents containing them (like an index at the back of a book), drastically speeding up queries.
  2. Crawling vs Indexing (爬取 vs 索引): 爬虫（Crawler）异步抓取网页，索引器（Indexer）离线构建索引。查询时只访问索引，不接触爬虫。/ Crawlers fetch pages asynchronously, and Indexers build the index offline. Queries only hit the index, never the crawlers.
  3. Ranking (排名): 仅找到文档不够，还需要根据相关性（如 PageRank、TF-IDF、机器学习模型）进行排序。/ Finding documents isn't enough; they must be sorted by relevance (e.g., PageRank, TF-IDF, ML models).

常见误区 / Common Mistakes:

  • ❌ 实时更新索引 (Real-time index updates): 每次有新网页就更新整个索引。/ Updating the entire index every time a new page is found.
  • ✅ 正确做法 (Correct approach): 使用主索引（只读，定期构建）和辅助/内存索引（处理新文档），查询时合并结果。/ Use a main index (read-only, built periodically) and an auxiliary/in-memory index (for new docs), merging results at query time.

🧒 ELI5 (Explain Like I'm 5):

搜索引擎就像一个超级图书管理员。他不一页一页翻书找答案，而是提前做了一个巨大的“词汇表”，记录了每个词在哪些书的哪一页。你一问，他查词汇表，瞬间就把书找出来了！

A search engine is like a super librarian. Instead of flipping through books page by page to find answers, they made a giant "vocabulary list" beforehand, recording which books and pages contain each word. When you ask, they check the list and find the books instantly!

💻 算法 / Algorithms — #853 Car Fleet (Medium) — Stack

🧩 单调栈模式 (6/7) — building on the template from Day X

场景 / Real-world analogy:

想象你在高速公路上开车，前面有一辆慢车。你不能超车，只能减速跟在它后面，你们就成了一个“车队”。有多少个这样的车队能到达终点？

Imagine driving on a highway behind a slow car. You can't pass it, so you slow down and follow it, forming a "fleet." How many such fleets will reach the destination?

问题 / Problem:

有 n 辆车在单车道上行驶，目标是 target。每辆车有初始位置 position[i] 和速度 speed[i]。如果一辆车追上前面的车，它必须降速并与前车组成一个车队（视为一个整体）。求到达终点时的车队数量。

There are n cars driving on a single-lane road to a target. Each car has an initial position[i] and speed[i]. If a car catches up to the one ahead, it must slow down and form a fleet (treated as one entity). Find the number of car fleets arriving at the target.

映射到模板 / Map to pattern template:

  • 排序 (Sort): 首先按位置降序排序（离终点近的在前面）。/ Sort by position descending (closest to target first).
  • 时间 (Time): 计算每辆车到达终点所需的时间 (target - pos) / speed。/ Calculate time to reach target for each car.
  • 单调栈 (Monotonic Stack): 维护到达时间。如果后面的车（栈顶）比前面的车（栈顶的下一个）时间短或等于，说明它能追上，形成车队（弹出后面的车）。/ Maintain arrival times. If a car behind (top of stack) takes less or equal time than the car ahead (next in stack), it catches up, forming a fleet (pop the car behind).

Python 代码 / Python Solution:

def carFleet(target: int, position: List[int], speed: List[int]) -> int:
    # 1. 组合并按位置降序排序 / Combine and sort by position descending
    cars = sorted(zip(position, speed), reverse=True)
    stack = []
    
    # 2. 遍历每辆车 / Iterate through each car
    for pos, spd in cars:
        # 计算到达时间 / Calculate arrival time
        time = (target - pos) / spd
        stack.append(time)
        
        # 3. 如果当前车（后车）的时间 <= 前车的时间，说明追上了，合并车队
        # If current car (behind) time <= car ahead time, it catches up, merge fleet
        if len(stack) >= 2 and stack[-1] <= stack[-2]:
            stack.pop() # 弹出当前车（后车），保留前车的时间 / Pop current car, keep car ahead's time
            
    return len(stack) # 栈中剩余的元素个数就是车队数量 / Remaining elements are the number of fleets

复杂度 / Complexity:

  • 时间 / Time: O(N log N) (排序 / Sorting), O(N) (遍历 / Traversal). Total: O(N log N).
  • 空间 / Space: O(N) (栈和排序数组 / Stack and sorted array).

举一反三 / Connect to other problems:

  • #739 Daily Temperatures: 寻找下一个更大的元素（单调递减栈）。/ Find next greater element (monotonic decreasing stack).
  • #84 Largest Rectangle in Histogram: 寻找左右边界（单调递增栈）。/ Find left and right boundaries (monotonic increasing stack).

🧒 ELI5 (Explain Like I'm 5):

把车排成一排，离终点近的在最前面。算算每辆车自己开到终点要多久。如果后面的车算出来的时间比前面的短，说明它开得快，会追上前面的车，然后只能跟着前面的车慢慢开（变成一个车队）。我们用一个栈来记录每个车队的时间，最后栈里有几个时间，就有几个车队！

Line up the cars, closest to the finish line first. Calculate how long each car takes to reach the finish line on its own. If a car behind has a shorter time than the car ahead, it means it's faster, will catch up, and then must follow slowly (forming a fleet). We use a stack to record the time of each fleet. The number of times left in the stack is the number of fleets!

🗣️ 软技能 / Soft Skills — Tell me about a time you successfully navigated organizational change

为什么这很重要？ / Why this matters:

在快速发展的科技公司中，唯一不变的就是变化（重组、技术栈迁移、优先级调整）。高级/专家工程师（Senior/Staff）需要展现出在混乱中找到方向、稳定团队并推动落地的能力。

In fast-paced tech companies, the only constant is change (re-orgs, tech stack migrations, shifting priorities). Senior/Staff engineers must show they can find direction in chaos, stabilize the team, and drive execution.

STAR 拆解 / STAR Breakdown:

  • S (Situation): 描述一个具体的组织变革（例如：公司决定从单体架构迁移到微服务，或者你的团队被合并到另一个部门）。/ Describe a specific organizational change (e.g., migrating from monolith to microservices, or your team merging with another).
  • T (Task): 你的任务是什么？（不仅是写代码，还包括沟通、规划、缓解团队焦虑）。/ What was your task? (Not just coding, but communication, planning, mitigating team anxiety).
  • A (Action): 你采取了什么行动？（主动沟通、制定过渡计划、建立反馈机制）。/ What actions did you take? (Proactive communication, creating a transition plan, setting up feedback loops).
  • R (Result): 结果如何？（平稳过渡、系统上线、团队士气恢复）。/ What was the result? (Smooth transition, system launch, team morale restored).

❌ 糟糕的回答 / Bad Answer:

“公司突然要换框架，我只能跟着学，然后把代码重写了一遍。虽然很烦，但我还是完成了。”

"The company suddenly wanted to switch frameworks, so I had to learn it and rewrite the code. It was annoying, but I got it done."

(被动接受，抱怨，没有展现领导力 / Passive acceptance, complaining, no leadership shown)

✅ 优秀的回答 / Good Answer:

“当公司决定从 AWS 迁移到 GCP 时，团队很焦虑。我主动组织了技术分享会，梳理了迁移的风险点，并制定了分阶段的迁移计划。我还与运维团队建立了每日同步机制，确保问题及时解决。最终我们提前两周完成了迁移，并且零故障。”

"When the company decided to migrate from AWS to GCP, the team was anxious. I proactively organized tech sharing sessions, identified migration risks, and created a phased plan. I also set up daily syncs with Ops to resolve issues quickly. We finished two weeks early with zero downtime."

(主动出击，稳定军心，跨团队协作 / Proactive, stabilizing the team, cross-team collaboration)

💡 Senior/Staff 提示 / Senior/Staff Tips:

  • Focus on the "Why": 解释你如何理解并传达变革背后的商业逻辑。/ Explain how you understood and communicated the business logic behind the change.
  • Manage Up and Down: 你不仅要安抚下属，还要向上管理预期。/ You must manage expectations up and soothe anxiety down.

🔑 核心收获 / Key Takeaways:

拥抱变化，成为团队的“稳定器”，而不是“抱怨者”。

Embrace change and be the "stabilizer" for the team, not the "complainer."

🎨 前端 / Frontend — Event Loop — Microtasks, Macrotasks, requestAnimationFrame

场景 / Real-world scenario:

你在做一个 dashboard，需要在一个复杂的计算后立即更新 UI，但发现页面卡死了，或者动画掉帧了。为什么？因为你可能阻塞了主线程，或者没有正确理解 JavaScript 的事件循环。

You're building a dashboard and need to update the UI immediately after a heavy calculation, but the page freezes or animations drop frames. Why? You might have blocked the main thread or misunderstood the JavaScript Event Loop.

核心概念 / Core Concept:

JavaScript 是单线程的，它通过事件循环 (Event Loop)来处理异步任务。

JavaScript is single-threaded and uses the Event Loop to handle asynchronous tasks.

执行顺序 / Execution Order:

  1. 同步代码 (Synchronous code): 立即执行。/ Execute immediately.
  2. 微任务 (Microtasks): 当前宏任务结束后，在浏览器渲染之前执行。例如：Promise.then、MutationObserver。/ Execute after the current macrotask, before browser rendering. E.g., Promise.then, MutationObserver.
  3. 宏任务 (Macrotasks): 在下一次事件循环中执行。例如：setTimeout、setInterval、setImmediate (Node.js)、I/O、UI 渲染。/ Execute in the next event loop iteration. E.g., setTimeout, setInterval, setImmediate (Node.js), I/O, UI rendering.
  4. requestAnimationFrame (rAF): 在浏览器下一次重绘之前执行，通常是每秒 60 次（约 16.6ms）。/ Execute before the next browser repaint, typically 60 times per second (~16.6ms).

代码示例 / Code Snippet:

console.log('1. 同步代码 / Sync');

setTimeout(() => {
  console.log('5. 宏任务 / Macrotask (setTimeout)');
}, 0);

Promise.resolve().then(() => {
  console.log('3. 微任务 / Microtask (Promise)');
});

requestAnimationFrame(() => {
  console.log('4. rAF (在下一次重绘前 / Before next repaint)');
});

console.log('2. 同步代码 / Sync');

猜猜输出什么？ / Quiz:

A) 1, 2, 3, 4, 5

B) 1, 5, 3, 4, 2

C) 1, 2, 3, 5, 4

D) 1, 3, 2, 4, 5

答案：A

常见误区 / Common Mistake:

  • ❌ 用 setTimeout 做动画 (Using setTimeout for animations): setTimeout 不保证执行时间，可能会导致掉帧。/ setTimeout doesn't guarantee execution time, which can lead to dropped frames.
  • ✅ 用 requestAnimationFrame 做动画 (Using rAF for animations): 浏览器会自动优化，保证动画流畅。/ The browser optimizes it automatically for smooth animations.

何时使用 / When to use:

  • 微任务 (Microtasks): 需要在当前任务完成后立即执行，且不希望被渲染打断的操作（如状态更新后的副作用）。/ Operations that need to run immediately after the current task, without being interrupted by rendering (e.g., side effects after state updates).
  • 宏任务 (Macrotasks): 可以稍后执行的低优先级任务（如定时器、网络请求回调）。/ Low-priority tasks that can run later (e.g., timers, network request callbacks).
  • rAF: 任何涉及视觉更新或动画的操作。/ Any operation involving visual updates or animations.

🧒 ELI5 (Explain Like I'm 5):

事件循环就像一个餐厅服务员。他先把你点好的菜端上来（同步代码），然后马上把桌子上的空盘子收走（微任务），接着去厨房看看有没有新做好的菜（宏任务）。如果餐厅要关门打扫了，他会在打扫前把最后一点活干完（rAF）。

The event loop is like a waiter. He serves the food you ordered right away (sync code), then immediately clears the empty plates from the table (microtasks), and then checks the kitchen for newly prepared dishes (macrotasks). If the restaurant is about to close for cleaning, he finishes the last bit of work before cleaning (rAF).
