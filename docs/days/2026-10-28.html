Imagine you're an architect at Snowflake / Databricks / Vercel. You need to design a multi-tenant control plane: thousands of customers share underlying infrastructure, but each tenant's data, quotas, and secrets are strictly isolated. 关键权衡 / Key Tradeoffs

决策 Decision为什么 Why
Cell-based (shuffle sharding)Blast radius 隔离：一个 cell 挂掉只影响部分租户。AWS、Slack 都用。参考 Shuffle Sharding 论文。
Pool model + Silo for enterprise小客户共享 Postgres schema (cheap)，大客户独立数据库 (security/compliance)。
Global metadata ≠ Global datatenant→cell mapping 用强一致存储；业务数据永远留在 cell 内，不跨区同步。

别踩这个坑 / Common Mistakes

  1. "noisy neighbor" via connection pool — 一个租户的慢查询吃光共享 pgbouncer 连接。解法：per-tenant pool quotas + pg_stat_activity 监控 + 自动 kill 长查询。
  2. Tenant ID 只在 app 层 enforce — SQL injection 或代码 bug 一旦漏 WHERE tenant_id=?，所有租户数据暴露。必须用 Postgres Row-Level Security (RLS) 做兜底。
  3. 跨 cell 的 "backfill" 作业变成单点 — ETL 一旦全局运行就违背了 cell 隔离。每个 cell 独立跑。
  4. Feature flag per-tenant 爆炸 — 10k 租户 × 100 flags = 1M flag evaluations/s。要本地缓存 + bulk evaluation API。
  5. Trace sampling 全局 1% — 大租户看不到自己的问题。改成 per-tenant sampling rate，关键租户 100% 采样。

💻 算法 / Algorithms — #1143 Longest Common Subsequence (🟡 Medium) — 2-D Dynamic Programming

🧩 二维动态规划模式 (2/11) — building on the template from Day 143 (#62 Unique Paths)

🔗 LeetCode: https://leetcode.com/problems/longest-common-subsequence/

📹 NeetCode: https://www.youtube.com/watch?v=Ua0GhsJSlWM

从 Unique Paths 到 LCS — 模板的变化 / From Unique Paths to LCS

昨天 Unique Paths 的 dp[i][j] 代表"到达格子 (i,j) 的路径数"，转移是 纯加法：dp[i][j] = dp[i-1][j] + dp[i][j-1]。

今天 LCS 的 dp[i][j] 代表 "text1[:i] 和 text2[:j] 的最长公共子序列长度"。核心变化：转移取决于两个字符串当前字符是否相等。

Yesterday: pure additive transition. Today: conditional transition — the recurrence branches on whether text1[i-1] == text2[j-1].

真实场景 / Real-World Analogy

Git diff / merge 底层就是 LCS 变体。diff a.txt b.txt 要找出两份文件最大重合的行序列，剩下的就是增删。字符串比对、DNA 测序、拼写检查、subtitle 对齐，全是 LCS 家族。

Git diff is literally LCS over lines. DNA alignment (BLAST), spell-check, subtitle sync — all LCS-based.

问题 / Problem

给两个字符串 text1, text2，返回它们最长公共子序列的长度（子序列不要求连续，但保持相对顺序）。

Example: text1 = "abcde", text2 = "ace" → 3 (subsequence "ace").

映射到模板 / Map to Template

# Template reminder:
# dp = [[0] * (m+1) for _ in range(n+1)]
# for i in 1..n: for j in 1..m: dp[i][j] = TRANSITION(dp[i-1][j], dp[i][j-1], dp[i-1][j-1])

def longestCommonSubsequence(text1: str, text2: str) -> int:
    n, m = len(text1), len(text2)
    # dp[i][j] = LCS length of text1[:i] and text2[:j]
    # Row 0 and col 0 are the "empty prefix" sentinel — stays 0.
    dp = [[0] * (m + 1) for _ in range(n + 1)]

    for i in range(1, n + 1):
        for j in range(1, m + 1):
            if text1[i - 1] == text2[j - 1]:
                # Match: extend the LCS of the shorter prefixes by 1
                dp[i][j] = dp[i - 1][j - 1] + 1
            else:
                # No match: skip one char from either string, take the better
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])

    return dp[n][m]

手动追踪 / Trace: "abcde" vs "ace"

         ""  a   c   e
      ""  0  0   0   0
      a   0  1   1   1
      b   0  1   1   1
      c   0  1   2   2
      d   0  1   2   2
      e   0  1   2  [3]

每格看 "左 / 上 / 左上+1(匹配时)"。右下角 3 就是答案。手动画一次表格，所有二维 DP 都能秒懂。

复杂度 / Complexity

  • Time: O(n·m) — fill entire table
  • Space: O(n·m) → optimizable to O(min(n, m)) using 2 rolling rows (or 1 row + prev_diag var)
# Space-optimized O(m)
def lcs(text1, text2):
    if len(text1) < len(text2): text1, text2 = text2, text1
    prev = [0] * (len(text2) + 1)
    for c1 in text1:
        curr = [0] * (len(text2) + 1)
        for j, c2 in enumerate(text2, 1):
            curr[j] = prev[j-1] + 1 if c1 == c2 else max(prev[j], curr[j-1])
        prev = curr
    return prev[-1]

🗣️ 软技能 / Soft Skills — Synthesis: Writing a Staff-Level Promotion Packet

Senior → Staff 升职的核心难点不是"做了什么"，而是如何讲清楚你的 scope、leverage、impact。所有 60 道行为题的本质其实都是在训练这三件事的叙事能力。今天综合一个 Staff 升职 packet 的写作框架。

The hardest part of Senior → Staff isn't what you did — it's articulating scope, leverage, and impact. All 60 behavioral questions trained these three narrative muscles. Today: a synthesis — the Staff promo packet framework.

为什么重要 / Why This Matters

Staff+ 是公司对你的赌注：你是不是能让 整个组织 变得更好，而不只是写好自己的代码。Promo committee 看的是 lasting change，不是 shipped tickets。

Staff+ is a bet that you make the org better, not just your tickets. Committees look for lasting change.

Staff Packet 的 STAR+L 框架 / STAR+L Framework

Situation · Task · Action · Result · Leverage

传统 STAR 卡在"你一个人做了什么"。Staff 层级必须加 L (Leverage)：你的工作如何通过别人放大？

要素Senior 版本Staff 版本
Situation"Service was slow""Company's largest revenue surface had 2x latency SLO breach impacting 3 PMs' roadmaps"
Task"I was asked to fix it""I proposed and secured funding for a 6-month platform migration"
Action"I rewrote the hot path""I wrote the RFC, built the first vertical slice, then enabled 4 teams to migrate independently via a self-serve toolkit"
Result"p99 dropped 40%""p99 dropped 40%, 4 teams migrated with zero on-call support from me, pattern adopted by 2 other orgs"
Leverage—"My RFC + toolkit → 25 engineers now ship 2x faster on this platform"

❌ Bad vs ✅ Good — 真实 Promo Bullet

❌ Bad (Senior-level thinking):

"Led migration of auth service to new framework. Reduced p99 by 40%."

Promo committee 心里：So what? Did anyone else benefit? What was hard?

✅ Good (Staff-level narrative):

"Identified org-wide risk: 7 services relied on a deprecated auth library with 2 known CVEs. Instead of fixing them one-by-one (6 months × 7 teams), I designed a shared migration framework (RFC #412), built a reference migration, and ran weekly office hours. Outcome: all 7 services migrated in 8 weeks; framework reused for 3 subsequent library migrations; 2 teams promoted engineers using this work."

三个 staff signal: (1) org-wide problem framing, (2) leverage via framework not fix, (3) second-order outcomes (reuse, promotions).

Senior/Staff 层级的 3 个常见陷阱 / 3 Common Pitfalls

  1. "Hero narrative" 陷阱 — 全写"我一个人救火"。Staff 该写的是"我设计了一个系统，让火不再发生"。
  2. 缺少 counterfactual — 不说明"如果没有我这个工作会怎样"。Promo committee 的默认假设：别人也能做。你要显式反驳。
  3. Impact 单位错了 — Senior 以 service/feature 为单位；Staff 以 org / quarterly plan / headcount saved 为单位。把 "40% latency reduction" 翻译成 "$X in prevented revenue loss" 或 "unblocked 2 PM roadmaps"。

Key Takeaways

  • Scope: 讲 problem framing，不要讲 task assignment
  • Leverage: 每个 bullet 都问"这个工作如何通过别人放大？"
  • Impact in business units: latency → revenue, bugs → trust, migrations → engineer-weeks saved
  • Written artifacts win: RFC、design doc、postmortem 是最硬的 staff 证据
  • Peer feedback is signal: Promo committee 更信 cross-team peers 的反馈，不信你 manager
