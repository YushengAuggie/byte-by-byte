## 真实场景 / Real Scenario

你在 code review 中看到同事写了这段代码：

```javascript
class Button {
  constructor(label) {
    this.label = label;
  }
  click() {
    console.log(`Clicked: ${this.label}`);
  }
}

const btn = new Button("Submit");
document.getElementById("btn").addEventListener("click", btn.click);
// User clicks → what happens?
```

点击后输出什么？

---

## 🤔 猜猜看 / Pop Quiz

**点击按钮后，控制台输出是？/ What does the console log?**

A) `"Clicked: Submit"`
B) `"Clicked: undefined"`
C) `TypeError: Cannot read properties of undefined`
D) Nothing, no error

<details><summary>显示答案 / Show Answer</summary>

**答案：B — `"Clicked: undefined"`**

原因：`btn.click` 作为回调传入时，`this` 绑定丢失了。事件触发时 `this` 指向 DOM 元素（`<button>`），而不是 `btn` 实例，所以 `this.label` 是 `undefined`。

Reason: When `btn.click` is passed as a callback, the `this` binding is lost. When the event fires, `this` refers to the DOM element, not the `btn` instance.

</details>

## 原型链 / Prototype Chain

JavaScript 中，**每个对象都有一个隐式指针指向它的"原型"**。当你访问一个属性，JS 先在对象本身找，找不到就沿着原型链往上找。

```javascript
const btn = new Button("Submit");

// btn 的原型链：
// btn → Button.prototype → Object.prototype → null

// 查找 btn.click 的过程：
// 1. btn 自身有 click 属性吗？❌
// 2. Button.prototype 有吗？✅ → 找到了
```

```javascript
// 可以直接验证：
console.log(btn.__proto__ === Button.prototype); // true
console.log(Button.prototype.__proto__ === Object.prototype); // true

// class 语法是 prototype 的语法糖：
// class Button {} === function Button() {} + Button.prototype.click = ...
```

## `this` 绑定规则 / The 4 Rules of `this`

```javascript
// 规则 1: 默认绑定 — 独立调用时 this = global/undefined(strict)
function greet() { console.log(this); }
greet(); // window (browser) or undefined (strict mode)

// 规则 2: 隐式绑定 — 方法调用时 this = 调用它的对象
const obj = { name: "Alice", greet() { console.log(this.name); } };
obj.greet(); // "Alice" ✅

// 规则 3: 显式绑定 — call/apply/bind
greet.call({ name: "Bob" }); // "Bob"
const boundGreet = obj.greet.bind({ name: "Charlie" });
boundGreet(); // "Charlie"

// 规则 4: new 绑定 — 构造函数中 this = 新创建的对象
const btn = new Button("Submit"); // this = btn
```

## ❌ 常见错误 vs ✅ 正确做法

```javascript
// ❌ 错误：this 绑定丢失
document.getElementById("btn").addEventListener("click", btn.click);
// 点击时 this = DOM element，不是 btn

// ✅ 方法 1：bind
document.getElementById("btn").addEventListener("click", btn.click.bind(btn));

// ✅ 方法 2：箭头函数（推荐，更简洁）
document.getElementById("btn").addEventListener("click", () => btn.click());
// 箭头函数没有自己的 this，捕获外层 this

// ✅ 方法 3：类字段语法（React 中最常见）
class Button {
  label: string;
  // 箭头函数作为类字段 — this 永远绑定到实例
  click = () => {
    console.log(`Clicked: ${this.label}`);
  };
}
// 代价：每个实例都有一份 click 函数的拷贝（vs 原型方法共享一份）
```

## 箭头函数 vs 普通函数的 this / Arrow vs Regular

```javascript
class Timer {
  constructor() {
    this.seconds = 0;
  }
  
  // ❌ 普通函数：this 丢失
  startWrong() {
    setInterval(function() {
      this.seconds++; // this = window/undefined!
    }, 1000);
  }
  
  // ✅ 箭头函数：捕获外层 this
  startCorrect() {
    setInterval(() => {
      this.seconds++; // this = Timer instance ✅
    }, 1000);
  }
}
```

**核心规则：箭头函数没有自己的 `this`，它"继承"外层作用域的 `this`。**
Arrow functions don't have their own `this` — they inherit it from the enclosing lexical scope.

## 何时用 / When to Use

| 场景 | 选择 |
|------|------|
| React class 组件方法 | 类字段箭头函数 `handleClick = () => {}` |
| 原型方法（共享逻辑）| 普通方法 `method() {}` |
| 回调中需要 this | 箭头函数 `() => this.xxx` |
| 工具库 polyfill | `.bind(context)` |
| 需要动态 this | 普通函数 + 显式绑定 |

## 🧒 ELI5 / 小孩版解释

JavaScript 里的 `this` 就像"代词我"——它的意思取决于说话的人是谁。如果你把"我的名字"这句话录下来，播放给别人，"我"就会变成播放的人，而不是你。`bind()` 就像把"我"直接替换成你的名字，这样不管谁播放都是对的。原型链就像家族遗传——找不到的属性就去问"父辈"。

In JS, `this` is like the word "I" — it depends on WHO is speaking. If you record "my name is..." and play it for someone else, "my" becomes them, not you. `bind()` is like replacing "my" with your actual name so it's always correct. Prototype chains are like family genes — if you don't have a trait, check your parents.
