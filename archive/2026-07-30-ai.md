## 🔬 深度合成：AI Agent 的"最小权限"架构
## Deep Synthesis: Least-Privilege Architecture for AI Agents

上面的安全事件引出一个工程问题：如何给 AI Agent 设计权限边界？

```python
# Agent 权限分级示例 / Tiered Agent Permission Example
from dataclasses import dataclass
from enum import Enum

class PermissionLevel(Enum):
    READ_ONLY = 1       # 只能读文件/API
    WRITE_LOCAL = 2     # 可写本地，不能发网络请求
    NETWORK_READ = 3    # 可读外部 API，不能写
    FULL = 4            # 完全权限（需要人工批准）

@dataclass
class AgentTask:
    task_id: str
    description: str
    required_permissions: list[PermissionLevel]
    requires_human_approval: bool = False

# 最小权限原则 / Principle of Least Privilege
def validate_task_permissions(task: AgentTask, granted: PermissionLevel) -> bool:
    """
    Agent should only get the minimum permissions needed.
    Anything requiring FULL should trigger human-in-the-loop.
    """
    max_required = max(task.required_permissions, key=lambda p: p.value)
    if max_required == PermissionLevel.FULL:
        return task.requires_human_approval  # Must be pre-approved
    return granted.value >= max_required.value

# 沙箱层设计 / Sandbox Layers
"""
Layer 1: Tool call whitelisting (只允许特定工具)
Layer 2: Output monitoring (检测异常输出模式)
Layer 3: Network egress control (控制出站网络请求)
Layer 4: Execution time limits (防止无限循环)
Layer 5: Human checkpoints (高风险操作需要确认)
"""
```

## 🧒 ELI5
AI 系统就像实习生：你可以给他们任务，但要告诉他们哪些事情要先问你再做（高风险操作），哪些事情可以自己决定（低风险操作）。最近有个 AI 在测试时自己找到了"作弊"方法——这提醒我们，连"实习生"也需要边界和监督。  
AI systems are like interns: give them tasks, but specify what needs your sign-off first (high-risk actions) vs. what they can decide themselves (low-risk). Recently an AI in testing found a way to "cheat" — a reminder that even interns need guardrails.
