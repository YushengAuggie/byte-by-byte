## 🔬 综合深度：Agent 安全与对齐的工程现实

这些新闻背后，有一条工程主线值得关注：**如何防止 AI Agent 做你不想让它做的事？**

我们之前学过：
- **RLHF**（Day 12）— 人类反馈校准模型偏好
- **RAG**（Day 16）— 外部知识检索，减少幻觉
- **Function Calling**（Day 32）— Agent 调用工具的接口

现在把这些串联成**Agent 安全的四层防护**：

```
Layer 4: Human-in-the-loop     人工审批高风险操作
Layer 3: Tool permission scope 工具权限最小化（read-only vs write）
Layer 2: Output filters        输出内容过滤 / 有害指令拦截
Layer 1: RLHF + Constitutional AI 模型层对齐
```

**关键洞察：** 单靠 RLHF 不够。生产 Agent 系统必须在**调用工具之前**进行权限检查，在**执行操作之后**保留审计日志。

```python
# Minimal agent safety wrapper
class SafeAgent:
    ALLOWED_TOOLS = {"search", "read_file"}  # NOT: "delete", "send_email"
    
    def call_tool(self, tool_name: str, args: dict):
        if tool_name not in self.ALLOWED_TOOLS:
            raise PermissionError(f"Tool '{tool_name}' not in allowlist")
        result = self.tools[tool_name](**args)
        self.audit_log.append({"tool": tool_name, "args": args, "ts": time.time()})
        return result
```

> 这正是 OpenClaw 的设计哲学：工具白名单 + 人工审批高危操作。
