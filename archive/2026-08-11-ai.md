## 技术一：KV Cache — 避免重复计算

**问题**: Transformer 每生成一个 token，都要重新计算所有历史 token 的 Key/Value。
**解法**: 缓存已计算的 K/V，只计算新 token。

```python
# Simplified KV Cache simulation
class SimpleKVCache:
    def __init__(self):
        self.key_cache = []    # cached keys per layer
        self.value_cache = []  # cached values per layer
    
    def append(self, new_key, new_value):
        """Add new token's K/V to cache"""
        self.key_cache.append(new_key)
        self.value_cache.append(new_value)
    
    def get_all_keys(self):
        return self.key_cache  # reuse without recomputing!

# Without KV cache: O(n²) compute for n tokens
# With KV cache:    O(n) compute, O(n) memory trade-off
# Memory cost: 2 * layers * heads * seq_len * d_head * bytes_per_param
```

**关键权衡**: KV cache 用内存换时间。长上下文 = 大 cache = 可能 OOM。
这就是为什么 128K context window 的模型需要那么多 GPU 显存。

## 技术二：Speculative Decoding — 用小模型猜，大模型验

**问题**: 大模型生成是串行的，每个 token 都要走一遍完整的前向传播。
**解法**: 用一个小"草稿"模型(draft model)先快速生成 4-8 个 token，然后用大模型并行验证。

```python
import random

def speculative_decode(draft_model, target_model, prompt, k=4):
    """
    Simplified speculative decoding loop.
    draft_model: small/fast model (e.g. 7B)
    target_model: large/accurate model (e.g. 70B)
    k: number of draft tokens to generate per round
    """
    tokens = list(prompt)
    
    while True:
        # Step 1: Draft model generates k tokens quickly
        draft_tokens = draft_model.generate(tokens, num_tokens=k)
        
        # Step 2: Target model evaluates ALL draft tokens in ONE forward pass
        # (parallel, not sequential — this is the speedup!)
        target_probs = target_model.get_probs(tokens + draft_tokens)
        
        # Step 3: Accept/reject each draft token
        accepted = []
        for i, draft_tok in enumerate(draft_tokens):
            p_target = target_probs[i][draft_tok]
            p_draft = draft_model.prob(tokens + accepted, draft_tok)
            
            # Accept with probability min(1, p_target/p_draft)
            if random.random() < min(1.0, p_target / p_draft):
                accepted.append(draft_tok)
            else:
                # Reject: sample from corrected distribution
                accepted.append(sample_corrected(target_probs[i], p_draft, draft_tok))
                break  # restart from here
        
        tokens.extend(accepted)
        if is_done(tokens):
            break
    
    return tokens

# Typical speedup: 2-3x on compatible model pairs
# Key: target model's output distribution is PRESERVED (mathematically proven)
```

**关键**: 加速比取决于草稿模型的"命中率"。通常同系列小模型效果最好 (Llama-7B 草稿 + Llama-70B 验证)。

## 技术三：Quantization 实战代码

```python
# pip install bitsandbytes transformers accelerate

from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig
import torch

# 4-bit NF4 quantization (QLoRA style)
bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",         # NormalFloat4 — better for LLMs
    bnb_4bit_compute_dtype=torch.bfloat16,  # compute in bf16, store in 4bit
    bnb_4bit_use_double_quant=True,    # quantize the quantization constants too
)

model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-2-7b-hf",
    quantization_config=bnb_config,
    device_map="auto"  # auto-distribute across available GPUs
)

# Memory comparison:
# fp32:  7B params × 4 bytes = 28 GB  (needs A100 80GB)
# fp16:  7B params × 2 bytes = 14 GB  (needs A100 40GB)
# int8:  7B params × 1 byte  =  7 GB  (RTX 3090 works!)
# nf4:   7B params × 0.5 byte = 3.5 GB (RTX 3060 works!)
print(f"Model memory: {model.get_memory_footprint() / 1e9:.1f} GB")
```

## 🧒 ELI5
三个省钱妙招：① KV Cache = 做过的计算存起来别重算（像记笔记）；② Speculative Decoding = 让一个聪明的学生先猜答案，老师只需确认或纠正（比老师从头想快多了）；③ Quantization = 把精确数字换成近似值，文件变小10倍但效果差不多。

Three cost-cutting tricks: ① KV Cache = save work you've already done (like notes); ② Speculative Decoding = let a smart student guess first, teacher just confirms (much faster than teacher thinking from scratch); ③ Quantization = use approximate numbers instead of precise ones — 10x smaller, barely any quality loss.
