## 直觉解释 / Intuitive Explanation

过去 5 年，AI 进步的主要来源是：**训练更久，用更多数据**（Scaling Law）。

但 2024-2025 年涌现出一个新范式：**让模型在推理时"想更长时间"**，而不是只依赖训练时学到的知识。

> 类比：给一个学生更多的考试时间，让他能检查答案、反复思考——而不只是增加他的备考时间。

这就是 **Test-Time Compute（TTC）**，也叫推理时扩展（Inference-Time Scaling）。

---

## 它是如何工作的？ / How It Works

### 方法 1：Chain-of-Thought（思维链）
```
普通推理：
  问题 → 答案

CoT 推理：
  问题 → 步骤1 → 步骤2 → 步骤3 → ... → 答案

模型"思考"的 token 越多，对复杂问题的准确率越高
```

### 方法 2：Self-Consistency（自一致性）
```python
# 伪代码：采样多个推理路径，投票选最优答案
answers = []
for _ in range(N):  # 生成 N 个独立答案
    answer = model.generate(problem, temperature=0.7)
    answers.append(answer)

final = majority_vote(answers)  # 多数投票
```

### 方法 3：MCTS + LLM（蒙特卡洛树搜索）
```
                   问题
                  /    \
           路径A        路径B
          /    \       /    \
        A1      A2   B1      B2
        ✗       ✓    ✗       ✗

模型探索多条推理路径，用奖励模型评估中间步骤
最著名实现：OpenAI o1/o3, DeepSeek-R1
```

## 为什么这很重要 / Why This Matters

**训练时扩展的局限：**
- 更多数据/参数 → 效果提升越来越难（收益递减）
- 成本指数增长
- 训练一次，能力固定

**测试时扩展的优势：**
- 对简单问题：少想（省算力）
- 对复杂问题：多想（准确率高）
- **动态分配算力**，而非固定

```
传统模型：
  简单问题: ████ 相同计算
  困难问题: ████ 相同计算

TTC 模型：
  简单问题: ██ 快速回答
  困难问题: ████████████ 深度推理
```

## 实际效果对比 / Real-World Impact

**数学推理（竞赛级别）：**
- GPT-4（标准）: AIME 数学竞赛约 ~10% 准确率
- o1（大量思考 token）: 显著提升至竞赛水平

**代码生成：**
- 标准 LLM：直接输出代码
- TTC 模型：生成 → 自我检查 → 发现 bug → 修复 → 输出

## 可运行代码 / Runnable Example

```python
# pip install openai

import openai

client = openai.OpenAI()

# 标准推理（快但不深）
def standard_answer(question):
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": question}],
        max_tokens=200
    )
    return response.choices[0].message.content

# 模拟 CoT — 增加推理步骤
def cot_answer(question):
    prompt = f"{question}\n\nLet's think step by step:"
    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": prompt}],
        max_tokens=1000  # 允许更长的"思考"
    )
    return response.choices[0].message.content

# 自一致性投票
def self_consistent_answer(question, n=5):
    from collections import Counter
    
    answers = []
    for _ in range(n):
        response = client.chat.completions.create(
            model="gpt-4o-mini",
            messages=[{"role": "user", "content": question}],
            temperature=0.7,  # 增加多样性
            max_tokens=300
        )
        answers.append(response.choices[0].message.content)
    
    # 对于数学题，提取最终数字答案投票
    # 这里简化为返回所有答案供人工对比
    return answers

if __name__ == "__main__":
    q = "If a train travels 120 km in 1.5 hours, what is its average speed?"
    
    print("Standard:", standard_answer(q))
    print("\nCoT:", cot_answer(q))
    print("\nSelf-consistent (5 samples):", self_consistent_answer(q, n=3))
```

## 局限性与权衡 / Limitations & Trade-offs

| 优势 | 局限 |
|------|------|
| 复杂推理准确率高 | 延迟高（o1 类模型秒级 → 分钟级） |
| 动态算力分配 | API 成本随"思考 token"线性增加 |
| 无需重新训练 | 需要奖励模型引导（RLHF/RLAIF） |
| 对数学/代码效果显著 | 对事实性问题提升有限 |

**工程实践建议：**
- 用户查询简单 → 标准模型（省成本）
- 代码生成/调试 → TTC 模型（准确率优先）
- 实时系统 → TTC 不合适（延迟太高）
