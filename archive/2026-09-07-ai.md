### 🔗 关键连接：这些概念如何互相依赖 / Key Dependencies

**为什么 RAG 需要 Embeddings + Vector DB？**

```python
# RAG Pipeline — 3个核心组件的协作
# 1. Embeddings (Day 6): 把文本变成向量
text = "Python GIL locks prevent true parallelism"
embedding = embed_model.encode(text)  # shape: [1536]

# 2. Vector DB (Day 18): 存储和检索相似向量
similar_docs = vector_db.query(embedding, top_k=5)

# 3. LLM + Context (Day 34): 用检索到的上下文生成答案
prompt = f"Context: {similar_docs}\n\nQuestion: {user_query}"
answer = llm.generate(prompt)
```

没有 Embeddings，RAG 无法度量相似度；没有 Vector DB，RAG 无法高效检索；没有足够的 Context Window，RAG 放不下检索结果。

**为什么 Agent 需要 Function Calling + Context？**

```python
# ReAct Agent Loop (Day 26) — 依赖 Function Calling (Day 32)
def agent_loop(user_query, tools, max_steps=10):
    messages = [{"role": "user", "content": user_query}]
    
    for step in range(max_steps):
        # LLM 决定: 思考 or 调用工具?
        response = llm.chat(messages, tools=tools)
        
        if response.tool_calls:
            # 执行工具 (Function Calling)
            for call in response.tool_calls:
                result = execute_tool(call.name, call.args)
                messages.append({"role": "tool", "content": result})
        else:
            # 没有工具调用 = 最终答案
            return response.content
    
    return "Max steps reached"

# 关键: 每步都消耗 Context Window tokens
# 这就是为什么 Context Window size 直接限制了 Agent 能做多复杂的任务
```

### ⚡ 性能优化全栈 / The Full Optimization Stack

```
问题: LLM 推理太慢/太贵
    ↓
1. KV Cache (Day 46): 避免重复计算 attention — 最重要的优化
   prefill: O(n²) → decode: O(n) per token with cache

2. Quantization (Day 44): 减少模型大小
   FP32 → FP16: 2x内存节省 | INT4: 8x内存节省
   精度损失 <1% (通常可接受)

3. Speculative Decoding (Day 46): 小模型打草稿，大模型验证
   小模型生成 K tokens → 大模型并行验证 → 平均接受 rate ~70%
   效果: 2-3x 吞吐量提升

4. MoE (Day 42): 只激活部分参数
   Mixtral 8x7B: 47B 参数，每次只用 13B
   训练成本 ~1/3，推理成本 ~1/3
```

### 💡 面试高频合成题 / High-Frequency Synthesis Questions

**Q: RAG vs Fine-tuning，什么时候用哪个？**
- RAG: 知识经常更新、需要引用来源、域外知识注入 → **灵活，无需训练**
- Fine-tuning: 固定风格/格式、特定任务、小模型专精 → **训练成本，推理快**

**Q: 为什么 GPT-4 比 GPT-3 对齐更好？**
- RLHF (Day 12) + Constitutional AI → 人类偏好建模
- 更多的 SFT 数据 + PPO 强化学习 → 减少有害输出

**Q: 怎么让 Agent 更可靠？**
- 工具调用加 schema 验证 (Structured Output)
- 关键步骤加 human-in-the-loop
- 设置 max_steps 防止无限循环
- 记录每步的 reasoning trace 便于调试
