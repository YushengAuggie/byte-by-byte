## 快速复习 / Quick Recap

```
LLM 推理的两个阶段：
┌─────────────────────────────────────────────────────┐
│  Prefill (预填充)                                    │
│  输入 prompt → 计算所有 token 的 KV → 生成第一个 token │
│  特点：可并行，GPU 利用率高                           │
├─────────────────────────────────────────────────────┤
│  Decode (解码)                                       │
│  逐 token 生成，每步只生成1个 token                   │
│  特点：串行，内存带宽瓶颈，GPU 利用率低               │
└─────────────────────────────────────────────────────┘
```

**核心瓶颈：Decode 阶段是内存带宽受限的（memory bandwidth bound），不是算力受限的**。这决定了优化方向。

---

## 三大武器如何配合 / How the Three Tools Compose

### 1. KV Cache — 消除重复计算
```python
# Without KV Cache: recompute all previous tokens every step
# With KV Cache: store K,V matrices, only compute new token

# Memory cost: 2 * num_layers * num_heads * head_dim * seq_len * batch_size * dtype_bytes
# For Llama-3 70B, 4096 seq len, fp16: ~8GB just for KV cache!
```
**瓶颈**：KV Cache 太大 → GPU 显存不够 → 限制 batch size → 吞吐量低

### 2. 量化 — 同时压缩权重和 KV Cache
```python
# INT8 量化：模型权重 70B → 70GB → ~35GB (fp16→int8)
# INT4 量化：70GB → ~18GB
# KV Cache 量化：KV cache int8 → 内存减半，更大 batch

# 用 bitsandbytes 加载量化模型
from transformers import AutoModelForCausalLM, BitsAndBytesConfig
import torch

bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.float16,
)
model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Meta-Llama-3-8B",
    quantization_config=bnb_config,
)
```

### 3. 投机解码 / Speculative Decoding — 克服串行瓶颈
```
核心思路：用小模型（draft model）猜几个 token，
         大模型（target model）一次性验证

步骤：
1. Draft model 生成 k=4 个候选 token: [t1, t2, t3, t4]
2. Target model 并行验证所有 4 个（因为可以并行！）
3. 接受到第一个不匹配处，拒绝后续

好处：target model 每次"解码"生成多个 token，
     GPU 从 memory-bound 变回 compute-bound
```

## 组合效果 / Combined Effect

```
朴素 Llama-3 70B serving:
- 内存：~140GB (fp32) → 需要 2x A100 80GB
- 吞吐：~20 tokens/sec per request

优化后：
- INT4 量化：~18GB，单卡 A100 可跑
- KV Cache + paged attention (vLLM)：batch size 提升 10x
- Speculative Decoding (7B draft)：latency 降低 2-3x
- 综合：单卡吞吐提升 5-10x
```

---

## 工程选型 / When to Use What

| 场景 | 推荐优化 |
|------|---------|
| 单卡内存不够 | INT4 量化 |
| 高并发低延迟 | Speculative Decoding + Batching |
| 长 context（>32k） | KV Cache 量化 + PagedAttention |
| 边缘部署 | 量化 + 蒸馏（小模型） |

## 可运行代码 / Runnable Snippet

```python
# pip install vllm
from vllm import LLM, SamplingParams

# vLLM combines PagedAttention (KV cache) + continuous batching
llm = LLM(
    model="meta-llama/Meta-Llama-3.1-8B-Instruct",
    quantization="int4",          # quantization
    speculative_model="[ngram]",  # speculative decoding (ngram draft)
    num_speculative_tokens=5,
    max_model_len=4096,
)

params = SamplingParams(temperature=0.8, max_tokens=200)
outputs = llm.generate(["Explain KV cache in one paragraph"], params)
print(outputs[0].outputs[0].text)
```

## 🧒 ELI5
LLM 生成文字就像一个接一个地摆积木——很慢。优化就是：用小帮手先猜几块（投机解码），把积木压缩变小（量化），记住之前摆过的位置不重算（KV Cache）。三招加起来快了好几倍。
Generating text is like placing one block at a time. Optimizations: have a small helper guess the next few blocks (speculative decoding), shrink the blocks (quantization), remember where you already placed things (KV cache). Together: much faster.
