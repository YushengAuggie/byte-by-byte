*You're building a search dashboard. Typing fast causes UI lag and race conditions where stale results override fresh ones.*

## 核心概念：React 并发模式

React 18 的并发模式允许渲染被**中断、暂停、恢复**。两个关键工具：

### `useTransition` — 降优先级的状态更新

```tsx
import { useState, useTransition } from 'react'

function SearchDashboard() {
  const [query, setQuery] = useState('')
  const [results, setResults] = useState<string[]>([])
  const [isPending, startTransition] = useTransition()

  const handleSearch = (value: string) => {
    // High priority: update input immediately
    setQuery(value)
    
    // Low priority: defer the expensive results update
    startTransition(() => {
      // Simulate expensive filtering
      const filtered = expensiveFilter(value)
      setResults(filtered)
    })
  }

  return (
    <div>
      <input value={query} onChange={e => handleSearch(e.target.value)} />
      {isPending && <span>Loading...</span>}
      <ResultsList results={results} />  {/* won't block input */}
    </div>
  )
}
```

### `useDeferredValue` — 延迟派生值

```tsx
import { useDeferredValue, memo } from 'react'

function SearchPage({ query }: { query: string }) {
  // Deferred version lags behind during fast typing
  const deferredQuery = useDeferredValue(query)
  
  return (
    <>
      <input value={query} ... />
      {/* This re-renders with lower priority */}
      <ExpensiveResultsList query={deferredQuery} />
    </>
  )
}

// Wrap in memo so it only re-renders when deferredQuery changes
const ExpensiveResultsList = memo(({ query }: { query: string }) => {
  // ... expensive rendering
})
```

## 猜猜输出 / Quiz

```tsx
const [isPending, startTransition] = useTransition()
console.log('before:', isPending)  // A) false  B) true
startTransition(() => setState(newVal))
console.log('after:', isPending)   // A) false  B) true
```

<details><summary>显示答案 / Show Answer</summary>

- before: `false`（默认不在过渡中）
- after synchronously: `false`（isPending 在下一次渲染才变 true）

`isPending` 是 React 状态，不会在同步代码中立即变化。正确答案 A → B（在下一个渲染中 isPending 变 true，完成后回 false）。

</details>

## ❌ vs ✅ 对比

```tsx
// ❌ Without transition: input lags when filtering 10k items
const handleChange = (e) => {
  setQuery(e.target.value)
  setResults(filterItems(e.target.value))  // blocks UI
}

// ✅ With transition: input stays responsive
const handleChange = (e) => {
  setQuery(e.target.value)  // urgent
  startTransition(() => {
    setResults(filterItems(e.target.value))  // deferrable
  })
}
```

## 何时用 / 何时不用

**用 `useTransition` when:**
- 状态更新触发昂贵的子树重渲染
- 用户需要即时输入反馈（搜索、过滤、tabs）
- 有明确的"紧急"和"非紧急"更新

**用 `useDeferredValue` when:**
- 你无法控制触发状态更新的代码（父组件）
- 想延迟某个 prop 的响应

**不要用 when:**
- 数据获取用 `Suspense` 更合适
- 更新本身就快（<16ms），加 transition 反而增加复杂度
