## Part 1: Theory / 理论基础 (5 min)

### 为什么加法 DP 不能直接用于乘法？/ Why Kadane's Doesn't Directly Transfer

**中文：**

先回忆 Kadane 算法（最大子数组和）的核心思想：

```
max_ending_here = max(num, max_ending_here + num)
```

逻辑很简单：要么从当前数重新开始，要么把当前数加到之前的最大子数组上。

但乘法完全不同。考虑数组 `[-2, -3, 7]`：
- Kadane 思维：-2 为负，丢掉；-3 为负，丢掉；答案是 7
- **正确答案**：(-2) × (-3) × 7 = **42**

为什么？因为两个负数相乘变正数，而且乘积的绝对值可以很大。

关键推论：**在乘法 DP 中，我们必须同时维护两个状态——以 i 结尾的子数组的最大乘积（max_prod）和最小乘积（min_prod）。**

**English：**

Recall Kadane's core idea (maximum subarray sum):
```
max_ending_here = max(num, max_ending_here + num)
```

Simple logic: either restart from current element, or extend the previous best subarray.

With multiplication, consider `[-2, -3, 7]`:
- Kadane thinking: -2 is negative, discard; -3 is negative, discard; answer = 7
- **Correct answer**: (-2) × (-3) × 7 = **42**

Why? Two negatives multiply to a positive, potentially huge. The key corollary: **in product DP, we must maintain both max_prod and min_prod ending at position i.**

### 状态定义 / State Definition

**中文：**

```
max_prod[i] = 以 nums[i] 结尾的所有子数组中乘积最大的值
min_prod[i] = 以 nums[i] 结尾的所有子数组中乘积最小的值
```

状态转移方程（3 种候选）：

```
以 nums[i] 结尾的子数组，只有 3 种情况：
  1. 仅包含 nums[i] 本身
  2. nums[i] × max_prod[i-1]  （扩展之前的最大乘积）
  3. nums[i] × min_prod[i-1]  （扩展之前的最小乘积）

当 nums[i] > 0 时，情况2通常产生新最大值
当 nums[i] < 0 时，情况3可能翻转成新最大值（负 × 负 = 正！）
当 nums[i] = 0 时，3种候选都归零，重新开始
```

因此：
```
max_prod[i] = max(nums[i], nums[i] × max_prod[i-1], nums[i] × min_prod[i-1])
min_prod[i] = min(nums[i], nums[i] × max_prod[i-1], nums[i] × min_prod[i-1])
```

**English：**

```
max_prod[i] = maximum product of any subarray ending at nums[i]
min_prod[i] = minimum product of any subarray ending at nums[i]
```

State transition — 3 candidates at each position:
```
Subarrays ending at nums[i] fall into exactly 3 cases:
  1. Just nums[i] alone
  2. nums[i] × max_prod[i-1]  (extend previous max)
  3. nums[i] × min_prod[i-1]  (extend previous min)

When nums[i] > 0: case 2 likely gives the new max
When nums[i] < 0: case 3 might flip to new max (negative × negative = positive!)
When nums[i] = 0: all candidates are 0; reset
```

Therefore:
```
max_prod[i] = max(nums[i], nums[i] × max_prod[i-1], nums[i] × min_prod[i-1])
min_prod[i] = min(nums[i], nums[i] × max_prod[i-1], nums[i] × min_prod[i-1])
```

## Part 2: Step-by-Step Implementation / 一步一步实现 (8 min)

### Approach 1: Naive Brute Force — O(n²)

**中文：**暴力解法：枚举所有子数组。面试时展示"我知道更优解，先给基准"。

**English:** Brute force — enumerate all subarrays. Show this first to establish baseline.

```python
def maxProduct_brute(nums: list[int]) -> int:
    """
    Brute force: try every possible subarray [i..j]
    Time: O(n^2), Space: O(1)
    """
    n = len(nums)
    result = nums[0]
    
    for i in range(n):
        product = 1
        for j in range(i, n):
            product *= nums[j]              # extend subarray [i..j]
            result = max(result, product)   # update global max
    
    return result

# Test: [2, 3, -2, 4] → 6 (subarray [2,3])
print(maxProduct_brute([2, 3, -2, 4]))   # 6 ✓
print(maxProduct_brute([-2, 0, -1]))      # 0 ✓
print(maxProduct_brute([-2, 3, -4]))      # 24 ✓
```

### Approach 2: Optimal Dual-Track DP — O(n) time, O(1) space

```python
def maxProduct(nums: list[int]) -> int:
    """
    Dual-track DP: track both max and min product ending at current position.
    
    Key insight: when nums[i] is negative, multiply by min_prod (which is
    also negative) gives a large positive — the new max.
    
    Time: O(n), Space: O(1)
    """
    if not nums:
        return 0
    
    # Initialize: both max and min start as nums[0]
    max_prod = nums[0]   # max product of subarray ending here
    min_prod = nums[0]   # min product of subarray ending here  
    result = nums[0]     # global maximum found so far
    
    for i in range(1, len(nums)):
        n = nums[i]
        
        # --- CRITICAL: compute candidates BEFORE overwriting max_prod/min_prod ---
        # Three possible products for subarrays ending at index i:
        candidate1 = n                  # start fresh: just [nums[i]]
        candidate2 = n * max_prod       # extend previous max subarray
        candidate3 = n * min_prod       # extend previous min subarray
        
        # New max is the largest of the three
        max_prod = max(candidate1, candidate2, candidate3)
        # New min is the smallest (track for future negative multiplications)
        min_prod = min(candidate1, candidate2, candidate3)
        
        # Update global result
        result = max(result, max_prod)
    
    return result


# ═══════════════════════════════════════════════
# Trace through [2, 3, -2, 4]:
# ═══════════════════════════════════════════════
# Start:  max_prod=2, min_prod=2, result=2
#
# i=1, n=3:
#   candidates = (3, 3*2=6, 3*2=6)
#   max_prod=6, min_prod=3, result=6
#
# i=2, n=-2:
#   candidates = (-2, -2*6=-12, -2*3=-6)
#   max_prod=-2, min_prod=-12, result=6
#
# i=3, n=4:
#   candidates = (4, 4*(-2)=-8, 4*(-12)=-48)
#   max_prod=4, min_prod=-48, result=6
#
# Final: 6 ✓ (subarray [2,3])
```

### One-Liner Trick (Pythonic) / 一行技巧

**中文：**可以用 `min()` 和 `max()` 组合成更简洁的写法：

**English:** A compact version using tuple unpacking:

```python
def maxProduct_compact(nums: list[int]) -> int:
    max_p = min_p = result = nums[0]
    for n in nums[1:]:
        # Python evaluates the ENTIRE right-hand tuple BEFORE any assignment,
        # so both max() and min() see the original (old) max_p and min_p. ✓
        max_p, min_p = (
            max(n, n * max_p, n * min_p),
            min(n, n * max_p, n * min_p)
        )
        result = max(result, max_p)
    return result
    
# 💡 Python tuple assignment is safe here: the RHS is fully evaluated first.
# max_p and min_p on the right still refer to the OLD values.
# If you prefer explicit clarity, save old values first:
# Safer (more readable) pattern:

def maxProduct_safe(nums: list[int]) -> int:
    max_p = min_p = result = nums[0]
    for n in nums[1:]:
        # Save originals explicitly
        old_max, old_min = max_p, min_p
        max_p = max(n, n * old_max, n * old_min)
        min_p = min(n, n * old_max, n * old_min)
        result = max(result, max_p)
    return result
```

## Part 3: Edge Cases & Gotchas / 边界情况 (2 min)

**中文：**5 个必须测试的边界情况：

**English:** 5 edge cases every interviewer expects you to handle:

```python
# ─────────────────────────────────────────────────
# Case 1: Single element (including negative)
# ─────────────────────────────────────────────────
assert maxProduct_safe([-3]) == -3          # Can't avoid it; must take it

# ─────────────────────────────────────────────────
# Case 2: Contains zero → resets the product chain
# ─────────────────────────────────────────────────
assert maxProduct_safe([-2, 0, -1]) == 0    # Zero breaks both sides
# Why: [-2,0] = 0, [0,-1] = 0, [-2,0,-1] = 0 → best is 0

# ─────────────────────────────────────────────────
# Case 3: All negative (even count) → product is positive
# ─────────────────────────────────────────────────
assert maxProduct_safe([-2, -3, -4]) == 12  # (-2)×(-3)×(-4)... nope
# Wait: best subarray is [-2,-3]→6 or [-3,-4]→12 → answer is 12 ✓

# ─────────────────────────────────────────────────
# Case 4: All negative (odd count) → forced to leave one out
# ─────────────────────────────────────────────────
assert maxProduct_safe([-2, -3, -4, -5]) == 120  # All four: (-2)×(-3)×(-4)×(-5) = 120
# Even count of negatives → full array product is positive. Answer: 120

assert maxProduct_safe([-2, -3, -4]) == 12  # Odd count → skip one end
# Best: skip -2 → (-3)×(-4)=12, or skip -4 → (-2)×(-3)=6 → answer 12

# ─────────────────────────────────────────────────
# Case 5: Multiple zeros splitting the array
# ─────────────────────────────────────────────────
assert maxProduct_safe([0, 2, 0, -5, 0]) == 2  # Each segment independent
```

**面试注意点 / Interview Gotchas:**

| 情况 | 原因 | 处理方式 |
|------|------|----------|
| 遇到 0 | 乘积归零，之后的子数组独立计算 | 候选1（仅nums[i]）=0，自然重置 |
| 全负偶数个 | 全部相乘最优 | 算法自动处理 |
| 全负奇数个 | 去掉绝对值最小的端点 | 算法自动处理 |
| 单元素 | 必须返回该元素（即使为负） | 初始化为nums[0] |
| 候选计算顺序 | 必须用上一轮的max/min | 先保存 old_max, old_min |

## Part 4: Real-World Application / 实际应用 (2 min)

**中文：**

这道题的核心技巧——**同时追踪最大值和最小值**——在生产环境中有真实的类比场景：

**1. 金融风险计算：**
一系列乘法收益率（如 +10%, -20%, +30%）中，找最优持仓窗口。负收益可能"救活"另一段负收益期（空头仓位）。追踪最大潜在收益和最大潜在损失同样重要。

**2. 对数转换 → 加法：**
在实际系统中，连续乘积常用对数转化为加法（避免下溢/上溢）：
```python

# Max product of subarray ≡ max sum of log(|nums[i]|)
# 但要处理负数的符号问题 → 需要特殊标记
```

**3. NLP/ML 序列评分：**
语言模型计算句子概率是各词概率的连乘积。找"最高置信度子序列"本质上是变种的 Maximum Product Subarray。

**English:**

The dual-track technique appears in real systems:

**1. Financial returns:** A series of multiplicative returns (+10%, -20%, +30%) — find the optimal holding window. Short positions mean negative returns can compound positively.

**2. Log-space arithmetic:** Production ML systems compute log-probabilities (sums) instead of raw products to avoid underflow. But the sign-tracking problem remains.

**3. Sequence scoring:** Finding the highest-confidence span in an NLP model's token probability sequence is exactly this pattern.

**The abstract pattern (generalize this!):**
> "When the 'worst' state can become the 'best' state due to the nature of the operation, you must track both extremes."

This appears in: Maximum Product Subarray, Maximum Absolute Sum of Subarray (#1749), products with complex numbers, etc.

## Part 5: Interview Simulation / 面试模拟 (3 min)

**场景：你在 Meta E5 面试，题目是 #152**

---

**Q1: 面试官问：为什么要追踪 min_prod？不就是追踪最大的就好了？**

> **A:** 不够。乘法有"翻转"效应：当前的最小乘积（负数）乘以下一个负数，会变成最大乘积。如果只追踪 max_prod，你会错过这个翻转机会。
>
> 例子：`[-5, -3]` → 仅追踪 max 的话，max_prod[-5]=-5；到 -3 时，候选是（-3, -3×(-5)=15, -3×(-5)=15）→ max=15。这里恰好还是对的，但在更复杂的序列中你需要 min 来避免错过深层翻转。

**Q2: 这个算法处理全零数组正确吗？**

> **A:** 是的。全零数组 `[0, 0, 0]`：初始化 result=0；每步三个候选都是 0；最终返回 0。正确。

**Q3: 如果题目改成"最小乘积子数组"怎么改？**

> **A:** 只需把 `result = max(result, max_prod)` 改成 `result = min(result, min_prod)`，其余逻辑完全相同。min_prod 已经在追踪了。

**Q4: 能用 Divide and Conquer 解这道题吗？时间复杂度多少？**

> **A:** 可以，类似 Maximum Subarray 的分治解法。每次从中点分割，答案是以下三者之一：左半部分的最大乘积、右半部分的最大乘积、或跨越中点的最大乘积。跨越中点的计算需要从中点向两侧扩展，但乘法版本需要同时维护最大和最小，复杂度 O(n log n)。不如线性 DP，通常没必要提，但体现了分治思维。

**Q5: 如果数组非常大（10亿元素），如何并行化？**

> **A:** 这是系统设计延伸。可以分块并行，每块返回 `(max_prod, min_prod, prefix_max, prefix_min, suffix_max, suffix_min, total_product)`，然后合并。类似 segment tree 的思路，适合 MapReduce 或 Spark。合并逻辑是这道题状态转移方程的"分布式版本"。
