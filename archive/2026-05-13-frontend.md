## 真实场景 / Real Scenario

你在做一个电商 dashboard，需要展示：
1. 商品列表（从数据库 fetch，SEO 重要）
2. 购物车数量（登录用户实时状态，每次操作都变）
3. 实时库存更新（WebSocket）

**问题：这三个分别用 Server Component 还是 Client Component？**

You're building an e-commerce dashboard showing:
1. Product list (fetched from DB, SEO-critical)
2. Cart count (real-time per-user state, changes on every action)
3. Live inventory updates (WebSocket)

**Question: Which should be Server Component vs Client Component?**

---

## 核心概念 / Core Concept

```
Server Components (默认，default)    Client Components ('use client')
─────────────────────────────────    ─────────────────────────────────
✅ 直接访问数据库/文件系统              ✅ useState, useEffect, hooks
✅ 敏感信息不暴露给浏览器               ✅ 事件监听 (onClick, onChange)
✅ 零 JS bundle size                  ✅ 浏览器 API (localStorage, WebSocket)
✅ 自动流式传输/Suspense               ✅ 实时交互
❌ 不能用 hooks                        ❌ 增加客户端 bundle
❌ 不能用浏览器 API                    ❌ 不能直接访问数据库
```

## 代码对比 / Code Comparison

```tsx
// ✅ Server Component (app/products/page.tsx)
// No 'use client' → Server Component by default
import { db } from '@/lib/db'

export default async function ProductsPage() {
  // Direct DB access — no API route needed
  const products = await db.product.findMany({ take: 20 })
  
  return (
    <div>
      {products.map(p => (
        <ProductCard key={p.id} product={p} />  // Pass to client component
      ))}
    </div>
  )
}

// ✅ Client Component (components/CartButton.tsx)
'use client'
import { useState } from 'react'

export function CartButton({ initialCount }: { initialCount: number }) {
  const [count, setCount] = useState(initialCount)
  
  return (
    <button onClick={() => setCount(c => c + 1)}>
      Cart ({count})
    </button>
  )
}
```

```tsx
// ❌ Common mistake: marking everything 'use client'
'use client'
import { db } from '@/lib/db'  // ❌ This will FAIL — db can't run in browser
export default async function ProductsPage() { ... }

// ❌ Another mistake: fetching in useEffect when Server Component would work
'use client'
export default function Products() {
  const [products, setProducts] = useState([])
  useEffect(() => {
    fetch('/api/products').then(r => r.json()).then(setProducts)  // ❌ Extra API route, waterfall
  }, [])
}
```

## 猜猜输出 / Quiz

```tsx
// app/page.tsx (Server Component)
export default async function Page() {
  console.log('where does this log?')
  return <div>Hello</div>
}
```

这个 `console.log` 输出在哪里？/ Where does this `console.log` appear?

A) 浏览器 DevTools Console  
B) Node.js 服务器终端  
C) 两者都有  
D) 不会输出，Server Components 不支持 console.log  

<details><summary>显示答案 / Show Answer</summary>

**B) Node.js 服务器终端**

Server Components 运行在服务器上，console.log 输出在你的终端（开发时）或服务器日志（生产时）。浏览器什么都看不到。

Server Components run on the server. `console.log` appears in your terminal (dev) or server logs (production). Nothing appears in the browser console.

</details>

## 决策框架 / Decision Framework

```
需要 useState/useEffect/hooks?  → Client Component
需要 onClick/onChange 等事件?   → Client Component
需要访问 localStorage/WebSocket? → Client Component
只是展示数据 + SEO 重要?        → Server Component ✅ (默认选择)
需要访问数据库/文件?            → Server Component ✅
```

**黄金法则**: 把交互部分"下推"到叶子节点，让尽可能多的组件保持 Server Component。

**Golden rule**: Push interactivity down to leaf nodes — keep as many components as Server Components as possible.

---

## 回答之前的问题 / Answering the Original Question

1. **商品列表** → Server Component ✅（数据库直接访问，SEO 友好，零 JS）
2. **购物车数量** → Client Component（需要 useState 跟踪变化）
3. **实时库存** → Client Component（需要 WebSocket / useEffect）

## 🧒 ELI5

Server Component 就像厨房里做好的菜直接端上桌——不需要顾客自己加热，已经是成品了，而且配料表（源码、数据库密码）留在厨房里。Client Component 就像自助餐台——食材在现场，顾客可以自己选、自己操作，但多了一些互动成本。

Server Component is like food prepared in the kitchen and served ready — no heating needed at the table, and the recipe (source code, DB secrets) stays in the kitchen. Client Component is like a buffet station — ingredients are on-site and guests can interact, but with more overhead.
