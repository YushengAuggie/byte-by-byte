## Overview / 概述

**中文：**
「戳气球」（LeetCode #312）是整个 NeetCode 150 中最能检验你对动态规划理解深度的题目之一。它属于「区间 DP」（Interval DP）这一大类，表面上暴力解是 O(n!) 的全排列，但一个反常识的关键洞见可以把它压缩到 O(n³)。

这题之所以难，不仅仅是因为转移方程复杂——更是因为它要求你**颠倒思维方向**：与其想「先戳哪个气球」，不如想「在某个区间内，最后戳哪个气球」。这个思维上的180°转弯，是区间DP所有难题的通用钥匙。

**English:**
"Burst Balloons" (LeetCode #312) is one of the most intellectually demanding problems in the NeetCode 150. It belongs to the **Interval DP** family. The brute-force solution tries all O(n!) burst orderings. One counterintuitive key insight collapses this to O(n³).

What makes it hard isn't just a complex recurrence — it demands a 180° mental shift: instead of asking *which balloon do I pop first*, ask *which balloon is the last one I pop inside a given range*. That reversal is the master key for all hard interval DP problems.

## Part 1: Theory / 理论基础 (5 min)

### 1.1 问题描述 / Problem Statement

**中文：**
给定 `n` 个气球，每个气球有一个整数值 `nums[i]`。戳破气球 `i` 获得硬币数 = `nums[i-1] * nums[i] * nums[i+1]`（若 i 是边界则把越界值视为 1）。戳完所有气球，求最多能获得多少硬币。

**English:**
Given `n` balloons with integer values `nums[i]`. Popping balloon `i` earns `nums[i-1] * nums[i] * nums[i+1]` coins (treat out-of-bounds as 1). Pop all balloons to maximize total coins.

```
Example: nums = [3, 1, 5, 8]
One optimal sequence: pop 1 → pop 5 → pop 3 → pop 8
Coins: 3×1×5 + 3×5×8 + 1×3×8 + 1×8×1 = 15 + 120 + 24 + 8 = 167
Answer: 167
```

---

### 1.2 为什么「正向」DP 失败 / Why Forward DP Fails

**中文：**
直觉上，我们想定义 `dp[S]` = 戳完集合 S 中所有气球能得到的最大硬币。但这会遇到**后效性问题**：戳破集合 S 中的一个气球后，它的相邻气球会发生变化，因为原本隔开它们的气球已经不存在了。每一步的子问题都依赖于父问题的中间状态，子问题无法独立求解。

**English:**
Intuitively, define `dp[S]` = max coins bursting all balloons in set S. But this has an **optimal substructure violation**: popping a balloon inside S changes who the neighbors are for all future pops. The subproblems aren't independent — each one depends on which other balloons are still alive.

```
When we pop balloon k first from [i...j]:
  Neighbors of k depend on what's already been popped.
  → Subproblem boundaries keep shifting.
  → Can't decompose cleanly.
```

---

### 1.3 关键洞见：倒过来想 / The Key Insight: Think Backwards

**中文：**
核心思路：**不要想「第一个戳哪个」，要想「最后一个戳哪个」。**

假设在范围 (i, j)（开区间，不含边界）中，气球 k 是最后一个被戳破的。那么：
- 在戳 k 之前，(i, k) 之间的所有气球已经被戳完了 → 子问题 `dp[i][k]`
- 在戳 k 之前，(k, j) 之间的所有气球也已经被戳完了 → 子问题 `dp[k][j]`
- 此时戳 k，它的左邻居是 `nums[i]`，右邻居是 `nums[j]`（因为两侧都空了）
- 获得硬币：`nums[i] * nums[k] * nums[j]`

这就是关键！当 k 是区间内最后一个气球时，它的左右邻居是**固定的**：恰好是区间的两个边界。子问题边界不再随机，区间DP得以成立。

**English:**
The core idea: **don't think about which balloon to pop first — think about which balloon to pop last.**

Say balloon `k` is the last one popped inside range `(i, j)` (open interval, boundaries excluded). Then:
- Before popping k, all balloons in (i, k) are already gone → subproblem `dp[i][k]`
- Before popping k, all balloons in (k, j) are already gone → subproblem `dp[k][j]`
- When we finally pop k, its left neighbor is `nums[i]` and right is `nums[j]` (both sides are clear)
- Coins earned: `nums[i] * nums[k] * nums[j]`

**This is the magic.** When k is the last balloon in a range, its neighbors are **fixed** — exactly the two boundary values. The subproblems are truly independent.

---

### 1.4 转移方程 / Recurrence

**中文：**
先在数组两端加虚拟气球（值为 1），设新数组为 `nums`（长度 n+2，原气球在下标 1..n）。

定义：`dp[i][j]` = 戳完开区间 `(i, j)` 内所有气球能获得的最大硬币数。

**English:**
Pad both ends with virtual balloons of value 1. Let `nums` have length n+2 with original balloons at indices 1..n.

Define: `dp[i][j]` = max coins from bursting all balloons strictly inside open interval `(i, j)`.

```
Recurrence:
dp[i][j] = max(
    dp[i][k] + nums[i] * nums[k] * nums[j] + dp[k][j]
)
for all k in (i+1, j-1) inclusive

Base case: dp[i][j] = 0 when j - i <= 1 (no balloons inside)
Answer: dp[0][n+1]
```

**Fill order:** From small intervals to large (length L = j - i from 2 upward).

## Part 2: Step-by-Step Implementation / 一步一步实现 (8 min)

### 2.1 Approach 0: Brute Force — O(n!) 暴力枚举

```python
# TLE for n >= 15. For conceptual clarity only.
def max_coins_brute(nums):
    if not nums:
        return 0
    
    best = 0
    for i, n in enumerate(nums):
        # Pop balloon i, collect coins with current neighbors
        left = nums[i-1] if i > 0 else 1
        right = nums[i+1] if i < len(nums)-1 else 1
        coins = left * n * right
        
        # Recurse on remaining balloons
        rest = nums[:i] + nums[i+1:]
        best = max(best, coins + max_coins_brute(rest))
    
    return best
```

**中文：** 时间复杂度 O(n!)，当 n=20 时有 2.4 × 10¹⁸ 种情况，完全不可行。

**English:** O(n!) — for n=20 that's 2.4 × 10¹⁸ cases. Completely infeasible.

---

### 2.2 Approach 1: Top-Down Memoization — O(n³)

```python
from functools import lru_cache

def max_coins_memo(nums):
    # Pad with virtual balloons of value 1
    nums = [1] + nums + [1]
    n = len(nums)
    
    @lru_cache(maxsize=None)
    def dp(i, j):
        """Max coins from bursting all balloons in OPEN interval (i, j)."""
        # Base case: no balloons to burst
        if j - i < 2:
            return 0
        
        best = 0
        # Try each balloon k as the LAST to pop in (i, j)
        for k in range(i + 1, j):
            # When k is last: left neighbor = nums[i], right = nums[j]
            coins = nums[i] * nums[k] * nums[j]
            # Subproblems: clear left side, then right side, then pop k
            total = dp(i, k) + coins + dp(k, j)
            best = max(best, total)
        
        return best
    
    return dp(0, n - 1)
```

**中文：**
- 状态数：O(n²) 个区间
- 每个状态需要 O(n) 时间枚举 k
- 总复杂度：**O(n³)** 时间，O(n²) 空间

**English:**
- O(n²) distinct `(i, j)` pairs
- O(n) work per state to try each `k`
- Total: **O(n³)** time, O(n²) space

### 2.3 Approach 2: Bottom-Up DP (Optimal) — O(n³)

```python
def max_coins(nums):
    # Step 1: Pad both ends with virtual balloons
    nums = [1] + nums + [1]
    n = len(nums)
    
    # Step 2: Initialize DP table
    # dp[i][j] = max coins from (i, j) open interval
    dp = [[0] * n for _ in range(n)]
    
    # Step 3: Fill in order of INCREASING interval length
    # Length L = j - i (minimum 2 for at least one balloon inside)
    for length in range(2, n):         # length of interval [i, j]
        for i in range(n - length):    # left boundary
            j = i + length             # right boundary
            
            # Try each k as the last balloon popped in (i, j)
            for k in range(i + 1, j):
                # k is last: neighbors are nums[i] and nums[j]
                coins = nums[i] * nums[k] * nums[j]
                total = dp[i][k] + coins + dp[k][j]
                dp[i][j] = max(dp[i][j], total)
    
    # Step 4: Answer is the entire range (0, n-1)
    return dp[0][n - 1]
```

### 2.6 类比记忆 / Analogy for Memory

**中文：**
想象你在拆除一栋楼。如果从外往里拆（先戳边界气球），每次拆掉一块砖，周围的结构就会变，子问题无法独立。但如果从里往外想（确定最后一根承重柱），中心柱拆掉前，两侧已经清空，它的受力情况是确定的。这就是区间DP的思路：**定义「最后消去的元素」，而不是「第一个消去的」**。

**English:**
Imagine demolishing a building. If you tear it down from the outside in, every brick you remove changes the structural stress — the subproblems interact. But if you identify the *last* load-bearing beam to come down, both sides are already cleared when it falls, so its load is completely determined. That's interval DP: **define the last element removed, not the first.**

## Part 3: Edge Cases & Gotchas / 边界情况 (2 min)

**中文：**

1. **单个气球** `nums = [5]`
   - 填充后 `[1, 5, 1]`
   - `dp[0][2]`: k=1 → 1×5×1 = 5 ✓

2. **全部相同** `nums = [1, 1, 1]`
   - 任何顺序结果相同，都是 `1*1*1 + 1*1*1 + 1*1*1 = 3`

3. **忘记填充边界**（最常见错误）
   - 若不加虚拟1，访问 `nums[-1]` 或 `nums[n]` 会越界或返回错误邻居
   - **必须先 pad：** `nums = [1] + nums + [1]`

4. **填表顺序错误**
   - 若先填大区间，依赖的小区间 dp 值还是 0 → 结果错误
   - **必须从 `length=2` 开始，递增到 `length=n-1`**

5. **混淆开/闭区间**
   - `dp[i][j]` 表示**开区间** `(i, j)` 内的气球（不含 i 和 j 本身）
   - 枚举 k 的范围是 `range(i+1, j)`（不含端点）

**English:**

1. **Single balloon** — handled correctly with padding.
2. **All same values** — any order gives same result; DP finds it.
3. **Forgetting to pad** — most common bug. Without the `[1] + ... + [1]`, boundary indices cause wrong neighbors or IndexError.
4. **Wrong fill order** — filling large intervals before small gives dp=0 for all small subproblems.
5. **Open vs closed interval confusion** — `dp[i][j]` covers ONLY balloons strictly BETWEEN i and j. The loop is `range(i+1, j)`, not `range(i, j+1)`.

## Part 4: Real-World Application / 实际应用 (2 min)

**中文：**
区间DP模式在工程中有直接应用：

1. **矩阵链乘法（Matrix Chain Multiplication）**
   - 给定一系列矩阵相乘，确定最优结合顺序以最小化乘法次数
   - 完全相同的「最后一步」思路：确定区间 (i, j) 内最后一次乘法的位置
   - 实际场景：编译器优化表达式求值顺序，深度学习框架的计算图优化

2. **最优 BST（Optimal Binary Search Tree）**
   - 给定查询频率，构造期望查询代价最小的BST
   - 应用于数据库索引设计和静态字典结构

3. **文件合并 / Huffman变体**
   - 合并多个有序文件的最优顺序，最小化总 IO
   - 外部排序归并阶段的优化

4. **表达式括号化**
   - 给定运算符序列，不同括号方案得到不同结果
   - SQL查询优化器中的 join ordering 是这个问题的变体

**English:**
The interval DP pattern appears directly in production systems:

1. **Matrix Chain Multiplication** — optimal multiplication order for a sequence of matrices. Compilers and ML frameworks (like TensorFlow's XLA) use this to minimize FLOP counts in computation graphs.

2. **Optimal BST** — given access frequency distributions, build a BST minimizing expected lookup cost. Relevant in database index design.

3. **File Merge / External Sort** — optimal merge order for sorted runs in external sorting (minimize total I/O). Used in MapReduce shuffles and database merge joins.

4. **Query Join Ordering** — SQL query optimizers must choose join order. This is NP-hard in general, but interval DP is used for small join trees (up to ~10 tables) in PostgreSQL's planner.

## Part 5: Interview Simulation / 面试模拟 (3 min)

**中文：** 面试官会这样追问你：

**English:** Likely follow-up questions in a real interview:

---

**Q1: 为什么不能直接用 dp[mask] 表示戳破某个子集的最大收益？/ Why can't we use bitmask DP?**

**A:** 可以，但复杂度是 O(2ⁿ × n)，n=30 就是 320 亿次操作。区间DP的 O(n³) 在 n=500 时仍然可行（约 1.25 亿次）。Bitmask DP is correct but O(2ⁿ × n) — exponential. Interval DP achieves O(n³) by exploiting the interval structure.

---

**Q2: 能否优化到 O(n²)？/ Can this be optimized below O(n³)?**

**A:** 目前没有已知的 O(n²) 解法。区间DP本质上需要枚举分割点，O(n³) 被认为是这类问题的理论下界（至少在当前已知算法框架下）。No known O(n²) solution exists. The need to enumerate a split point `k` for each O(n²) interval pair is an inherent cost of the interval structure. O(n³) is considered essentially optimal for this problem class.

---

**Q3: dp[i][j] 和 dp[i][k] + dp[k][j] 是怎么保证独立的？/ Why are dp[i][k] and dp[k][j] independent?**

**A:** 因为 k 是区间 (i,j) 内最后被戳的气球。在戳 k 之前，(i,k) 和 (k,j) 两个子区间都已经完全清空，互不影响。k 存在的唯一作用是固定两侧子问题的边界：左侧子问题的右边界是 k，右侧子问题的左边界是 k。Since `k` is the LAST balloon popped in `(i, j)`, by definition both sub-intervals `(i, k)` and `(k, j)` are completely cleared before `k` is popped. They never interfere with each other — `k` acts as a fixed partition wall.

---

**Q4: 如果把「获得最多硬币」改为「获得最少硬币」，代码需要怎么改？/ Minimum coins variant?**

**A:** 把 `max(dp[i][j], total)` 改为 `min(dp[i][j], total)`，初始化把 `dp[i][j]` 设为 `float('inf')`（除基础情况的0以外）。Change `max` to `min` and initialize non-base cells to `float('inf')`. The recurrence structure is identical.

---

**Q5: 这道题和「合并石子」有什么关系？/ Relationship to Stone Merge problem?**

**A:** 完全相同的区间DP模式！「合并石子」（Stone Merge）是另一道经典题：把 n 堆石子合并成一堆，每次合并相邻两堆的代价是两堆之和，求最小代价。转移方程：`dp[i][j] = min(dp[i][k] + dp[k+1][j] + sum(i..j))`。两题都是「确定区间内的最后一次操作」。Exact same pattern! "Stone Merge" defines `dp[i][j]` as the cost to merge piles `i..j`, tries every split point `k` as the last merge, and fills by interval length. The only differences are the cost function and boundary conditions.

**中文思考总结：**
1. 看到「在一组元素中操作，操作后改变相邻关系」→ 考虑区间DP
2. 子问题互相干扰（正向想）→ 反转：定义最后一次操作
3. 添加虚拟边界元素，统一处理边界情况
4. 按区间长度从小到大填表（保证依赖项已计算）

**English summary:**

| Dimension | Value |
|---|---|
| Time Complexity | O(n³) |
| Space Complexity | O(n²) |
| Core Insight | Enumerate the LAST balloon popped, not the first |
| When to Apply | Any "find optimal split in interval" problem |
| Sister Problems | Stone Merge, Matrix Chain, Optimal BST |

**Mental checklist:**
1. See "operate on elements, operations change adjacency" → think Interval DP

3. Add virtual boundary elements for clean base cases
4. Fill by increasing interval length (guarantees dependencies are ready)
