🤖 **AI** — Structured Output & JSON Mode

---

## 问题背景 / The Problem

你让 LLM 返回 JSON，但得到这样的结果：

You ask an LLM to return JSON, and you get:
```
Sure! Here's the JSON you asked for:
```json
{"name": "Alice", "age": 30}
```
Let me know if you need any modifications!
```

然后你的 `json.loads()` 直接抛异常。这种情况在生产系统里非常危险。

Then your `json.loads()` throws an exception. This is dangerously unreliable in production.

---

## 结构化输出是什么 / What Is Structured Output?

结构化输出 = **API 层面强制保证模型输出严格符合 JSON Schema**，而不只是「提示模型生成 JSON」。

Structured output = **API-level guarantee that model output strictly conforms to a JSON Schema**, not just "asking the model nicely to produce JSON."

实现原理：**约束解码 (Constrained Decoding)**  
模型在生成每个 token 时，只能从符合当前 Schema 状态的 token 集合中选择。用上下文无关文法 (CFG) 将 JSON Schema 编译成状态机，逐 token 过滤。

Implementation: **Constrained Decoding**  
At each token generation step, the model can only sample from tokens valid for the current schema state. A JSON Schema is compiled into a state machine (Context-Free Grammar), filtering token candidates at each step.

## 两种模式对比 / Two Modes Compared

### JSON Mode (旧方式 / Legacy)
```python
# OpenAI — JSON Mode
response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Return user info as JSON"}],
    response_format={"type": "json_object"}  # Only guarantees valid JSON syntax
)
# 保证: 是合法 JSON。不保证: 字段名、类型、结构
# Guarantees: valid JSON syntax. Does NOT guarantee: field names, types, structure
```

### Structured Outputs (新方式 / Current Standard)
```python
# OpenAI — Structured Outputs with Pydantic
from pydantic import BaseModel

class UserInfo(BaseModel):
    name: str
    age: int
    email: str

response = client.beta.chat.completions.parse(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Extract user info from: Alice, 30, alice@example.com"}],
    response_format=UserInfo
)
user = response.choices[0].message.parsed  # Already a UserInfo object!
print(user.name)  # "Alice"
```

## Anthropic 原生结构化输出 / Anthropic Native Structured Outputs

据报道，Anthropic 于 2026 年初正式 GA 结构化输出功能，支持两种模式：

Anthropic reportedly launched structured outputs GA in early 2026 with two modes:

```python
import anthropic

client = anthropic.Anthropic()

# Mode 1: JSON Outputs Mode (data extraction)
response = client.messages.create(
    model="claude-sonnet-4-5",
    max_tokens=1024,
    # Note: Exact parameter name may vary — check docs.anthropic.com for current API
    output_format={
        "type": "json_schema",
        "json_schema": {
            "name": "UserInfo",
            "schema": {
                "type": "object",
                "properties": {
                    "name": {"type": "string"},
                    "age": {"type": "integer"},
                    "email": {"type": "string"}
                },
                "required": ["name", "age", "email"]
            }
        }
    },
    messages=[{"role": "user", "content": "Extract: Alice, 30, alice@example.com"}]
)
import json
user = json.loads(response.content[0].text)  # Guaranteed valid + schema-conformant

# Mode 2: Strict Tool Use (agentic workflows)
tools = [{
    "name": "create_user",
    "input_schema": {
        "type": "object",
        "properties": {"name": {"type": "string"}, "age": {"type": "integer"}},
        "required": ["name", "age"]
    },
    "strict": True  # Parameters will EXACTLY match the schema
}]
```

## 最佳实践 / Best Practices

### 1. Schema-First 开发
先定义 Pydantic 模型 / Zod schema，再写 prompt，不要用字符串拼 JSON。

```python
# ❌ 旧方式
prompt = 'Return JSON with fields: name (string), age (int), email (string)'

# ✅ 新方式  
class UserInfo(BaseModel):
    name: str
    age: int
    email: str
# 直接传 UserInfo 给 response_format
```

### 2. 处理拒绝 / Handle Refusals
```python
if response.choices[0].message.refusal:
    # Model refused due to safety — handle gracefully
    print("Model refused:", response.choices[0].message.refusal)
else:
    user = response.choices[0].message.parsed
```

### 3. 两阶段生成 / Two-Stage for Complex Reasoning
对于需要推理的任务，先让模型 think，再格式化输出：
```python
# Stage 1: Let the model reason freely
reasoning = client.chat("Think through this problem...")

# Stage 2: Format the conclusion
result = client.chat(
    f"Given this reasoning: {reasoning}\n\nNow output as JSON:",
    response_format=MySchema
)
```

## 什么时候用 / When to Use

| 场景 | 推荐方式 |
|------|---------|
| 数据提取 (实体抽取、分类) | Structured Outputs |
| Agentic 工具调用 | Strict Tool Use |
| 简单 JSON 转换 | JSON Mode (够用) |
| 需要推理 + 结构化输出 | Two-stage generation |
| 创意写作 | 不用结构化输出 |

## 🧒 ELI5
让 LLM 返回 JSON 就像让朋友帮你填一张表格。普通方式：你口头说字段名，朋友可能填错地方。结构化输出：你给朋友一张预印的表格，每个格子里只能填指定类型的内容，填完自动校验——出不了错。

Asking an LLM to return JSON is like asking a friend to fill out a form. Normal way: you describe the fields verbally — your friend might put things in the wrong box. Structured output: you hand them a pre-printed form where each box only accepts certain content and auto-validates — errors are impossible.
