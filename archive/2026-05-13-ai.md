# 🤖 AI — Mixture of Experts (MoE): Efficient Large Models

> Day 42 · Mastery Phase · ~2 min read

---

## 直觉解释 / Intuitive Explanation

传统大模型（Dense Model）每次处理 token 时，**所有参数都参与计算**。GPT-4 级别的模型有数千亿参数，每个 token 都要过一遍，这非常耗算力。

**MoE（混合专家模型）** 的思路完全不同：把模型拆分成多个"专家"（小型 FFN 网络），每次只激活少数几个专家，其余保持沉默。结果是：参数总量大，但每次推理的计算量小。

Traditional Dense Models activate **all parameters** for every token. For a model with hundreds of billions of parameters, every single token triggers the full computation — extremely expensive.

**MoE (Mixture of Experts)** takes a different approach: split the model into multiple "experts" (small FFN sub-networks). For each token, only a few experts are activated; the rest stay silent. Result: large total parameters, but small per-token compute.

---

## 工作原理 / How It Works

```
Input Token
    │
    ▼
[Router / Gating Network]
    │ (softmax → Top-K experts selection)
    ├──────────┬──────────┐
    ▼          ▼          ▼
[Expert 1] [Expert 4] [Expert 7]   ← Only top-2 (or top-K) activated
    │          │          │
    └──────────┴──────────┘
               │
          [Weighted Sum]
               │
            Output
```

**Router 的工作** / What the Router Does:
- 对每个 token，输出 N 个专家的概率分布
- 选择 Top-K 个专家（通常 K=2）
- 把 token 发给这 K 个专家处理，结果加权求和

**关键参数** / Key Numbers:
- **Total experts**: 通常 8、64 甚至数百个
- **Active experts per token**: 通常只有 2 个
- **Sparsity**: 如果有 64 个专家每次只用 2 个，激活率 = 3%

## 实际应用 / Real Applications

| 模型 | 架构 | 说明 |
|------|------|------|
| GPT-4 | 据报道是 MoE | 8 个专家，每次激活 2 个 |
| Mixtral 8x7B | MoE | 8 个 7B 专家，相当于 47B 总参数，实际计算量约 13B |
| DeepSeek-V3 | MoE | 671B 总参数，每次激活 37B |
| Switch Transformer | MoE | Google，2021，证明 MoE 可扩展 |

**为什么 Mixtral 8x7B 很厉害？** 推理速度接近 13B 模型，但效果接近 70B 模型。鱼和熊掌兼得。

**Why Mixtral 8x7B is impressive**: Inference speed similar to a 13B model, but quality approaching a 70B model. Best of both worlds.

## 可运行的演示 / Runnable Demo

```python
# pip install torch
import torch
import torch.nn as nn
import torch.nn.functional as F

class MoELayer(nn.Module):
    def __init__(self, input_dim=64, num_experts=4, top_k=2):
        super().__init__()
        self.top_k = top_k
        # Each "expert" is a small FFN
        self.experts = nn.ModuleList([
            nn.Linear(input_dim, input_dim) for _ in range(num_experts)
        ])
        # Router: maps input to expert scores
        self.router = nn.Linear(input_dim, num_experts)

    def forward(self, x):
        # x: (batch, input_dim)
        scores = self.router(x)                      # (batch, num_experts)
        weights, indices = torch.topk(scores, self.top_k, dim=-1)
        weights = F.softmax(weights, dim=-1)          # normalize top-k weights
        
        output = torch.zeros_like(x)
        for k in range(self.top_k):
            expert_idx = indices[:, k]               # which expert for each item
            weight = weights[:, k].unsqueeze(-1)     # scalar weight
            for i, idx in enumerate(expert_idx):
                output[i] += weight[i] * self.experts[idx](x[i])
        return output

# Demo
layer = MoELayer(input_dim=64, num_experts=4, top_k=2)
x = torch.randn(3, 64)  # batch of 3 tokens
out = layer(x)
print(f"Input: {x.shape}, Output: {out.shape}")  # both (3, 64)
```

## MoE 的挑战 / Challenges

1. **负载不均衡（Load Imbalance）** — Router 可能总选同几个专家，其他专家"失业"。解决：在 loss 里加辅助均衡项（auxiliary load balancing loss）
2. **通信开销** — 分布式训练时，token 要路由到不同 GPU 上的专家，网络通信成为瓶颈
3. **训练不稳定** — Router 学习过程中可能出现 "expert collapse"，需要精心调参

Imagine a company with 64 specialist employees (math, language, code, logic...). A task arrives and the receptionist (Router) says "get Expert #2 (math) and Expert #7 (code) for this." The other 62 keep drinking coffee. Total capacity is huge, but only 2 people are called each time — very efficient.
