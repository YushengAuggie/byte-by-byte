# Closures & Lexical Scope — JS Interview Classic

## 场景 / Scenario
中文：你在做一个 dashboard，需要给每一行渲染一个“重试 / Retry”按钮。点击时要带上该行的 `rowId`。如果你不小心写错闭包，你可能会发现：不管点哪个按钮，拿到的都是同一个 `rowId`（通常是最后一个）。

English: You’re building a dashboard with a “Retry” button per row. If you misuse closures, every button can end up using the same `rowId` (often the last one).

---

## 核心概念 / Core idea
中文：
- **词法作用域（lexical scope）**：变量能否被访问，取决于代码“写在哪里”，不是“从哪里调用”。
- **闭包（closure）**：函数 + 它创建时捕获的外部变量环境。

English:
- **Lexical scope**: what you can access depends on where code is written, not where it’s called.
- **Closure**: a function plus the environment it captured when created.

## 代码示例 / Code snippet
```ts
// The closure captures `rowId`.
export function makeRetryHandler(rowId: string) {
  return async function onRetryClick() {
    // Comments in English
    await fetch(`/api/retry?rowId=${encodeURIComponent(rowId)}`, { method: 'POST' });
  };
}

// Usage (e.g., inside a component render)
const handler = makeRetryHandler(row.id);
```

中文：`makeRetryHandler` 返回的内部函数，会把 `rowId` “记住”。这就是闭包。

English: The inner function “remembers” `rowId` — that’s a closure.

## 猜猜输出什么？/ Quiz (A/B/C/D)
```ts
const fns: Array<() => number> = [];
for (var i = 0; i < 3; i++) {
  fns.push(() => i);
}
console.log(fns[0](), fns[1](), fns[2]());
```
A) `0 1 2`
B) `3 3 3`
C) `0 0 0`
D) 抛异常 / throws

答案 / Answer: **B**
中文解释：`var` 是函数作用域，循环结束后 `i` 变成 3；三个函数闭包捕获的是“同一个 i”。
English: `var` is function-scoped; after the loop `i === 3`, and all closures reference the same `i`.

---

## 常见错误 vs 正确写法 / Common mistake vs correct
❌ 错误（捕获同一个变量）/ Wrong:
```ts
const fns: Array<() => number> = [];
for (var i = 0; i < 3; i++) {
  fns.push(() => i);
}
```

✅ 正确 1：用 `let`（块级作用域）/ Correct 1: use `let`:
```ts
const fns: Array<() => number> = [];
for (let i = 0; i < 3; i++) {
  fns.push(() => i);
}
```

✅ 正确 2：用工厂函数制造新作用域 / Correct 2: scope factory:
```ts
const fns: Array<() => number> = [];
for (var i = 0; i < 3; i++) {
  const fn = ((x: number) => () => x)(i);
  fns.push(fn);
}
```

## 什么时候用 / 什么时候别用 / When to use / when NOT to
中文（实战判断）：
- ✅ 用闭包：
  - 你需要“绑定参数”给回调（事件处理、定时器、重试函数、日志上下文）
  - 你需要封装内部状态（不想暴露成全局/类字段）
- ❌ 小心闭包：
  - 在热路径里创建大量闭包（每次 render 都 new 很多函数）→ 可能导致子组件重复渲染
  - 闭包捕获了会变化的大对象（例如 props/state 的整个对象）→ 容易产生“旧值 / stale value”问题

English (practical):
- ✅ Use closures to bind parameters to callbacks or to encapsulate private state.
- ⚠️ Be careful when creating tons of closures on hot render paths, or capturing changing objects that can cause stale values.

## 小提示（React/TS 实战）/ React/TS production tip
中文：如果你把 handler 传给 `React.memo` 子组件，并且不想每次 render 都变引用：
- 用 `useCallback`，并确保依赖是最小的（不要把整个对象塞进去）。

English: If passing handlers to memoized children, use `useCallback` with minimal dependencies.
