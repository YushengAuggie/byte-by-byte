#### 技术演进时间线 / Technical Evolution

```
2017-2020: RLHF 时代
  ├─ 人类标注员对输出排名
  ├─ 训练 Reward Model (RM)
  └─ PPO 优化 LLM → 最大化 RM 分数
  问题: RM hacking (模型找到刷分捷径)

2021-2023: DPO & RLAIF 时代  
  ├─ DPO (Direct Preference Optimization): 去掉独立 RM，直接优化偏好
  ├─ RLAIF: 用 AI 替代人类标注 (更便宜，更快)
  └─ Constitutional AI (Anthropic): 给模型一套"宪法"原则
  
2024-2026: 自动化红队 + 可解释性时代
  ├─ 自动红队模型（如 OpenAI 据报道训练的专用破解模型）：找越狱漏洞
  ├─ Mechanistic Interpretability: 理解 transformer 内部电路
  └─ Scalable Oversight: 用 AI 监督 AI (因为人类跟不上)
```

#### 自动红队背后的技术 / What Automated Red-Teaming Represents

```python
# Simplified red-teaming pipeline concept
class RedTeamLoop:
    """
    Adversarial self-improvement:
    1. Red model generates attack prompts
    2. Target model responds
    3. Judge model scores if attack succeeded
    4. Red model learns from successful attacks
    """
    
    def __init__(self, red_model, target_model, judge_model):
        self.red = red_model
        self.target = target_model
        self.judge = judge_model
    
    def run_episode(self, category: str) -> dict:
        # Red model generates attack
        attack = self.red.generate(
            f"Generate a prompt that will cause the target to violate policy in category: {category}"
        )
        
        # Target responds
        response = self.target.generate(attack)
        
        # Judge scores (1=attack succeeded, 0=target held)
        success = self.judge.score(attack, response, category)
        
        # Red model gets reward signal
        self.red.update(reward=success)
        
        return {"attack": attack, "response": response, "success": success}

# Key insight: this is essentially adversarial training
# The target model gets harder to break as it's trained
# against successful attacks → "most robust to prompt injection"
```

# This demonstrates the Constitutional AI critique-revision loop

CONSTITUTION = [
    "Be helpful, harmless, and honest.",
    "Do not assist with activities that could harm people.",
    "Respect user privacy and autonomy.",
]

def constitutional_ai_step(response: str, constitution: list) -> str:
    """
    Simulates the CAI critique-revision loop:
    1. Critique response against each principle
    2. Revise to better align
    (In practice, this uses the LLM itself to self-critique)
    """
    critique_prompt = f"""
Response to critique: "{response}"

Constitution principles:
{chr(10).join(f'- {p}' for p in constitution)}

Does this response violate any principle? If yes, revise it.
"""
    # In production: call LLM with critique_prompt
    # The model self-critiques and revises
    print(f"[CAI] Running critique against {len(constitution)} principles")
    return "revised_response"  # stub: call real LLM here

# The key insight: instead of human feedback for every response,
# the model uses the constitution to self-correct
# This scales much better than pure RLHF
constitutional_ai_step(
    "Here's how to pick a lock...",
    CONSTITUTION
)

### 工程视角：对齐 ≠ 审查 / Engineering Perspective

对齐的目标不是让 AI 无法回答"危险"问题，而是让它能**正确理解语境**：

```
问题: "如何开锁？"
× 过度对齐: 拒绝回答
✓ 正确对齐: 区分上下文
  - 你刚搬家锁匠没来 → 帮你找解决方案
  - 询问入室盗窃技巧 → 拒绝并解释原因
```

自动红队（Auto Red-Teaming）这类工具的价值：**自动化找到这个边界的漏洞，而不是手动尝试越狱**。

### 🧒 ELI5
Teaching AI to be safe is like teaching a new employee. RLHF = you watch them work and give thumbs up/down. Constitutional AI = you give them a rulebook and they check their own work. Auto red-team = you hire a security tester to try to trick them, and every trick they fall for, you fix. The goal isn't a robot that never answers questions — it's one that knows the difference between "how do I pick a lock for my own house" vs "how do I break into someone else's house."
