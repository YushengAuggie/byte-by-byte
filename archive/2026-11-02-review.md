### 📝 Quick Quiz — 3 Mini-Reviews

**Q1: [💻 Algorithms — 0/1 背包 / 0-1 Knapsack DP]**

Partition Equal Subset Sum (#416): Given `nums = [1, 5, 11, 5]`, how do you transform this into a 0/1 knapsack problem? Why must you iterate the DP array **backwards**?

<details><summary>显示答案 / Show Answer</summary>

Target = `sum(nums) // 2 = 11`. Use a 1D boolean dp array where `dp[j] = True` means sum `j` is achievable. For each number, update **right-to-left**: `dp[j] = dp[j] or dp[j - num]`.

Backwards traversal enforces the "0/1" constraint — each item can be used at most once. If you went forward, you'd reuse the same element multiple times (unbounded knapsack behavior). For `[1,5,11,5]`: `dp[11] = True` → partition `[11]` vs `[1,5,5]`. ✅

**核心洞察 / Key Insight:** 0/1 knapsack always iterates backwards; unbounded knapsack iterates forwards.
</details>

**Q2: [💻 Algorithms — 2D Grid DP]**

Unique Paths (#62): A robot moves on an `m×n` grid (only right or down). What is `dp[i][j]`? Write the transition. When does this DP approach beat the combinatorics formula `C(m+n-2, m-1)`?

<details><summary>显示答案 / Show Answer</summary>

`dp[i][j]` = number of unique paths to reach cell `(i, j)` from `(0, 0)`.

Transition: `dp[i][j] = dp[i-1][j] + dp[i][j-1]` (paths from above + from left)
Base case: `dp[0][j] = 1`, `dp[i][0] = 1` (only one way along any edge)

The DP approach generalizes to **Unique Paths II** (with obstacles), where the formula breaks down. When `grid[i][j] == obstacle`, set `dp[i][j] = 0`. The combinatorics formula only works for the obstacle-free version.

**核心洞察 / Key Insight:** 2D grid DP: each cell depends only on top and left neighbors. First row/col are all 1s.
</details>

**Q3: [💻 Algorithms — 2D String DP]**

Both LCS (#1143) and Edit Distance (#72) use a 2D table on two strings. What does `dp[i][j]` mean in each? What's the key difference in their transitions when characters **don't** match?

<details><summary>显示答案 / Show Answer</summary>

**LCS** — `dp[i][j]` = length of longest common subsequence of `text1[:i]` and `text2[:j]`
- Match: `dp[i][j] = dp[i-1][j-1] + 1`
- No match: `dp[i][j] = max(dp[i-1][j], dp[i][j-1])` ← take the better of skipping one char from either string

**Edit Distance** — `dp[i][j]` = min operations to convert `word1[:i]` → `word2[:j]`
- Match: `dp[i][j] = dp[i-1][j-1]` (free — no operation needed)
- No match: `dp[i][j] = 1 + min(dp[i-1][j], dp[i][j-1], dp[i-1][j-1])` ← delete, insert, or replace

Same table shape, opposite objectives: LCS **maximizes** (common length), Edit Distance **minimizes** (operations). The `dp[i-1][j-1]` diagonal cell is the key shared structural element.

**核心洞察 / Key Insight:** 2D string DP always initializes: `dp[i][0] = i`, `dp[0][j] = j` (build from empty string).
</details>
