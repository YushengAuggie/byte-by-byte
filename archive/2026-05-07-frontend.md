# 🎨 前端 / Frontend — Day 37
**主题 / Topic:** Virtualization — Rendering 10K Items Without Dying
**类别 / Category:** Performance | **阶段 / Phase:** Mastery

## 真实场景 / Real Scenario

你在做一个后台 dashboard，需要展示一个有 **10,000 条记录**的交易列表。产品说"不要分页，用户要能滚动看所有数据"。你直接 `items.map(item => <Row />)` 之后，浏览器直接卡死……

You're building an admin dashboard that needs to show **10,000 transaction rows**. Product says "no pagination — users should scroll through everything." You naively `items.map(item => <Row />)` and the browser hangs.

**问题根源:** DOM 中存在 10,000 个节点，即使大多数在视口外，浏览器仍然需要布局、样式计算、内存分配全部节点。

---

## 什么是虚拟化 / What is Virtualization?

**核心思路：** 只渲染视口内（及附近缓冲区）的节点，其余用占位符撑满滚动高度。

```
Without virtualization:
┌─────────────────┐ ← viewport (visible)
│ Row 1 (DOM)     │
│ Row 2 (DOM)     │
│ Row 3 (DOM)     │
└─────────────────┘
│ Row 4 (DOM)     │ ← not visible, but still in DOM!
│ ...             │
│ Row 10000 (DOM) │ ← all 10K nodes exist

With virtualization:
┌─────────────────┐ ← viewport
│ Row 47 (DOM)    │ ← only ~20 rows in DOM
│ Row 48 (DOM)    │
│ Row 49 (DOM)    │
└─────────────────┘
  (spacer div)      ← fakes scroll height for all 10K rows
```

## 代码示例 / Code Example

### 使用 react-window (推荐 / Recommended)

```tsx
import { FixedSizeList } from 'react-window';

interface Transaction {
  id: string;
  amount: number;
  date: string;
}

const Row = ({ index, style, data }: {
  index: number;
  style: React.CSSProperties;
  data: Transaction[];
}) => (
  // Must apply style prop! It positions the row absolutely
  <div style={style} className="flex px-4 items-center border-b">
    <span>{data[index].date}</span>
    <span className="ml-auto">${data[index].amount}</span>
  </div>
);

export function TransactionList({ transactions }: { transactions: Transaction[] }) {
  return (
    <FixedSizeList
      height={600}        // viewport height
      itemCount={transactions.length}
      itemSize={48}       // row height in px (must be fixed for FixedSizeList)
      width="100%"
      itemData={transactions}
    >
      {Row}
    </FixedSizeList>
  );
}
```

### 变高行 / Variable Height Rows → 用 react-virtual

```tsx
import { useVirtualizer } from '@tanstack/react-virtual';

function VariableList({ items }: { items: string[] }) {
  const parentRef = useRef<HTMLDivElement>(null);
  
  const virtualizer = useVirtualizer({
    count: items.length,
    getScrollElement: () => parentRef.current,
    estimateSize: () => 48,  // initial estimate, measured after render
    overscan: 5,             // extra rows above/below viewport
  });

  return (
    <div ref={parentRef} style={{ height: '600px', overflow: 'auto' }}>
      {/* Total height spacer */}
      <div style={{ height: virtualizer.getTotalSize(), position: 'relative' }}>
        {virtualizer.getVirtualItems().map((virtualItem) => (
          <div
            key={virtualItem.key}
            style={{
              position: 'absolute',
              top: virtualItem.start,
              width: '100%',
            }}
          >
            {items[virtualItem.index]}
          </div>
        ))}
      </div>
    </div>
  );
}
```

## 猜猜输出 / What Does This Code Do?

```tsx
// Without style prop:
const Row = ({ index }: { index: number }) => (
  <div className="row">{index}</div>  // ← missing style prop!
);
```

A) 正常渲染，只是没有虚拟化  
B) 所有行重叠在 top:0 的位置  
C) 什么都不显示  
D) 报错 TypeError

<details><summary>答案 / Answer</summary>
**B) 所有行重叠在 top: 0**

react-window 通过 `style` prop 给每行设置 `position: absolute; top: Npx; height: 48px`。不传 style 的话所有行都默认 `top: 0`，全部堆叠在列表顶部。这是使用 react-window 最常见的 bug。
</details>

## ❌ vs ✅ 对比 / Common Mistakes

```tsx
// ❌ Forgetting the style prop
const Row = ({ index, data }) => (
  <div>{data[index].name}</div>  // rows pile up at top!
);

// ✅ Always apply the style prop
const Row = ({ index, style, data }) => (
  <div style={style}>{data[index].name}</div>
);

// ❌ Inline function as children (re-creates on every render)
<FixedSizeList>
  {({ index, style }) => <Row ... />}
</FixedSizeList>

// ✅ Define Row component outside (stable reference)
const Row = ({ index, style, data }) => ...;
<FixedSizeList itemData={items}>{Row}</FixedSizeList>

// ❌ Using index as key when list can reorder
{items.map((item, i) => <Row key={i} />)}

// ✅ Use stable unique id
{items.map((item) => <Row key={item.id} />)}
```

## 何时用 / 何时不用 / When to Use / Not Use

| ✅ 用虚拟化 / Use | ❌ 不用 / Skip |
|------------------|---------------|
| 列表 > 200 条 | 列表 < 100 条 |
| 每行有复杂 DOM | 静态表格，服务端渲染 |
| 移动端性能敏感 | 需要 ctrl+F 搜索页面内容 |
| 无限滚动 | 行高非常不规则且无法估算 |

**注意:** 虚拟化使 Ctrl+F（浏览器查找）无法搜索未渲染的行，SEO 也会受影响。

## 🧒 ELI5
你在看一本 1000 页的书，但你只能看到当前打开的那两页。聪明的电脑只"印刷"你正在看的那两页，其余的页只是撑着书的厚度。你翻页时，它才印下一页，同时把之前的页"回收"。这就是虚拟化。

Like reading a 1000-page book, but only the open pages exist in your hands. The smart printer only prints the 2 pages you're reading, using blank fillers for thickness. When you turn a page, it prints the next one and "recycles" the previous. That's virtualization.
