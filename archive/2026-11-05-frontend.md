## 三种方案对比 / The Three Approaches

### 1. React Context — 原生，但有陷阱

```tsx
// ❌ 常见错误: 把所有状态放一个 Context
const AppContext = createContext({});

function AppProvider({ children }) {
  const [user, setUser] = useState(null);
  const [cart, setCart] = useState([]);
  const [theme, setTheme] = useState('light');
  const [notifications, setNotifications] = useState([]);

  // 问题: 任何一个状态变化，所有消费者都会重渲染！
  return (
    <AppContext.Provider value={{ user, cart, theme, notifications }}>
      {children}
    </AppContext.Provider>
  );
}

// ✅ 正确: 拆分 Context，最小化重渲染范围
const UserContext = createContext(null);
const CartContext = createContext(null);
const ThemeContext = createContext(null);
```

**Context 的真相:** Context 不是状态管理库，它是**数据传递机制**。
频繁变化的状态放 Context 会导致整棵子树重渲染，性能杀手。

### 2. Zustand — 现代轻量首选

```tsx
import { create } from 'zustand';

interface CartStore {
  items: CartItem[];
  total: number;
  addItem: (item: CartItem) => void;
  removeItem: (id: string) => void;
}

const useCartStore = create<CartStore>((set) => ({
  items: [],
  total: 0,

  addItem: (item) =>
    set((state) => ({
      items: [...state.items, item],
      total: state.total + item.price,
    })),

  removeItem: (id) =>
    set((state) => {
      const items = state.items.filter((i) => i.id !== id);
      return { items, total: items.reduce((sum, i) => sum + i.price, 0) };
    }),
}));

// ✅ 组件只订阅需要的切片 — 避免无关重渲染
function CartIcon() {
  // Only re-renders when items.length changes
  const count = useCartStore((state) => state.items.length);
  return <Badge count={count} />;
}

function CartTotal() {
  // Only re-renders when total changes
  const total = useCartStore((state) => state.total);
  return <span>${total.toFixed(2)}</span>;
}
```

**为什么 Zustand 好用:**
- 无 Provider 包裹
- Selector 精确订阅，避免无效渲染
- TypeScript 支持一流
- Bundle size 极小 (~1KB)

### 3. Redux Toolkit — 大型团队 / 复杂业务

```tsx
import { createSlice, configureStore } from '@reduxjs/toolkit';

const cartSlice = createSlice({
  name: 'cart',
  initialState: { items: [] as CartItem[], total: 0 },
  reducers: {
    addItem: (state, action) => {
      state.items.push(action.payload); // Immer: direct mutation is OK
      state.total += action.payload.price;
    },
    removeItem: (state, action) => {
      state.items = state.items.filter((i) => i.id !== action.payload);
      state.total = state.items.reduce((s, i) => s + i.price, 0);
    },
  },
});

// 优势: 内置 devtools + time-travel, middleware, 严格单向数据流
// 代价: 模板代码多，概念多 (action/reducer/selector/thunk)
```

## 猜猜输出 / Guess the Output

```tsx
const useStore = create<{ count: number; inc: () => void }>((set) => ({
  count: 0,
  inc: () => set((state) => ({ count: state.count + 1 })),
}));

function Counter() {
  const count = useStore((state) => state.count);
  const inc = useStore((state) => state.inc);
  console.log('render');
  return <button onClick={inc}>{count}</button>;
}
```

点击按钮 3 次，`console.log` 一共输出几次？

A) 1 次（只有初始渲染）
B) 3 次（只有点击触发）
C) 4 次（初始 1 次 + 点击 3 次）
D) 6 次（两个 selector 各触发）

**答案: C — 4 次**
初始渲染 1 次，每次点击 count 变化触发 1 次，共 4 次。
`inc` 是稳定引用（不变），不会额外触发重渲染。

## ❌ vs ✅ 决策框架

| 场景 | 推荐方案 | 理由 |
|------|----------|------|
| 主题 / 语言 (低频变化) | Context | 简单，无需库 |
| 购物车 / 用户信息 (中频) | **Zustand** | 轻量，selector 优化 |
| 服务器数据 (API 响应) | **React Query / SWR** | 缓存、loading、refetch 全包 |
| 大型企业多团队 | Redux Toolkit | 可预测，devtools，规范强 |

**黄金法则 / Golden Rule:**
> 服务器状态 → React Query/SWR
> 客户端全局状态 → Zustand
> 低频数据传递 → Context
> Redux: 团队规模或状态复杂度真正需要时再引入

**千万别这样做 / What NOT to do:**
```tsx
// ❌ 用 Redux 存 API 数据（重复造轮子）
dispatch(fetchUserData()); // 手写 loading/error/cache

// ✅ 用 React Query（专业工具做专业事）
const { data, isLoading } = useQuery(['user'], fetchUser);
```

## 🧒 ELI5

把状态管理想象成你家的收纳系统：
- **Context** = 家里的公共桌子，随手放，但人一多就乱
- **Zustand** = 整洁的小收纳盒，每样东西有固定位置，找起来快
- **Redux** = 严格标签化的文件柜，大家庭 / 公司适用
- **React Query** = 专门放"从外面带回来的东西"的区域（外卖 = API 数据）

小项目用收纳盒（Zustand），大公司用文件柜（Redux），外卖另放（React Query）。
