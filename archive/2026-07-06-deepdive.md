## Overview / 概述

**为什么堆很重要？**

堆（优先队列）是面试中频率极高的数据结构——只要题目出现 "top K"、"K 个最小/最大"、"合并 K 个有序序列"、"动态中位数" 这类关键词，第一反应就应该是堆。

核心价值：**不需要对整个数组排序（O(n log n)），只维护一个大小为 k 的堆（O(n log k)）**。当 k << n 时，性能差异巨大。

本期深度讲解三个层次：
1. 基础：K 个最近点（中等，热身）
2. 进阶：数组第 K 大元素（中等，多种解法对比）
3. 巅峰：数据流中位数（困难，双堆经典）

**Why heaps matter:**

The heap (priority queue) pattern shows up whenever you need to efficiently maintain the "top K" of a dynamic dataset. The insight is powerful: instead of re-sorting everything, you maintain a bounded heap that does O(log k) work per element instead of O(log n). For "find median from a stream" this becomes the two-heap trick — one of the most elegant data structure designs in interview canon.

## Part 1: Theory / 理论基础 (5 min)

### 堆的本质 / The Heap Mental Model

Python 的 `heapq` 是**最小堆**：最小值永远在堆顶（index 0）。

```
最小堆示例:
        1
       / \
      3   2
     / \
    4   5
```

**关键技巧：用最小堆模拟最大堆 → 存入负值**

```python
import heapq

# Min-heap (default)
min_heap = [3, 1, 4, 1, 5]
heapq.heapify(min_heap)
print(heapq.heappop(min_heap))  # 1

# Max-heap trick: negate values
max_heap = [-3, -1, -4, -1, -5]
heapq.heapify(max_heap)
print(-heapq.heappop(max_heap))  # 5
```

**三种堆的使用模式 / Three Heap Patterns:**

| 场景 | 用什么堆 | 核心操作 |
|------|---------|---------|
| Top K 最大值 | 大小为 k 的最小堆 | 若新元素 > 堆顶 → 替换堆顶 |
| Top K 最小值 | 大小为 k 的最大堆 | 若新元素 < 堆顶 → 替换堆顶 |
| 动态中位数 | 两个堆（大小各半）| 平衡两堆大小 |

**为什么维护 K 个最大值要用最小堆？/ Why use a min-heap for top-K largest?**

想象你有一个"门卫"在守住前 K 名。新来一个候选人，需要问：**"你比现有 K 人里最弱的那个强吗？"** 最小堆的堆顶就是那个"最弱"的人——O(1) 时间就能检查，O(log k) 时间踢掉并加入新人。

The min-heap's root is always the *weakest* element in your top-K set. It's your bouncer. Every new element only gets in if it beats the current weakest. This is the core insight for all "Top K" problems.

## Part 2: Step-by-Step Implementation / 一步一步实现 (8 min)

### 2.1 K Closest Points to Origin (Medium)

**问题**：给定 n 个点，返回距离原点最近的 k 个点。距离 = √(x² + y²)（比较时可省略 √）。

**方法一：直接排序（简单但非最优）**

```python
def kClosest_sort(points: list[list[int]], k: int) -> list[list[int]]:
    # Sort all points by squared distance, take first k
    # Time: O(n log n), Space: O(n)
    points.sort(key=lambda p: p[0]**2 + p[1]**2)
    return points[:k]
```

**方法二：最大堆，维护 K 个最小值（面试首选）**

```python
import heapq

def kClosest(points: list[list[int]], k: int) -> list[list[int]]:
    # Use a max-heap of size k
    # Python only has min-heap, so negate distance to simulate max-heap
    # Time: O(n log k), Space: O(k)
    
    max_heap = []  # stores (-distance_squared, x, y)
    
    for x, y in points:
        dist_sq = x*x + y*y
        # Push negative distance (max-heap trick)
        heapq.heappush(max_heap, (-dist_sq, x, y))
        
        # If heap exceeds size k, remove the farthest point (heap root = largest dist)
        if len(max_heap) > k:
            heapq.heappop(max_heap)  # removes the most negative = largest distance
    
    # Extract points (discard distance)
    return [[x, y] for (_, x, y) in max_heap]


# Trace through example: points = [[1,3],[-2,2],[5,-1]], k = 2
# 
# Process [1,3]: dist=10  → heap=[(-10, 1, 3)]           size=1 ≤ k, no pop
# Process [-2,2]: dist=8  → heap=[(-10,1,3),(-8,-2,2)]   size=2 ≤ k, no pop
# Process [5,-1]: dist=26 → heap=[(-26,5,-1),(-8,-2,2),(-10,1,3)]  size=3 > k
#   pop max → removes (-26, 5, -1)  [farthest point]
#   heap=[(-10,1,3),(-8,-2,2)]
# 
# Result: [[1,3],[-2,2]] ✓
```

**方法三：Quick Select（最优平均，O(n) 平均）**

```python
import random

def kClosest_quickselect(points: list[list[int]], k: int) -> list[list[int]]:
    # Partition-based selection — O(n) average, O(n²) worst
    # Not recommended in interviews unless specifically asked
    
    def dist(p):
        return p[0]**2 + p[1]**2
    
    def partition(left, right, pivot_idx):
        pivot_dist = dist(points[pivot_idx])
        # Move pivot to end
        points[pivot_idx], points[right] = points[right], points[pivot_idx]
        store = left
        for i in range(left, right):
            if dist(points[i]) <= pivot_dist:
                points[store], points[i] = points[i], points[store]
                store += 1
        # Move pivot to final position
        points[store], points[right] = points[right], points[store]
        return store
    
    left, right = 0, len(points) - 1
    while left < right:
        pivot_idx = random.randint(left, right)
        pivot_final = partition(left, right, pivot_idx)
        if pivot_final == k:
            break
        elif pivot_final < k:
            left = pivot_final + 1
        else:
            right = pivot_final - 1
    
    return points[:k]
```

**解法对比 / Comparison:**

| 解法 | 时间复杂度 | 空间复杂度 | 何时用 |
|------|-----------|-----------|------|
| 排序 | O(n log n) | O(1) | k 接近 n 时 |
| 最大堆 | O(n log k) | O(k) | **面试首选** |
| Quick Select | O(n) 平均 | O(1) | 追求最优、可接受最坏情况 |

### 2.2 Find Median from Data Stream (Hard) — 双堆经典

**问题**：设计一个数据结构，支持：
- `addNum(num)`: 加入一个整数
- `findMedian()`: 返回所有已加入整数的中位数

**核心思路 / Core Insight:**

把数据分成两半：
- 左半部分 → **最大堆**（堆顶 = 左半最大值）
- 右半部分 → **最小堆**（堆顶 = 右半最小值）

中位数 = 两堆堆顶的均值（或较大堆的堆顶）

```
数据: [1, 2, 3, 4, 5]

左半 (max-heap): [1, 2]  → 堆顶 = 2
右半 (min-heap): [3, 4, 5] → 堆顶 = 3

中位数 = (2 + 3) / 2 = 2.5 ✓
    
           2  |  3
          1   |   4
              |     5
     max-heap | min-heap
```

```python
import heapq

class MedianFinder:
    """
    Two-heap approach for dynamic median.
    
    Invariant:
      1. max_heap (left) stores the smaller half — as negatives (min-heap trick)
      2. min_heap (right) stores the larger half
      3. len(max_heap) == len(min_heap)  OR  len(max_heap) == len(min_heap) + 1
         (max_heap can have at most 1 extra element)
    
    Time: O(log n) per addNum, O(1) per findMedian
    Space: O(n)
    """
    
    def __init__(self):
        self.max_heap = []  # left half — stored as negatives
        self.min_heap = []  # right half
    
    def addNum(self, num: int) -> None:
        # Step 1: Always push to max_heap first
        heapq.heappush(self.max_heap, -num)
        
        # Step 2: Balance — ensure max_heap top ≤ min_heap top
        # If max_heap's largest > min_heap's smallest, move it over
        if self.min_heap and (-self.max_heap[0]) > self.min_heap[0]:
            val = -heapq.heappop(self.max_heap)
            heapq.heappush(self.min_heap, val)
        
        # Step 3: Rebalance sizes — max_heap can have at most 1 extra
        if len(self.max_heap) > len(self.min_heap) + 1:
            val = -heapq.heappop(self.max_heap)
            heapq.heappush(self.min_heap, val)
        elif len(self.min_heap) > len(self.max_heap):
            val = heapq.heappop(self.min_heap)
            heapq.heappush(self.max_heap, -val)
    
    def findMedian(self) -> float:
        # If odd total: max_heap has the extra element (middle value)
        if len(self.max_heap) > len(self.min_heap):
            return float(-self.max_heap[0])
        # If even total: average of both tops
        return (-self.max_heap[0] + self.min_heap[0]) / 2.0


# ── Trace through: addNum(1), addNum(2), addNum(3) ──
#
# addNum(1):
#   push -1 to max_heap → max_heap=[-1], min_heap=[]
#   no balance needed (min_heap empty)
#   sizes: 1 vs 0 → ok (max_heap can have +1)
#   state: max_heap=[-1], min_heap=[]
#
# addNum(2):
#   push -2 to max_heap → max_heap=[-2,-1], min_heap=[]
#   balance check: -(-2)=2 > nothing (min_heap empty) → skip
#   size check: len(max_heap)=2 > len(min_heap)+1=1 → move top of max to min
#     pop -2 from max_heap → push 2 to min_heap
#   state: max_heap=[-1], min_heap=[2]
#
# addNum(3):
#   push -3 to max_heap → max_heap=[-3,-1], min_heap=[2]
#   balance check: -(-3)=3 > min_heap[0]=2 → move 3 to min_heap
#     pop -3 from max_heap → push 3 to min_heap
#   max_heap=[-1], min_heap=[2,3]
#   size check: len(min_heap)=2 > len(max_heap)=1 → move min top to max
#     pop 2 from min_heap → push -2 to max_heap
#   state: max_heap=[-2,-1], min_heap=[3]  → wait sizes 2 vs 1, max_heap has +1 ✓
#
# findMedian():
#   len(max_heap)=2 > len(min_heap)=1 → return -max_heap[0] = -(-2) = 2 ✓
#   Actual data: [1,2,3] → median = 2 ✓
```

**为什么这样设计不会出错？/ Why does this invariant work?**

关键是两个堆维护了一个"有序分割线"：
- max_heap 里所有元素 ≤ min_heap 里所有元素（Step 2 保证）
- 两堆大小差最多为 1（Step 3 保证）
- 因此中位数始终在堆顶，O(1) 可读

The invariant guarantees that after every `addNum`, the heaps are sorted relative to each other AND balanced in size. The median is always at one or both heap tops — no scanning needed.

## Part 3: Edge Cases & Gotchas / 边界情况 (2 min)

**K Closest Points:**

```python
# Edge case 1: k == len(points) → return all points
# Edge case 2: points on same distance → any k of them valid
# Edge case 3: k == 1 → heap of size 1 = just track current minimum
# GOTCHA: Don't sqrt! x*x + y*y is sufficient for comparison
# GOTCHA: Tuple comparison — heapq compares tuples element by element
#   (-dist, x, y) works because dist disambiguates before x, y are checked
```

**Find Median from Data Stream:**

```python
# Edge case 1: single element → return float(that element)
# Edge case 2: two elements → return their average
# Edge case 3: all same values → median is that value

# GOTCHA 1: Don't forget the negation when extracting from max_heap
#   return -self.max_heap[0]  ← the minus sign is easy to forget!

# GOTCHA 2: The balance condition order matters
#   Always push to max_heap FIRST, then check cross-heap ordering,
#   THEN balance sizes. Reversing steps leads to subtle bugs.

# GOTCHA 3: Python's heapq doesn't support decrease-key
#   If you need to remove arbitrary elements, use a lazy deletion pattern
#   or use sortedcontainers.SortedList instead (O(log n) insert+delete)
```

**通用堆陷阱 / General heap gotchas:**

```python
# heapq.heappush / heappop work on lists in-place
# heapq does NOT sort the list visually — internal array != sorted order!
import heapq
h = [3, 1, 4, 1, 5, 9]
heapq.heapify(h)
print(h)  # [1, 1, 4, 3, 5, 9] — NOT [1,1,3,4,5,9]!
# But heappop() always returns the minimum correctly
```

## Part 5: Interview Simulation / 面试模拟 (3 min)

**Q1: K Closest Points 时间复杂度是多少？什么时候用排序更好？**

> 堆方案 O(n log k)，排序方案 O(n log n)。当 k 很大（k ≈ n）时，排序不一定更慢，因为常数因子更小；当 k << n（比如 k=10, n=1000000）时，堆方案快很多。面试时两种都说，然后给 tradeoff。

**Q2: Find Median 如果允许 O(n) 空间但要 O(1) addNum，能做到吗？**

> 不能在最坏情况下保证 O(1) addNum + O(1) median。堆方案已经是最优了：O(log n) addNum，O(1) median。如果只需要近似中位数，可以用 T-Digest（流式统计算法），但精确中位数无法比 O(log n) 更快。

**Q3: 如何扩展双堆方案支持删除某个特定数字？**

> 标准堆不支持 O(log n) 随机删除。解法：**懒删除（Lazy Deletion）**——用一个 Counter 记录"已删除但还在堆里"的元素，heappop 时检查并跳过。时间复杂度均摊 O(log n)。或者用 `SortedList`（sortedcontainers 库），O(log n) 支持任意插入删除。

**Q4: 数组第 K 大（LeetCode #215）有更快的解法吗？**

> Quick Select 平均 O(n)，最坏 O(n²)。堆方案 O(n log k)。对于固定 k 值，堆通常更可预测（无最坏情况）。面试时如果面试官追问"能做到线性吗"，则答 Quick Select。

```python
def findKthLargest(nums: list[int], k: int) -> int:
    # Min-heap of size k — top is the kth largest
    # Time: O(n log k), Space: O(k)
    heap = []
    for n in nums:
        heapq.heappush(heap, n)
        if len(heap) > k:
            heapq.heappop(heap)
    return heap[0]  # kth largest is the smallest in our top-k heap
```

**Q5: 如果数据流数据量超大（PB 级），如何设计分布式中位数？**

> 单机双堆不够用时：
> 1. **采样方案**：随机采样 + 排序，给近似中位数（Reservoir Sampling）
> 2. **分段汇总**：每台机器维护本地直方图（histogram），汇总时合并直方图找中位数（Spark/Flink 的实现思路）
> 3. **T-Digest**：Databricks/Spark 用的流式近似中位数算法，空间 O(1/epsilon²)，精度可配置
