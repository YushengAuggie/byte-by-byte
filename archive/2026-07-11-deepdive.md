## Overview / 概述

**中文：**
回溯算法是面试中最常考的算法之一，也是最容易搞混的。它的本质是**受控穷举**——在搜索树上做深度优先遍历，遇到不满足条件的节点就"剪枝"，回退到上一状态再尝试其他选项。

掌握回溯 = 掌握一个模板 + 一套思维方式。NeetCode 150 中有 9 道回溯题（全在今天开始的这个 block），从今天的 Subsets 到最终的 N-Queens。这篇 deep dive 会让你把模板内化，用一套心智模型解决所有变体。

**English:**
Backtracking is "controlled brute-force." You explore a decision tree depth-first, undo choices when they lead to dead ends, and continue. The key insight: **you're building a result incrementally, and the "undo" step is what makes it backtracking (not just DFS).**

This deep dive covers the universal template, 5 core problem types, and the mental model that lets you derive solutions from scratch in interviews.

## Part 1: Theory / 理论基础 (5 min)

### 核心思维模型 / The Mental Model

**中文：**
把回溯想象成一棵**决策树**：
- 每个**节点**代表当前选择路径（`path`）
- 每条**边**代表你做的一个选择（"选 or 不选 X"）
- **叶节点**是最终答案（完整路径）
- **剪枝**：某个分支注定不可能产生有效答案，直接跳过

三步走：**选择 → 递归 → 撤销**

```
选择 (Choose)   → path.append(item)
递归 (Recurse)  → backtrack(next_state)
撤销 (Undo)     → path.pop()
```

**English:**
Think of it as a **decision tree**:
- Root = empty state
- Each level = one decision
- Leaf = complete valid solution

The "undo" step is critical — it **restores state** before trying the next branch. Without undo, you'd need to copy state on every call (expensive). With undo, you reuse a single mutable path.

### 通用模板 / Universal Template

```python
def solve(problem_input):
    result = []
    
    def backtrack(path, start_or_remaining):
        # BASE CASE: path is complete
        if is_complete(path):
            result.append(path[:])  # ← shallow copy! path will mutate
            return
        
        # EXPLORE choices
        for choice in get_choices(start_or_remaining):
            # PRUNE: skip invalid choices early
            if not is_valid(choice, path):
                continue
            
            # CHOOSE
            path.append(choice)
            
            # RECURSE
            backtrack(path, next_state(start_or_remaining, choice))
            
            # UNDO (backtrack)
            path.pop()
    
    backtrack([], initial_state)
    return result
```

### 五种变体的关键差异 / 5 Problem Types

| 问题类型 | 是否排列敏感 | 是否可重用元素 | 关键参数变化 |
|---------|------------|-------------|------------|
| 子集 Subsets | 否 | 否 | `start` 递增 |
| 组合 Combination Sum | 否 | 是 | `start` 不变 |
| 排列 Permutations | 是 | 否 | `used[]` 标记 |
| 子集II (有重复) | 否 | 否 | 排序 + 去重 |
| N-Queens | 是 | 否 | `cols/diags` 标记 |

## Part 2: Step-by-Step Implementation / 一步一步实现 (8 min)

### Problem 1: Subsets (#78) — 基础模板

**中文：** 给定不含重复元素的整数数组 `nums`，返回所有可能的子集（幂集）。

**English:** Return all possible subsets (power set) of a list with no duplicates.

🔗 [LeetCode #78](https://leetcode.com/problems/subsets/) | 📹 [NeetCode](https://www.youtube.com/watch?v=REOH22Xwdkk)

```python
def subsets(nums: list[int]) -> list[list[int]]:
    result = []
    
    def backtrack(start: int, path: list[int]):
        # Every node in the tree IS a valid subset (including empty)
        # So we collect at EVERY call, not just leaf nodes
        result.append(path[:])  # copy current path
        
        for i in range(start, len(nums)):
            # CHOOSE: add nums[i] to path
            path.append(nums[i])
            
            # RECURSE: only consider elements after i (no duplicates, no reuse)
            backtrack(i + 1, path)
            
            # UNDO: remove nums[i] from path
            path.pop()
    
    backtrack(0, [])
    return result

# Example: nums = [1, 2, 3]
# Decision tree:
#              []
#          /   |   \
#        [1]  [2]  [3]
#       /   \    \
#    [1,2] [1,3] [2,3]
#     /
# [1,2,3]
# Result: [[], [1], [1,2], [1,2,3], [1,3], [2], [2,3], [3]]
```

**复杂度 / Complexity:** Time O(n · 2ⁿ), Space O(n) recursion stack + O(n · 2ⁿ) output

### Problem 2: Combination Sum (#39) — 元素可重复使用

**中文：** 从 `candidates` 中选数，允许重复使用，找出所有和为 `target` 的组合。

**English:** Find all unique combinations that sum to target; each number may be used unlimited times.

🔗 [LeetCode #39](https://leetcode.com/problems/combination-sum/)

```python
def combinationSum(candidates: list[int], target: int) -> list[list[int]]:
    result = []
    
    def backtrack(start: int, path: list[int], remaining: int):
        if remaining == 0:
            # COMPLETE: path sums to target
            result.append(path[:])
            return
        if remaining < 0:
            # PRUNE: overshot, no point continuing
            return
        
        for i in range(start, len(candidates)):
            path.append(candidates[i])
            # KEY: pass i (not i+1) → same element can be reused
            backtrack(i, path, remaining - candidates[i])
            path.pop()
    
    backtrack(0, [], target)
    return result

# vs Subsets: start=i (not i+1) allows reuse
```

### Problem 3: Permutations (#46) — 顺序敏感

**中文：** 返回数组的所有全排列。[1,2] 和 [2,1] 是不同结果。

**English:** Return all permutations. Order matters: [1,2] ≠ [2,1].

🔗 [LeetCode #46](https://leetcode.com/problems/permutations/)

```python
def permute(nums: list[int]) -> list[list[int]]:
    result = []
    used = [False] * len(nums)  # track which elements are in current path
    
    def backtrack(path: list[int]):
        if len(path) == len(nums):
            # COMPLETE: used all elements exactly once
            result.append(path[:])
            return
        
        for i in range(len(nums)):
            if used[i]:
                continue  # PRUNE: already in path
            
            # CHOOSE
            used[i] = True
            path.append(nums[i])
            
            # RECURSE: no start param — we consider ALL unused elements
            backtrack(path)
            
            # UNDO
            path.pop()
            used[i] = False
    
    backtrack([])
    return result

# KEY DIFFERENCE from subsets/combinations:
# - No `start` parameter (order matters, can pick from anywhere)
# - Uses `used[]` array instead to avoid duplicates within a path
```

### Problem 4: Subsets II (#90) — 处理重复元素

**中文：** 数组中有重复元素，要求输出不重复的子集。

**English:** Array has duplicates; return unique subsets (no duplicate subsets).

🔗 [LeetCode #90](https://leetcode.com/problems/subsets-ii/)

```python
def subsetsWithDup(nums: list[int]) -> list[list[int]]:
    nums.sort()  # STEP 1: sort so duplicates are adjacent
    result = []
    
    def backtrack(start: int, path: list[int]):
        result.append(path[:])
        
        for i in range(start, len(nums)):
            # STEP 2: skip duplicate at same tree level
            # i > start means we've already explored nums[i-1] at this level
            if i > start and nums[i] == nums[i - 1]:
                continue  # ← the dedup trick
            
            path.append(nums[i])
            backtrack(i + 1, path)
            path.pop()
    
    backtrack(0, [])
    return result

# nums = [1, 2, 2]
# After sort: [1, 2, 2]
# At level 1:
#   i=0: pick 1 ✓
#   i=1: pick 2 ✓
#   i=2: nums[2]==nums[1] AND i>start → SKIP (would duplicate [2])
```

**去重规则 / Dedup Rule:** `if i > start and nums[i] == nums[i-1]: continue`
- `i > start` means "we're at the same recursion level" (not going deeper)
- Skip if same value as previous element at this level

### Problem 5: N-Queens (#51) — 约束传播

**中文：** 最经典的回溯题。在 n×n 棋盘上放 n 个皇后，使其互不攻击。

**English:** Place n queens on n×n board such that no two queens attack each other.

🔗 [LeetCode #51](https://leetcode.com/problems/n-queens/)

```python
def solveNQueens(n: int) -> list[list[str]]:
    result = []
    # Track which columns and diagonals are occupied
    cols = set()
    pos_diag = set()  # row + col is constant along \ diagonals
    neg_diag = set()  # row - col is constant along / diagonals
    board = [['.' for _ in range(n)] for _ in range(n)]
    
    def backtrack(row: int):
        if row == n:
            # COMPLETE: placed queen in every row
            result.append([''.join(r) for r in board])
            return
        
        for col in range(n):
            # PRUNE: this position is under attack
            if col in cols or (row + col) in pos_diag or (row - col) in neg_diag:
                continue
            
            # CHOOSE: place queen
            cols.add(col)
            pos_diag.add(row + col)
            neg_diag.add(row - col)
            board[row][col] = 'Q'
            
            # RECURSE: move to next row
            backtrack(row + 1)
            
            # UNDO: remove queen
            cols.remove(col)
            pos_diag.remove(row + col)
            neg_diag.remove(row - col)
            board[row][col] = '.'
    
    backtrack(0)
    return result

# Key insight: one queen per row (we recurse row by row)
# Diagonal detection:
#   pos_diag (↘): cells on same diagonal have equal row+col
#   neg_diag (↗): cells on same anti-diagonal have equal row-col
```

**复杂度 / Complexity:** Time O(n!), Space O(n²)

## Part 3: Edge Cases & Gotchas / 边界情况 (2 min)

**1. 忘记复制路径 (Forgetting to copy path)**
```python
# WRONG — appends reference to same list
result.append(path)  # ← all entries will be empty [] at the end!

# CORRECT
result.append(path[:])  # shallow copy is fine for flat lists
result.append(list(path))  # equivalent
```

**2. 重复问题不排序 (Skipping sort for duplicates)**
- `Subsets II`, `Combination Sum II`, `Permutations II` all require sorting first
- Without sort, duplicates aren't adjacent → dedup logic breaks

**3. 收集时机错误 (Wrong collection point)**
- Subsets: collect at EVERY call (every node is a result)
- Combination Sum: collect only when `remaining == 0`
- Permutations: collect only when `len(path) == n`

**4. 组合 vs 排列的 start 参数**
```python
# Combination: pass i+1 to avoid reuse, i to allow reuse
backtrack(i + 1, ...)  # no reuse
backtrack(i, ...)      # allow reuse (Combination Sum)

# Permutation: NO start param, use `used[]` instead
```

**5. 提前终止 (Early termination)**
```python
# For sorted arrays, if current is already too large, prune the rest
for i in range(start, len(candidates)):
    if candidates[i] > remaining:
        break  # all remaining are larger (since sorted)
```

## Part 4: Real-World Application / 实际应用 (2 min)

**中文：**
回溯在实际工程中比你想象的更常见：

1. **正则表达式引擎** — `.*` 匹配时需要回溯尝试不同的匹配长度
2. **编译器解析** — 语法树解析中的回溯文法
3. **约束求解** — Sudoku solvers, scheduling systems, SAT solvers
4. **游戏 AI** — Chess, Go 的 minimax 树（带剪枝）
5. **包依赖解析** — pip/npm 解析依赖版本组合

**English:**
Backtracking powers systems you use daily:

- **Regex engines**: `.*` tries all possible lengths, backtracks on mismatch
- **SQL query planners**: try different join orders, backtrack when cost estimate is poor  
- **IDE autocomplete**: generate candidate completions, prune invalid ones
- **Package managers**: resolve dependency version combinations (a real combinatorial problem!)
- **Constraint solvers**: workforce scheduling, exam timetabling

The pattern: **explore → validate → backtrack** maps directly to any search-over-state-space problem.

## Part 5: Interview Simulation / 面试模拟 (3 min)

**面试官：** Given Subsets, can you walk me through the decision tree?

> **你：** Sure. We start with an empty path. For `[1,2,3]`, at level 0 we choose whether to include 1: if we do, go left; if not, go right. Then same decision for 2, then 3. Every node (not just leaves) is a valid subset. That's why we collect at every recursive call, not just the base case.

---

**面试官：** How would you modify Subsets to handle duplicates like `[1,2,2]`?

> **你：** Sort the array first, so duplicates are adjacent. Then during the for loop, if `i > start` and `nums[i] == nums[i-1]`, we skip — this prevents generating duplicate subsets at the same tree level. The `i > start` condition is crucial: it only skips at the same level, not across levels (which would incorrectly prune `[1,2]` and `[1,2]` from different branches).

---

**面试官：** What's the time complexity of Permutations?

> **你：** O(n · n!). There are n! permutations; for each, we spend O(n) copying the path into results. The recursion tree has at most n levels, each branching up to n times, but the `used[]` check ensures we don't revisit — so total nodes = n! (leaf) + n!/1 + n!/2 + ... ≈ O(n · n!).

---

**面试官：** When would you use backtracking vs dynamic programming?

> **你：** DP when you need the optimal value of overlapping subproblems. Backtracking when you need to enumerate all valid solutions (or just one). If the problem says "find ALL combinations/permutations/subsets", that's backtracking. If it says "find the MINIMUM cost / MAXIMUM value", lean toward DP first.

---

**面试官：** Can you solve Combination Sum without backtracking? (follow-up)

> **你：** You could use iterative BFS with a queue of (current_path, remaining), but it's much less clean and has the same complexity. Backtracking's elegance is in the natural undo via the call stack — the recursive structure mirrors the problem structure. I'd keep it as backtracking.

## Summary: The Backtracking Cheat Sheet

```
CHOOSE what to add to path (loop over choices)
  ↓ PRUNE if invalid (i > start + duplicate, used[], constraint violated)
    ↓ RECURSE (pass new start OR same start for reuse)
      ↓ at base case: result.append(path[:])
    ↑ UNDO: pop from path, unmark used[]
```
