## Mini-Quiz: Days 61–64

**Q1: [System Design] What makes designing a Stock Exchange / Order Matching Engine different from a typical CRUD system?**
> **A:** Determinism and latency are paramount. The matching engine must be single-threaded per symbol for correctness (no race conditions), use event sourcing for crash recovery, and achieve microsecond-level latency. Unlike CRUD systems, you can't use a relational DB as the primary store — state lives in-memory with a write-ahead log.

**Q2: [Algorithms] In Binary Tree Level Order Traversal (BFS), what's the key to separating nodes by level?**
> **A:** Before processing each level, record `queue.size()`. Dequeue exactly that many nodes — they all belong to the current level. Their children go into the queue for the next level. This avoids needing a sentinel/null marker.

**Q3: [Python Craft] Why is the Singleton pattern often considered an anti-pattern in Python?**
> **A:** It creates hidden global state, makes testing hard (can't reset between tests), and violates dependency injection principles. Python alternatives: module-level globals (already singleton by nature), `functools.lru_cache` on a factory function, or dependency injection via constructor. Use Singleton only when you truly need one shared resource (e.g., a connection pool) and can't inject it.
