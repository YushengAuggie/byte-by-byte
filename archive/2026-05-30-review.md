**Q1: [🏗️ System Design]** From Day 51 — Distributed File System (HDFS/GFS)

HDFS 把一个大文件分成多个 chunk 存在不同 DataNode 上。NameNode 挂掉了，会发生什么？Google GFS 是怎么处理这个单点故障问题的？

HDFS splits files into chunks across DataNodes. The NameNode goes down — what happens? How does GFS address this single point of failure?

<details>
<summary>显示答案 / Show Answer</summary>

**NameNode 是 HDFS 的元数据中心，挂掉后整个集群无法读写（因为没人知道数据在哪）。**

- **HDFS 方案:** Secondary NameNode 定期做 checkpoint，但它不是热备，故障恢复需要时间。HDFS HA 方案用两个 NameNode (Active/Standby) + ZooKeeper 自动切换。
- **GFS 方案:** GFS 也是单 Master，但通过 operation log + checkpoint 到多副本持久化来减少恢复时间；同时 chunk lease 机制允许 chunk server 之间直接传输数据，降低 Master 压力。
- **核心洞察:** 元数据服务的高可用比数据服务更难，因为元数据必须强一致。

</details>

**Q2: [⚙️ Algorithms]** From Day 53 — Reverse Nodes in K-Group

给你一个链表和整数 K，每 K 个节点翻转一组，不足 K 个的保持原样。这道题和"翻转整个链表"有什么关键区别？空间复杂度能做到 O(1) 吗？

Given a linked list and integer K, reverse every K-group; leave the tail as-is if fewer than K nodes remain. What's the key difference from reversing the whole list? Can you achieve O(1) space?

<details>
<summary>显示答案 / Show Answer</summary>

**关键区别：需要先"看前方"确认剩余节点 ≥ K 才翻转，否则保留。**

```
核心步骤：
1. 先检查从当前位置往后是否还有 K 个节点（不够就停止）
2. 翻转这 K 个节点（标准链表翻转）
3. 将翻转后的头接到上一组的尾部
4. 将这组的尾部（原头部）连到下一组
5. 前进到下一组起点，重复
```

**空间复杂度:** 迭代实现可以做到 O(1)；递归实现是 O(N/K) 栈空间。面试中首选迭代。

**最容易出 bug 的地方:** 翻转前忘记断开与后续节点的连接，导致成环。

</details>

**Q3: [🐍 Python Craft]** From Day 54 — GIL Deep Dive

Python 的 GIL 到底保护的是什么？为什么 I/O 密集型任务用多线程有效，而 CPU 密集型任务无效？什么时候应该用 multiprocessing 代替 threading？

What exactly does Python's GIL protect? Why does multi-threading work for I/O-bound but not CPU-bound tasks? When should you reach for multiprocessing instead?

<details>
<summary>显示答案 / Show Answer</summary>

**GIL (Global Interpreter Lock) 保护的是 CPython 解释器内部的引用计数机制，防止多线程同时修改对象引用计数导致内存损坏。**

- **I/O 密集型有效的原因:** 线程在等待 I/O（网络、磁盘）时会主动释放 GIL，让其他线程运行。所以 10 个线程各自等待网络请求，总体吞吐量是单线程的 ~10x。
- **CPU 密集型无效的原因:** 纯计算不需要等待外部，GIL 每隔 ~5ms 才强制切换一次。多线程 Python 在 CPU 密集任务上实际上是串行的，切换开销反而更慢。
- **什么时候用 multiprocessing:** 需要并行 CPU 计算时——每个进程有独立的 GIL，可以真正并行。代价是进程间通信开销 + 内存不共享（需要序列化）。
- **实用规则:** I/O 密集 → threading 或 asyncio；CPU 密集 → multiprocessing 或 C 扩展。

</details>
