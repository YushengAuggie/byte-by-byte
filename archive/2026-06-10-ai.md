## AI Coding Assistants — Architecture & How They Work

> **AI 编程助手的底层架构** — Copilot、Cursor 是怎么工作的？

*(CONCEPT mode — deep technical explanation)*

---

### 直觉解释 / Intuitive Explanation

你用 GitHub Copilot 或 Cursor 时，感觉它"懂"你的代码。但它不是真的理解——它在做一件非常复杂的事：**把你的整个编辑器上下文打包成 prompt，喂给一个专门微调过的 LLM，再把输出实时渲染回编辑器**。

*Copilot/Cursor doesn't "understand" your code in the human sense. It's doing something sophisticated: packaging your entire editor context into a prompt, feeding it to a fine-tuned LLM, and streaming the output back in real time.*

---

### 核心架构层 / Core Architecture Layers

```
┌─────────────────────────────────────────────────────────┐
│                    Editor Plugin                         │
│  VSCode Extension / JetBrains Plugin                     │
│  - Captures keystrokes, cursor position                  │
│  - Renders inline completions                            │
│  - Shows diff views (Cursor's agent mode)                │
└───────────────────────────┬─────────────────────────────┘
                            │ Context Assembly
┌───────────────────────────▼─────────────────────────────┐
│                Context Engine                            │
│  - Current file (above + below cursor)                   │
│  - Open tabs / recently edited files                     │
│  - Language Server Protocol (LSP) symbols & types        │
│  - Git history (recently changed lines)                  │
│  - Comments, docstrings, test files                      │
│  - Vector search over codebase (RAG for large repos)     │
└───────────────────────────┬─────────────────────────────┘
                            │ Prompt
┌───────────────────────────▼─────────────────────────────┐
│                LLM Inference Layer                       │
│  - Fill-in-the-Middle (FIM) model for completions        │
│  - Chat model for agent/explain mode                     │
│  - Streaming tokens back to editor                       │
│  - Model: GPT-4o / Claude Sonnet / DeepSeek / local      │
└───────────────────────────┬─────────────────────────────┘
                            │ Post-processing
┌───────────────────────────▼─────────────────────────────┐
│               Output Processing                          │
│  - Parse code fences, strip artifacts                    │
│  - Apply to editor as inline ghost text                  │
│  - Diff view for larger edits                            │
│  - Multi-file edits (Cursor Composer / Copilot Workspace)│
└─────────────────────────────────────────────────────────┘
```

### 关键技术 1: Fill-in-the-Middle (FIM) / Key Tech 1

普通 LLM 只做 **prefix → completion**（给前缀，预测后文）。  
编程场景更需要 **prefix + suffix → middle**（知道前后文，填中间）。

*Standard LLMs predict what comes next. But in code editing, you often need to fill a gap between existing lines — that's FIM.*

```
Standard:  [prefix]  → [completion]

FIM:       [prefix]  [FILL]  [suffix]
           "def foo(x):"  ???  "return result"
```

训练时专门构造这样的三元组：`<PRE>prefix<SUF>suffix<MID>middle`。  
DeepSeek Coder、Code Llama、StarCoder 都有 FIM 能力。

---

### 关键技术 2: 上下文组装 / Key Tech 2: Context Assembly

LLM 的 context window 是有限的（128K tokens ≈ ~100K 字符）。如何决定塞什么进去？

**GitHub Copilot 的做法（公开研究）：**
1. **当前文件** — 光标附近的代码优先级最高
2. **Import/require 的文件** — 直接依赖有语义关联
3. **最近编辑的文件** — 时间局部性
4. **Jaccard 相似度** — 找词汇相似的代码片段（不需要 embedding！）
5. **语言服务器（LSP）** — 获取类型信息、函数签名

Cursor 更进一步，用 **codebase embedding + vector search（RAG）** 在大型仓库里找相关代码。

---

### 关键技术 3: Agent Mode / Key Tech 3

Cursor Composer 和 Copilot Workspace 代表下一代：从"补全"到"代理"。

```
User: "Add pagination to the user list API"

Agent Loop:
  1. Read: src/routes/users.ts, src/models/User.ts
  2. Plan: need to modify query + API response + tests
  3. Edit: src/routes/users.ts (add limit/offset params)
  4. Edit: src/models/User.ts (add paginate method)  
  5. Edit: tests/users.test.ts (add pagination tests)
  6. Run: npm test → see if tests pass
  7. Fix: if tests fail, iterate
```

这是 **ReAct 模式**（Reason + Act）在编程场景的落地：  
LLM 循环调用工具（读文件、写文件、运行命令），直到任务完成。

### 可运行示例 / Runnable Python Snippet

用 OpenAI API 模拟一个简单的 FIM 请求：

```python
# pip install openai
from openai import OpenAI

client = OpenAI()  # uses OPENAI_API_KEY env var

# Simulating FIM-style completion
# (GPT-4 doesn't have native FIM, but we can prompt it)
prefix = """def calculate_discount(price: float, user_type: str) -> float:
    \"\"\"Apply discount based on user type.\"\"\"
    if user_type == "premium":
"""

suffix = """
    return discounted_price
"""

response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{
        "role": "user",
        "content": f"Complete the middle of this Python function.\n\nPrefix:\n{prefix}\n\nSuffix:\n{suffix}\n\nMiddle only (no prefix/suffix):"
    }],
    max_tokens=100,
    temperature=0.2,
)

print(response.choices[0].message.content)
# Expected output:
#     discounted_price = price * 0.8
# elif user_type == "vip":
#     discounted_price = price * 0.7
# else:
#     discounted_price = price
```

*For native FIM, use models like `deepseek-coder` or `codellama` which have FIM tokens built in.*

### 🧒 ELI5

你有一个超聪明的朋友，他读过 GitHub 上所有的代码（数十亿行）。你开始写代码，他站在你背后看着你的屏幕——不只看你刚写的，还看你打开的其他文件、你的 import、你的注释。然后他在你脑海里轻轻说"你下一行应该写这个"。AI 编程助手就是这个朋友，只是他住在服务器里，每次你停止打字时他都要想一下。

*Imagine a friend who's read billions of lines of code. He watches your whole screen — current file, open tabs, your imports. Then he whispers suggestions in your ear. AI coding assistants are that friend, except they live on a server and think for a split second every time you pause typing.*
