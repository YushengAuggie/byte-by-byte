## Next.js App Router — Layouts, Loading, Error
> Mastery Phase · ~2 min read | Category: Next.js | Week 7

---

### 🎯 真实场景 / Real Scenario

你在做一个 **SaaS dashboard**，需要：
- 所有 `/dashboard/*` 页面共享侧边栏和导航
- 数据加载时显示 skeleton，不是白屏
- API 出错时优雅展示错误页，不是崩溃

You're building a **SaaS dashboard** — all `/dashboard/*` pages share a sidebar and nav, loading states need skeleton screens (not blank pages), and API errors should show a graceful error UI instead of crashing the app.

App Router 用**文件系统约定**解决这三个问题：`layout.tsx`、`loading.tsx`、`error.tsx`。

---

### 💻 代码示例 / Code Example

**文件结构：**
```
app/
  dashboard/
    layout.tsx      ← shared shell for all /dashboard routes
    loading.tsx     ← auto shown during server component fetch
    error.tsx       ← catches errors in this subtree
    page.tsx
    settings/
      page.tsx      ← inherits layout.tsx automatically
```

**layout.tsx — 共享外壳：**
```tsx
// app/dashboard/layout.tsx
export default function DashboardLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <div className="flex">
      <Sidebar />          {/* persists across navigations */}
      <main className="flex-1">
        {children}         {/* page content swaps here */}
      </main>
    </div>
  )
}
```

**loading.tsx — 自动 Suspense 边界：**
```tsx
// app/dashboard/loading.tsx
// Next.js wraps page.tsx in <Suspense fallback={<Loading />}>
export default function Loading() {
  return <DashboardSkeleton />  // show while page fetches data
}
```

**error.tsx — 错误边界：**
```tsx
'use client'  // must be client component

import { useEffect } from 'react'

export default function Error({
  error,
  reset,
}: {
  error: Error & { digest?: string }
  reset: () => void    // retry function from Next.js
}) {
  useEffect(() => {
    console.error(error)
  }, [error])

  return (
    <div>
      <h2>Something went wrong!</h2>
      <button onClick={() => reset()}>Try again</button>
    </div>
  )
}
```

### 🤔 猜猜输出 / Quiz

```tsx
// app/dashboard/layout.tsx renders <Sidebar /> + {children}
// User navigates from /dashboard to /dashboard/settings

// Q: Does <Sidebar /> re-render?
```

**A) Yes, full re-render**
**B) No, layout persists across navigations**
**C) Depends on whether Sidebar has state**
**D) Only re-renders if layout.tsx has 'use client'**

<details><summary>显示答案 / Show Answer</summary>
**B** — Layout 组件在路由切换时**不会重新挂载**，这是 App Router 的核心优化。Sidebar 里的 state（如展开/收起）在页面导航后仍然保留。这也是为什么 layout.tsx 里不能用 `searchParams`——它不会因为 URL 参数变化而重新渲染。

**B** — Layout components **do not remount** during navigation, which is a core App Router optimization. State inside Sidebar (like open/closed) persists across page navigations. This is also why you can't rely on `searchParams` in layout.tsx — it won't re-render when search params change.
</details>

### ❌ 常见错误 vs ✅ 正确做法

```tsx
// ❌ error.tsx without 'use client'
export default function Error({ reset }) {  // ERROR: not a client component
  return <button onClick={reset}>Retry</button>
}

// ✅ Must add 'use client' directive
'use client'
export default function Error({ error, reset }) {
  return <button onClick={() => reset()}>Retry</button>
}
```

```tsx
// ❌ Trying to fetch in layout and pass to children via props
export default async function Layout({ children }) {
  const data = await fetchUser()
  return <div><Sidebar user={data} />{children}</div>  
  // ❌ children might not need user data
}

// ✅ Fetch in the component that needs it (Server Components compose)
// Each page/component fetches its own data — Next.js deduplicates
```

### 📐 When to Use / When NOT to Use

**✅ Use layout.tsx when:**
- UI is shared across multiple routes (nav, sidebar, footer)
- You need persistent state across navigations
- Server-side auth checks for a route group

**❌ Don't use layout.tsx when:**
- UI is only for one specific page → put it in `page.tsx`
- You need to respond to URL changes → layouts don't re-render on nav

**✅ Use loading.tsx when:**
- Page has async server-side data fetching
- You want instant visual feedback (streaming)

**✅ Use error.tsx when:**
- Route can fail (API errors, missing data)
- You want a recovery mechanism without full page reload

### 🧒 ELI5
layout.tsx 是所有页面共享的"框架"，就像一栋楼的电梯和走廊——进哪间房（页面）都要经过。loading.tsx 是电梯里的等待音乐。error.tsx 是走廊里的消防指示牌——出问题了告诉你怎么办。

`layout.tsx` is the shared frame all pages live in — like a building's hallways and elevator. `loading.tsx` is the hold music when you're waiting. `error.tsx` is the fire exit sign — tells you what to do when things go wrong.
