## Overview / 概述

**中文：**
你有 `n` 个城市，`m` 条有向航班（带价格）。给定出发地 `src`、目的地 `dst`、以及最多允许中转 `k` 次，求最便宜的方案。找不到就返回 -1。

这道题之所以经典，是因为它打破了标准 Dijkstra 的假设：**最便宜的路径不一定是中转次数最少的路径**。当你加入"最多 K 次中转"这个约束时，标准的贪心策略会失效。你必须在「花费最小」和「步数受限」之间做权衡。

这是 Advanced Graphs 模式中最能考察候选人是否真正理解最短路径算法本质的题目。

**English：**
You have `n` cities, `m` directed flights with prices. Given `src`, `dst`, and at most `k` stops (not flights — `k+1` flights total), find the cheapest price. Return -1 if impossible.

Why this matters: standard Dijkstra assumes "if I reach a node via the cheapest path, I never need to revisit it." That breaks here. A slightly more expensive early path might save stops, keeping you within the K limit. This forces you to either track stops in your state, or use a fundamentally different algorithm.

**The Core Insight / 核心洞察:**
> "最多 K 次中转" = "最多 K+1 次航班" = "Bellman-Ford 只跑 K+1 轮"

## Part 1: Theory / 理论基础 (5 min)

### 为什么标准 Dijkstra 在这里失效？/ Why Standard Dijkstra Fails Here

**中文：**

Dijkstra 的核心假设是：一旦某节点被弹出优先队列（达到最低代价），它的最短路径就确定了，不需要再更新。

但这道题里，路径有两个维度：**代价** 和 **已用步数**。

```
示例：
n=4, flights=[[0,1,100],[1,3,100],[0,2,500],[2,3,100]], src=0, dst=3, k=1

路径A: 0→1→3, 代价=200, 步数=2次航班(1次中转) ✅
路径B: 0→2→3, 代价=600, 步数=2次航班(1次中转) ❌ 更贵

如果 k=0（不允许中转）:
路径A: 需要2次航班 ❌ 超出限制
路径B: 需要2次航班 ❌ 超出限制
答案: -1
```

如果 k=1 但我们把一个"代价200但需要1次中转"的路径和"代价200但不需要中转"的路径混在一起，就会误判。

**English：**

Standard Dijkstra only tracks `(cost, node)`. But here we need `(cost, node, stops_used)`. Two paths to the same node might have the same cost but different stops used — and the one with fewer stops remaining might be better for reaching the destination.

The key insight: **stops are a resource, and we need to track resource consumption alongside cost**.

### 三种算法的本质 / Three Algorithmic Approaches

| 算法 | 思路 | 时间复杂度 | 适用场景 |
|------|------|-----------|---------|
| Bellman-Ford | 外层循环K+1次，每次松弛所有边 | O(K·E) | 面试首选，代码简洁 |
| Modified Dijkstra | 状态 = (cost, node, stops)，visited 带 stops | O(E·log(V·K)) | 稀疏图效率高 |
| BFS/DP | dp[i][node] = 用恰好 i 次航班到达node的最小代价 | O(K·E) | 最直观，易理解 |

**为什么 Bellman-Ford 是面试首选？**

Bellman-Ford 的核心思想：每跑一轮，意味着"多用一次航班"。跑 K+1 轮，意味着"最多用了 K+1 次航班 = K 次中转"。

这个映射关系极其直觉：**外层 for 循环的迭代次数 = 航班数量**。

## Part 2: Step-by-Step Implementation / 一步一步实现 (8 min)

### 解法一：Bellman-Ford（面试推荐）

**中文算法步骤：**
1. `dist[]` 初始化：`dist[src]=0`，其他为无穷大
2. 外层循环跑 `K+1` 次（最多用 K+1 次航班）
3. 每次循环：遍历所有边，但**用上一轮的 dist 来更新**（防止同一轮内链式更新）
4. 返回 `dist[dst]`，如果仍为无穷大则返回 -1

**关键：用临时数组 `temp_dist` 防止"串联更新"问题**

```python
import math
from typing import List

def findCheapestPrice_bellman(n: int, flights: List[List[int]], 
                               src: int, dst: int, k: int) -> int:
    # Initialize: infinite cost to all nodes except source
    # 初始化：除出发点外全部为无穷大
    dist = [math.inf] * n
    dist[src] = 0
    
    # Run K+1 iterations = at most K+1 flights = at most K stops
    # 跑 K+1 轮 = 最多 K+1 次航班 = 最多 K 次中转
    for i in range(k + 1):
        # CRITICAL: snapshot the current state before this round of relaxation
        # 关键：必须用上一轮的快照，防止在本轮内链式更新
        temp_dist = dist.copy()
        
        for u, v, price in flights:
            # Relax edge: can we reach v cheaper via u?
            # 松弛：能否通过 u 更便宜地到达 v？
            if dist[u] != math.inf and dist[u] + price < temp_dist[v]:
                temp_dist[v] = dist[u] + price
        
        dist = temp_dist  # commit this round's results
    
    return -1 if dist[dst] == math.inf else dist[dst]
```

**Trace Example / 执行追踪：**
```
Input: n=3, flights=[[0,1,100],[1,2,100],[0,2,500]], src=0, dst=2, k=1

Initial:  dist = [0, inf, inf]

--- Round 1 (i=0, flight 1 allowed) ---
  temp_dist = [0, inf, inf]  (copy)
  Edge 0→1 (100): dist[0]=0, 0+100=100 < inf → temp_dist[1] = 100
  Edge 1→2 (100): dist[1]=inf → skip (can't use chain in same round!)
  Edge 0→2 (500): dist[0]=0, 0+500=500 < inf → temp_dist[2] = 500
  dist = [0, 100, 500]

--- Round 2 (i=1, flight 2 allowed = 1 stop) ---
  temp_dist = [0, 100, 500]  (copy)
  Edge 0→1 (100): 0+100=100, not < 100 → no change
  Edge 1→2 (100): dist[1]=100, 100+100=200 < 500 → temp_dist[2] = 200
  Edge 0→2 (500): 0+500=500, not < 200 → no change
  dist = [0, 100, 200]

Result: dist[2] = 200 ✅
```

### 解法二：Modified Dijkstra（状态包含 stops）

**中文：**
把 `(cost, node)` 扩展为 `(cost, node, stops_used)`。visited 条件变为：若同一 node 以相同或更少的 stops 被访问过且代价更低，才跳过。

```python
import heapq
import collections

def findCheapestPrice_dijkstra(n: int, flights: List[List[int]], 
                                src: int, dst: int, k: int) -> int:
    # Build adjacency list: graph[u] = [(v, price), ...]
    # 构建邻接表
    graph = collections.defaultdict(list)
    for u, v, price in flights:
        graph[u].append((v, price))
    
    # Min-heap: (cost, node, stops_used)
    # 优先队列：（花费，节点，已用停站数）
    heap = [(0, src, 0)]
    
    # visited[node] = min stops used when we reached this node with some cost
    # We can revisit a node if we have fewer stops used
    # 已访问：记录到达该节点时用的最少停站数
    visited = {}
    
    while heap:
        cost, node, stops = heapq.heappop(heap)
        
        # If we've reached the destination, return immediately
        # (Dijkstra guarantee: first time we pop dst is cheapest)
        # 第一次弹出目的地即为最优解
        if node == dst:
            return cost
        
        # Pruning: if we've seen this node with fewer/equal stops, skip
        # 剪枝：如果曾以更少中转数到达此节点，跳过
        if node in visited and visited[node] <= stops:
            continue
        visited[node] = stops
        
        # Can't take more flights if we've used K+1 already
        # 已用 K 次中转（K+1 次航班），不能继续飞了
        if stops == k + 1:
            continue
        
        for neighbor, price in graph[node]:
            new_cost = cost + price
            heapq.heappush(heap, (new_cost, neighbor, stops + 1))
    
    return -1
```

**为什么 visited 的判断是 `visited[node] <= stops` 而不是简单地 `node in visited`？**

```
反例说明：
假设我们有两条路径都到达节点2：
  路径A: cost=100, stops=0（但没有更多廉价边继续走）
  路径B: cost=150, stops=2（但从这里出发还剩K-2次中转可用）

如果仅靠 cost 决定 visited，路径A会阻止路径B被处理。
但路径B 可能因为"剩余中转次数更多"而到达目的地，路径A 却不行。
```

### 解法三：BFS/DP（最直观）

```python
def findCheapestPrice_dp(n: int, flights: List[List[int]], 
                          src: int, dst: int, k: int) -> int:
    # dp[node] = cheapest cost to reach node using at most i flights so far
    # dp[节点] = 用恰好 i 次航班到达该节点的最小花费
    dp = [math.inf] * n
    dp[src] = 0
    
    # K stops = K+1 flights total
    for _ in range(k + 1):
        temp = dp.copy()  # snapshot: same "no chain update" rule
        for u, v, price in flights:
            if dp[u] != math.inf:
                temp[v] = min(temp[v], dp[u] + price)
        dp = temp
    
    return -1 if dp[dst] == math.inf else dp[dst]

# Note: BFS/DP and Bellman-Ford are mathematically identical here.
# The difference is purely in how you think about it:
# Bellman-Ford: "relax all edges K+1 times"
# BFS/DP: "compute optimal cost for exactly i flights, for i = 1..K+1"
```

## Part 3: Edge Cases & Gotchas / 边界情况 (2 min)

### ⚠️ Gotcha 1: 链式更新（Chain Update Bug）

**这是本题最常见的 bug。**

```python
# ❌ WRONG: single dist array — chain update within same round
dist = [0, inf, inf]
for u, v, price in flights:
    if dist[u] != inf:
        dist[v] = min(dist[v], dist[u] + price)
# In round 1: 0→1 updates dist[1]=100, then 1→2 IMMEDIATELY uses dist[1]=100
# This effectively uses 2 flights in 1 round — violates K constraint!

# ✅ CORRECT: use temp array (snapshot)
temp = dist.copy()
for u, v, price in flights:
    if dist[u] != inf:      # read from OLD dist
        temp[v] = min(temp[v], dist[u] + price)  # write to NEW temp
dist = temp
```

### ⚠️ Gotcha 2: src == dst

```python
# If src == dst, cost is 0 — but the initial dist[src]=0 handles this.
# Your code should return 0 without any flights. ✅
```

### ⚠️ Gotcha 3: K=0 意味着只能直飞 / K=0 means direct flight only

```python
# k=0: no stops allowed → only direct flights src→dst count
# Bellman-Ford handles this naturally: loop runs exactly once (k+1=1)
```

### ⚠️ Gotcha 4: Modified Dijkstra 的 visited 条件

```python
# Wrong: if node in visited: continue  (blocks valid paths with more stops remaining)
# Right: if node in visited and visited[node] <= stops: continue
```

### ⚠️ Gotcha 5: 无效路径 / Disconnected Graph

```python
# If dst is unreachable within K stops, dist[dst] stays inf → return -1
return -1 if dist[dst] == math.inf else dist[dst]

## Part 4: Real-World Application / 实际应用 (2 min)

**中文：**

"最多 K 次中转的最便宜航班"这个模式在工程中无处不在：

**1. 网络路由（Network Routing）**
路由器使用 Bellman-Ford 的变体（RIP 协议）来计算最短路径。"最多 K 跳"的约束对应 TTL（Time To Live）——IP 包每经过一个路由器，TTL 减一，防止无限循环。

**2. 供应链优化（Supply Chain）**
从仓库 A 到客户 B，中间经过最多 K 个转运中心，求最便宜的运输方案。每条边权重是运费，K 是允许的最大中转数。

**3. 金融套利检测（Arbitrage Detection）**
货币兑换图：节点是货币，边权是汇率（取对数后变成加法）。Bellman-Ford 的负环检测可以找到套利机会。这里的 K 约束限制了套利链的长度。

**4. 服务网格跳数限制（Service Mesh）**
微服务 A 调用 B，B 调用 C...允许最多 K 跳，超过则断路。Kubernetes 的流量控制 (Istio) 就有类似的最大跳数配置。

**English:**

The "shortest path with a hop constraint" pattern appears everywhere:

- **BGP Routing**: Routers exchange path vectors; AS-PATH length limits prevent routing loops
- **CDN Edge Selection**: Choose the cheapest edge node within K network hops from the user
- **Database Query Planning**: Joins are edges; query optimizer finds cheapest plan within cost bounds
- **Microservice Timeouts**: Distributed tracing depth limits map directly to this K-stops model

## Part 5: Interview Simulation / 面试模拟 (3 min)

**Q1: 为什么不能直接用标准 Dijkstra？**

*Answer:* Standard Dijkstra marks a node "done" when it's first popped from the heap. But here, two paths to the same node with the same cost might have different stops used. The one with more stops used should be discarded (fewer remaining stops), but if it was popped first, we'd incorrectly block better paths. Solution: track stops in the heap state, or use Bellman-Ford which naturally handles this via iteration count.

**Q2: Bellman-Ford 和 BFS/DP 的关系是什么？**

*Answer:* They're mathematically identical. Bellman-Ford: "relax all edges K+1 times." BFS/DP: "dp[i][v] = min cost using exactly i flights." Both iterate K+1 times over all edges with a snapshot. The only difference is framing — Bellman-Ford is graph-centric, BFS/DP is table-centric.

**Q3: Modified Dijkstra 什么时候比 Bellman-Ford 更快？**

*Answer:* When E >> K*V (dense graph, small K). Dijkstra's heap prunes paths early via the priority queue. Bellman-Ford always processes all E edges in every round. For sparse graphs with large K (e.g., k=n-1), they're similar. In interviews, Bellman-Ford is usually preferred for clarity.

**Q4: 如果改成"恰好 K 次中转"而不是"最多 K 次中转"怎么做？**

*Answer:* Change the DP: `dp[k][v] = cost using EXACTLY k+1 flights`. Initialize only `dp[0][src]=0` and don't carry forward intermediate minima. At the end, return `dp[K][dst]` only (not `min(dp[0..K][dst])`). Bellman-Ford as written gives "at most K+1 flights" because it carries forward previous-round values via `temp = dist.copy()`.

**Q5: 这道题和 Bellman-Ford 检测负环有什么关系？**

*Answer:* Classic Bellman-Ford detects negative cycles by running V-1 rounds and checking if a V-th round still relaxes any edge. Here, we run exactly K+1 rounds (not V-1). The K constraint prevents negative cycle exploitation. If K were unlimited and there were negative-weight edges, Bellman-Ford would detect it — but this problem guarantees positive prices, so that's not a concern.

# Template: Cheapest Flights Within K Stops (Bellman-Ford)
def findCheapestPrice(n, flights, src, dst, k):
    dist = [float('inf')] * n
    dist[src] = 0
    for _ in range(k + 1):          # K+1 flights = K stops
        temp = dist.copy()           # snapshot! no chain updates
        for u, v, p in flights:
            if dist[u] != float('inf'):
                temp[v] = min(temp[v], dist[u] + p)
        dist = temp
    return -1 if dist[dst] == float('inf') else dist[dst]
# Time: O(K·E) | Space: O(N)
```

- "Weighted graph" + "constraint on path length" → Modified Dijkstra with (cost, node, constraint) state
- "Negative weights" → Bellman-Ford (Dijkstra breaks with negatives)
- "Detect arbitrage/negative cycle" → Bellman-Ford V-1 rounds + check
