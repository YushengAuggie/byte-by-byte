# 🎨 前端 / Frontend — Day 30
## React.memo, useMemo, useCallback — The Memoization Triangle

---

### 真实场景 / Real Scenario

你在做一个数据 dashboard，有一个 `<DataTable>` 组件显示 1000 行数据，还有一个搜索框。每次用户输入一个字，父组件 re-render，`DataTable` 也跟着重新渲染——即使数据根本没变，页面开始卡顿。

*You're building a data dashboard. A `<DataTable>` shows 1000 rows. A search input causes the parent to re-render on every keystroke, dragging `DataTable` along for the ride — even though its data didn't change. The UI starts stuttering.*

---

### 三者关系 / The Triangle

```
React.memo  ──── wraps ──────▶  Component
                                    │
                                 receives
                                    │
              ┌─────────────────────┴──────────────────────┐
              ▼                                             ▼
         useMemo                                      useCallback
    (memoize a value)                           (memoize a function)

问题: React.memo 只对 props shallow-equal 检查。
如果 prop 是 object/function，每次 render 都是新引用 → memo 失效！
useMemo/useCallback 解决的就是这个"引用稳定性"问题。
```

---

### 代码示例 / Code Snippet

```tsx
// ❌ 问题：每次父组件 render，handleSort 和 config 都是新引用
// DataTable 的 React.memo 完全没用
function Dashboard() {
  const [query, setQuery] = useState('');
  const [data] = useState(largeDataset);

  const handleSort = (key: string) => {   // new ref every render!
    console.log('sort by', key);
  };
  
  const config = { pageSize: 50 };         // new ref every render!
  
  return (
    <>
      <input onChange={e => setQuery(e.target.value)} />
      <DataTable data={data} onSort={handleSort} config={config} />
    </>
  );
}

// ✅ 修复：稳定引用，让 React.memo 真正生效
function Dashboard() {
  const [query, setQuery] = useState('');
  const [data] = useState(largeDataset);

  const handleSort = useCallback((key: string) => {
    console.log('sort by', key);
  }, []);                                  // stable ref ✓
  
  const config = useMemo(() => ({
    pageSize: 50
  }), []);                                 // stable ref ✓
  
  return (
    <>
      <input onChange={e => setQuery(e.target.value)} />
      <DataTable data={data} onSort={handleSort} config={config} />
    </>
  );
}

const DataTable = React.memo(({ data, onSort, config }) => {
  // Now only re-renders when data/onSort/config actually change
  return <table>...</table>;
});
```

### 猜猜输出？/ Quiz

```tsx
const fn1 = useCallback(() => console.log('hello'), []);
const fn2 = useCallback(() => console.log('hello'), []);

console.log(fn1 === fn2);
```

**A)** `true`  
**B)** `false`  
**C)** Depends on render count  
**D)** TypeError

<details><summary>显示答案 / Show Answer</summary>

**B) false**

`useCallback` 返回的是 **同一个组件实例中跨 render 稳定的引用**，但 `fn1` 和 `fn2` 是两个独立的 `useCallback` 调用，是两个不同的函数对象。同一个 `useCallback`（依赖不变时）跨 render 返回相同引用，所以 `fn1 === fn1`（跨两次 render）会是 `true`，但 `fn1 === fn2` 永远是 `false`。

</details>

### ❌ 常见错误 vs ✅ 正确做法

| 情形 | ❌ 错误 | ✅ 正确 |
|------|--------|---------|
| 组件接收 object prop | `<C config={{size:50}} />` | `useMemo(() => ({size:50}), [])` |
| 组件接收 callback | `<C onClick={() => fn(x)} />` | `useCallback(() => fn(x), [x])` |
| 忘记依赖 | `useMemo(() => compute(a), [])` 当 a 变化时 | `useMemo(() => compute(a), [a])` |
| 过度使用 | 对简单 string/number prop 用 useMemo | 直接传值，原始类型自动 compare by value |

---

### 何时用 / 何时不用 / When to Use vs Not

**✅ 该用：**
- 子组件有 `React.memo` 包裹 + prop 是 object/function
- 计算量大的派生数据（如排序/过滤大数组）
- 传给 `useEffect` 依赖数组的函数引用

**❌ 不该用：**
- prop 是 string/number/boolean（原始类型，自动 value compare）
- 组件渲染本来就很轻（memo 本身有成本！）
- 没有实际性能问题时（premature optimization）

*Rule of thumb: profile first, memoize second. React DevTools Profiler shows which components re-render unnecessarily.*

### 🧒 ELI5
`React.memo` 像保安，拒绝没变化的 props 进门。但如果你每次都带着"新袋子"（新的 object/function 引用），保安认不出你，还是放你进去了。`useMemo` 和 `useCallback` 是让你每次带**同一个袋子**——这样保安才真的能拦住重复进入。

*React.memo is a bouncer that blocks unchanged props. But if you bring a "new bag" (new object/function reference) every time, the bouncer doesn't recognize you and lets you in anyway. useMemo/useCallback ensure you always bring the SAME bag — so the bouncer actually works.*
